# 0.6.0: a plain terminal with the companion: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jaffer becomes a plain terminal with the companion animations: no saved screen, no Resume/Restart Claude, no login agent, no session that outlives the app, no memory, no Safety edges; the app starts the terminal host as its own child and ends it on quit.

**Architecture:** Remove in an order where every step leaves `npm run typecheck && npm test` able to pass: untangle shared pieces, delete the small features (Safety), then memory (backend, then window), the saved screen, the resume stack, the login agent, then change the process model (the daemon becomes the app's child), then the one-time migration of an upgraded Mac, then docs/version. The inventory (read it first) lists every file, line range and test group.

**Tech Stack:** TypeScript, Node (daemon child), Electron main, Preact renderer, vitest (unit and real-process daemon tests), Playwright-core UI tests.

**Spec:** `docs/superpowers/specs/2026-10-10-plain-terminal-design.md` (approved by the owner's decisions; it wins over this plan on any conflict). **Inventory:** `.superpowers/sdd/2026-10-10-plain-terminal/inventory.md` (file-level removal map, section numbers are cited by the tasks below; line numbers are from commit `6fbe377` and drift as tasks land: search by name).

## Global Constraints

- **No test and no run may call the real `launchctl`, touch `~/Library/LaunchAgents`, or run the real `caffeinate`.** `JAFFER_NO_LAUNCHCTL=1` stays set for all test runs; the legacy-agent cleanup is tested with an injected fake `launchctl`. THIS IS THE PERSON'S REAL MAC. The repo's `release/` folder holds the owner's running app: never removed by a test or build.
- Test hygiene: tests of removed behaviour are removed deliberately and **listed in the report**; **every other test keeps its name**. After editing a test file diff its `it(`/`describe(` names against the base commit and report any missing one not on the removal list. Never truncate a test file's tail when editing by script (use Python, not `sed -i`, on macOS). Vitest groups listed as "whole" in the inventory are deleted whole; "partly" means only the named describes/tests go.
- What stays true (CLAUDE.md rules that survive): redaction (`src/shared/redact.ts`) for anything the watcher/notifications handle; one session, one terminal; Claude Code only; no API key; sign-in only from `claude auth status`; the hooks (`jaffer hook <event>`) are asynchronous, print nothing, exit 0 on every path and do nothing unless `JAFFER_SESSION=1`; cost reads only token counts; the window shows only its own page; command-line helpers slice to a `COMMAND_HEAD` (4096) head with timing tests; staying awake is an idle-sleep hold only. The only things the product types into the shell: `claude` (⇧⌘C and the first-run switch).
- Config is conformed to the kind of the defaults (`conform`); a new key needs a default of the right kind. Old config files with removed keys must load (keys are ignored until the migration prunes them, Task 9).
- The window stays calm: no new panels, toasts only where a task says; colours are theme tokens; no new global CSS class that collides with an existing selector.
- Never ask for, print or store a password. No change to CI workflows, entitlements or signing config. `jafferd.cjs` keeps its path (`dist/daemon/jafferd.cjs`): an old wrapper names it.
- Verify with `npm run typecheck && npm test`; the UI with `JAFFER_CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npx vitest run --config vitest.e2e.config.ts test/e2e/ui.test.ts` (the UI file is allowed to be red between Task 3 and Task 4 only, and must be green from Task 4 on). Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never push, tag or publish in a task.

## Review Focus

1. **A kept feature broken by a removal:** a Claude hook event reaches the watcher through the socket and drives the companion, a notification, the cost figure and stay-awake end to end; SessionStart and Stop are async and guarded and print nothing. (Task 3, 6, 8)
2. **The first start on an upgraded Mac:** an installed login agent, a running old daemon, `~/.jaffer/{memory,session,bin/jafferd}`, an old `settings.json` with `# jaffer-managed` hooks, a CLAUDE.md block, `jaffer-*` skills with the marker, the MCP entry: migrated once, idempotent, only Jaffer's own entries touched, the two hand-written files backed up; a failure in one step does not stop the rest or the app. (Task 7, 8, 9)
3. **The child's life:** quitting ends shell and Claude (with the confirmation when something runs), an app crash or SIGKILL does not leave the daemon or the shell running, `Update and restart` and `jaffer reset` end cleanly, the parent-exit watch is opt-in so tests still start the daemon with `stdio: 'ignore'`. (Task 8)
4. **Nothing dead left behind:** grep for the removed identifiers (memory, ingest, resume, restart-claude, keepRunning, restoreScreen, safety, launch-agent, danger-zone) across src, test, docs, scripts; palette entries, menu items, IPC channels, RPC methods, config keys, CSS tokens, Settings sections and first-run steps all gone; the README claims only what exists. (Task 10)
5. **Deleted tests:** only tests of removed behaviour are gone, none truncated; the kept suites (watcher, stay-awake, notify, cost, redact, rpc, session, hooks, reset, updater) still run real processes. (every task)
