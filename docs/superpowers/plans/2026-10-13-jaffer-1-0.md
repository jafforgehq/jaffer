# 1.0.0: forty features: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the forty features of the spec as Jaffer 1.0.0, signed and published.

**Architecture:** Data first (watcher and daemon), then the renderer in three slices (command blocks, terminal power, title bar and Claude UI), then the companion, then app-level features (themes, focus mode, blur, Settings), then docs and the release. Each task keeps `npm run typecheck && npm test` and the UI file green.

**Tech Stack:** TypeScript, Node (daemon child), Electron main, Preact + signals renderer, xterm.js 6 (addons: fit, search, unicode11, web-links, clipboard, image, webgl), vitest, Playwright-core UI tests.

**Spec:** `docs/superpowers/specs/2026-10-13-jaffer-1-0-design.md` (binding; feature numbers below are the spec's). **Feature map:** `.superpowers/sdd/2026-10-13-jaffer-1-0/feature-map.md` (exact files, names, line refs at 4737187; lines drift: search by name).

## Global Constraints

- THE PERSON'S REAL MAC: no test or run touches the real `launchctl`, `caffeinate`, `~/.jaffer` or `~/.claude`; never run the app with the default home (`npm run dev|start|smoke` set no `JAFFER_HOME`): use temp homes. The repo's `release/` folder holds the owner's running app: never removed. `JAFFER_NO_LAUNCHCTL=1` stays.
- Rules from CLAUDE.md stay, except the two the spec narrows (calm window additions; watcher may keep tool names, counts, timings, failure flags and non-sensitive edited file paths in memory). The only thing typed into the shell is `claude`. Nothing new on disk except `config.json` keys. Everything shown about a command goes through `safeCommand()`; anything from a hook payload through `redactText`. Every scan over untrusted text (paths, ports, sensitive paths, git output) is bounded, with 1 MB and 8 MB timing tests.
- New config keys need a default of the right kind in `DEFAULT_CONFIG` (`conform`). Keys and defaults (exact): `claude.liveCost` true, `claude.dailyBudgetUsd` 0, `claude.typicalTurnMs` 0, `claude.toolStrip` true, `claude.turnSummary` true, `terminal.blocks` true, `terminal.pasteGuard` true, `terminal.ruler` 0, `terminal.editorUrl` '', `terminal.images` true, `terminal.portLinks` true, `appearance.systemStats` false, `appearance.glow` true, `appearance.autoTheme` 'off', `appearance.lightTheme` 'jaffer-light', `appearance.blur` true.
- New IPC (main + preload + `global.d.ts` + the dev bridge shim in `src/dev/bridge.ts`), each with the `trusted(e)` sender check: `jaffer:save-text` (dialog + write, ≤ 32 MB), `jaffer:reveal-path` (existing absolute path → `shell.showItemInFolder` only), `jaffer:open-editor` (template from `terminal.editorUrl`, scheme allow-list: vscode, vscode-insiders, cursor, windsurf, zed, idea, subl, txmt; the path URL-encoded), `jaffer:system-stats` (main → renderer push every 5 s while `appearance.systemStats`), `jaffer:focus-mode` (renderer → main: on/off). Never `shell.openPath` on a printed path.
- Colours are theme tokens; motion respects `appearance.animations` (`:root[data-motion='off']`) and `prefers-reduced-motion`; CSS is global: check a new class is not already a standalone selector.
- Tests of removed behaviour do not exist here (nothing is removed); every existing test keeps its name unless the spec demands a change (the calm-window test and the watcher privacy test change deliberately: say so). Name-diff every touched test file against the task BASE.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push, tag or publish in a task. No change to CI workflows, entitlements or signing config.
- Verify: `npm run typecheck`; `node scripts/gen-shell.mjs --check`; `npm run build`; `npm test`; the UI file `JAFFER_CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npx vitest run --config vitest.e2e.config.ts test/e2e/ui.test.ts`.

## Review Focus

1. Privacy: nothing beyond the narrowed set reaches the window or memory (no commands' text from hooks, no prompts, no tool arguments except non-sensitive edited paths), and nothing new on disk except config keys.
2. Safety of new IPC: a printed path or URL can never run anything (reveal only; editor URLs only for allowed schemes; ports only `http://localhost`); save-text writes only where the person chose.
3. Performance on untrusted output: path/port scanning and block parsing are bounded and do not slow `pty.data` (a 50 MB `cat` stays smooth: no per-chunk full-buffer work).
4. Block markers survive normal use and degrade cleanly after `term.reset()` (re-attach, `pty.reset`, shell restart): no stale decorations, no exceptions.
5. Calm by default: new visuals off or subtle by default as the spec says; animations off / reduced motion stop all new motion; focus mode holds notifications and releases one summary.

**Interfaces (produces):**

- `isSensitivePath(p: string): boolean` (spec list; bounded: slices to 4096 chars).
- `ClaudeSession` gains: `startedAt: number` (first event of the session), `turns: number` (UserPromptSubmit count, excluding task notifications), `compacting?: boolean`, `calls: ToolCall[]` (current turn only, max 200: `{name: string, category, startedAt: number, endedAt?: number, failed?: boolean, agentId?: string}`), `counts: Record<string, number>` (current turn, by category), `file?: string` (the path of the running Edit/Write/MultiEdit/NotebookEdit call, redacted, not sensitive), `files: string[]` (current turn's edited/written paths, unique, max 50), `ClaudeSubagent` gains `tool?: string` (when a PreToolUse carries `agent_id`).
