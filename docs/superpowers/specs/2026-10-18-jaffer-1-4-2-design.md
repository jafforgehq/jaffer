# 1.4.2: the Setup list tells the truth about MCP servers and finds your skills

Date: 2026-10-18 · Status: bug report from the owner's real Mac (screenshots of 1.4.1: Claude Code's own /mcp shows godot, blender and meshy-mcp-server connected; Jaffer's Setup list shows them "Failed to connect"; Skills show 0 though many exist). Patch release; fixes only.

## Findings (reproduced on the owner's Mac)
- `claude mcp list` run by the daemon inherits the app's environment. A Mac app started from the Dock/Finder has a minimal PATH (`/usr/bin:/bin:/usr/sbin:/sbin`), so MCP servers started with `npx`, `node`, `uvx` fail with `ENOENT: Executable not found in $PATH: "npx"`. The same command with the person's shell environment connects them. Real output sample (names/states only): `godot | ✘ Failed to connect — ENOENT: Executable not found in $PATH: "npx"` with a minimal PATH, `godot | ✔ Connected` with the shell's PATH.
- `claude mcp list` also prints `claude.ai <Name>: <url> - ✔ Connected` lines (connectors, names with spaces) and `plugin:<plugin>:<server>: … - ! Needs authentication`; Jaffer's list showed 9 servers and none of the four `claude.ai …` ones.
- Skills: `~/.claude/skills/synced/<uuid>/<name>/SKILL.md` (skills synced from the Claude desktop app) are nested two folders deeper than the reader looks, and the skills inside installed plugins (`<plugin installPath>/skills/<name>/SKILL.md`) are not read at all.

## Fixes
1. **The shell's PATH for the MCP check.** The shell-integration scripts (zsh, bash, fish) report the shell's `$PATH` after its startup files ran, as `OSC 633;P;Path=<value>` before a prompt, only when it differs from the last one reported. `PtySession` parses it (printable text only, no control characters, at most 8192 characters; anything else is ignored) and keeps `shellPath` per pane (memory only; PATH is not a secret, never logged or shown). `claude.mcp {cwd, pane?}` runs `claude mcp list` with `PATH` = that pane's shell PATH (the window passes the focused pane); if none is known yet, with the app's PATH plus the usual tool folders appended once each when they exist: `<home>/.local/bin`, `/opt/homebrew/bin`, `/opt/homebrew/sbin`, `/usr/local/bin`. Everything else about the check stays (argv, scrubbed env, 25 s, 64 KB, process group, one run per folder, gate, click only).
2. **Server lines with spaces.** `parseMcpList` keeps names such as `claude.ai Claude Docs` and `plugin:context7:context7` (the name is everything before the first `: ` that is followed by the target, which starts with a URL scheme, a path or a command); a test with the real sample lines (below); the Setup panel shows them with the other servers (the count says how many).
3. **Skills sources.** Besides `~/.claude/skills/<name>/SKILL.md` and `<cwd>/.claude/skills/<name>/SKILL.md`: nested skill folders under `~/.claude/skills` to depth 3 (synced skills), and the skills of installed plugins that are enabled: `<installPath>/skills/<name>/SKILL.md` for each entry of `installed_plugins.json` (installPath must resolve inside `<claudeDir>/plugins`; same confinement, size and entry caps; a plugin-level scope label `plugin:<id>`); total skills capped at 300; state `on` unless `skillOverrides` says otherwise (plugin skills are not affected by `skillOverrides`: show them `on` for enabled plugins and `off` for disabled ones).
4. Docs: CLAUDE.md (Setup rule: skills sources, the MCP check's PATH; memory list: per-pane shell PATH; the OSC), README (Setup description, limits), ARCHITECTURE, `docs/releases/v1.4.2.md` (card ≤ 800 chars, `<!-- card-end -->`, last line exact), version 1.4.2, SECURITY.md only if a claim changes.
