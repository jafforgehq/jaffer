# 1.4.0: split terminals, a permissions screen, a tour, and more

Date: 2026-10-16 · Status: scope decided by the owner in conversation: up to four terminals in split view; a close/delete button per terminal; ideas 1-11 (context meter, 5-hour usage, weekly digest, work-time budget, project budgets, today timeline, tags, hide, storage view, clear old, deep search); an MCP/skills/rules list with state in the right pane; an interactive tour with info buttons, a glossary and tips, and Claude-written explanations ("can we ask the user to allow everything and make these things"); minor version bump, ship. Facts: `.superpowers/sdd/2026-10-16-jaffer-1-4-0/feature-map.md` (survey of main @ 15219f4); Claude Code docs facts in the ledger.

## Rulings (rules this release changes or keeps)
- **The one-terminal rule is replaced by "up to four, only by the person's own split".** CLAUDE.md's "exactly one session and one terminal" is rewritten; the guard tests (`session.test.ts` 'one session, ever', `daemon.test.ts` 'there is only one session', the UI test 'there is exactly one session') become tests of the new limit. Still true: one window, one daemon child, nothing saved or replayed (the layout is memory only; a new start has one terminal), the app owns every shell (quit ends all).
- **A permissions model.** `permissions` config section (all booleans) lets the person switch sensitive capabilities on or off, in *Settings → Privacy and permissions* and as a screen at the end of first-run: `explain` (false), `deepSearch` (false), `resumeTyping` (true: off = a click only copies), `trash` (true: off = no remove buttons), plus the existing `claude.approvals` (false). Each switch says in plain words what it reads, sends or does. **Locked, no switch:** Allow needs a trusted armed click and the whole request shown; Jaffer never reads Claude's login files (`~/.claude.json`, the keychain item) or credentials; nothing is permanently deleted; everything shown is redacted; a sensitive command is never named.
- **Explain (opt-in, `permissions.explain`)**: only when on, a button runs ONE helper `claude -p` with tools disabled and no session saved, fed the text of the active Claude's latest reply (read from the transcript tail, clipped to 6000 characters, redacted, kept in memory only) plus a fixed instruction to explain it plainly; the answer is shown as plain text in a dismissible card in the side panel. It uses the person's own subscription (counts against their plan; the card says so), never an API key, and the text goes only to Claude, which already saw it. If the installed `claude` cannot run with tools disabled and no saved session, the feature is not offered (checked once with `claude --help`; the implementer reports exactly which flags). Without the permission nothing of a reply is ever read. The "Ask Claude to explain" prompt-copy button exists regardless (it only copies).
- **On disk, new:** config keys only: `permissions.*`, `tour.done`, `tips.enabled`, `tips.seen` (list of tip ids), `history.tags` (list "<uuid> <tag>"), `history.hidden` (list of uuids), `claude.dailyWorkBudgetMin` (number), `claude.projectBudgets` (list "<folder>=<usd>"), `usage` (numbers only: this week's and last week's `{id, usd, workMs}` and `digestWeek`), `notifications.weeklyDigest` (true). No text of Claude's, no commands, no folders except the person's own budget list.
- Typing/rules unchanged except: resume typing targets the **focused terminal** and uses that terminal's idle state.

## Features
**A. Split terminals (Tasks 1-2)**
1. Daemon/host: `SessionHost` holds up to 4 panes (`main`, then `p2`..`p4` ids, free ids reused); `pane.split {cwd?, cols?, rows?}` (cwd defaults to the active pane's folder, refused at 4) and `pane.close {pane}` (kills that shell and removes it; refused for the last pane: use `session.restart {pane}`); lifecycle `'closed'`; `session.restart`, `session.detach`, `session.info` take a `pane`; attach state per pane (`conn.meta.attached` becomes a set); git status per pane; env `JAFFER_PANE=<id>` in each shell; the hook CLI forwards it as `jaffer_pane` in the `claude.event` payload and the watcher keeps `pane?` on a session (a new watcher field: its entry in the privacy test); `endAll` becomes `endPane(pane)` for pane exits and Claude-command ends; stay-awake counts a command in any pane; `userAnswered()` still moves needs-you sessions on typing in the pane that session lives in.
2. Renderer: per-pane info (`paneInfo` map; the existing `info` signal is the focused pane's, so current consumers keep working), `currentClaude()` prefers the focused pane's Claude, `PaneTree` renders 1-4 panes in a grid (1; 2 side by side; 3: one left, two stacked right; 4: 2×2), equal sizes (no drag), the focused pane has a thin accent outline, each pane has a small chip (state dot, folder name, ✕); blocks, sticky header, find bar act on the focused pane; each pane's `TerminalView` fits itself and sends its own `pty.resize`; per-pane detach on unmount.
3. Menu/palette (one line actions, unique accelerators): `split-terminal` ⌘D "Split Terminal", `close-terminal` ⇧⌘W "Close Terminal", `focus-terminal-1..4` ⌘1..⌘4, `next-terminal` ⌘] and `prev-terminal` ⌘[ (confirm they are free in menu-spec; roles checked by hand). `restart-shell` acts on the focused terminal. Split is refused with a toast at 4.
4. **Close / delete button** (the owner's "delete session button in terminal"): the chip's ✕ ends that terminal. With several panes it closes the pane; the last pane's ✕ is "Restart terminal" (a fresh shell in the same folder). If a command or Claude runs in it, an inline confirmation under the chip says what runs ("A command is running: node server.js") with *End terminal* / *Cancel* (Cancel default, Esc cancels); nothing running: no question.
5. Main: quit asks if ANY pane runs a command or Claude (map pane → command), notifications and tray keep working; a pane's shell exiting by itself still respawns fresh (as today) except when closed by the person.
**B. Claude insight (Task 4)**
6. Context meter: the daemon reads the latest assistant message's `usage` (input + cache creation + cache read tokens) from the transcript with the existing cost reader and `contextWindow(model)` (pure table in `src/shared/claude-cost.ts`: 1,000,000 for the 1M families named in the docs (Fable 5.1, Fable 5, Mythos 5.x, Opus 5.x, Opus 4.7+, Sonnet 5.x, Haiku 5.5), 200,000 otherwise, none for an unknown id: tokens only) → Now card line and a thin bar ("Context 62% of 1M", warn from 80%, danger from 92%); one toast at 85% per session. Says "estimate". Memory only. If a transcript has no usage, nothing shows.
7. Last 5 hours: sum of tokens and estimated usd of usage lines timestamped in the last 5 h across transcripts modified in that window (≤ 60 files, ≤ 24 MB each, bounded reads) → Now card line "Last 5 h ≈ $x · 3.2M tokens (estimate; not your plan's limit)"; refreshed with the history read; memory only.
8. Weekly digest: `usage.week` / `usage.lastWeek` numbers added at each counted Stop (week id = ISO week, local); at app start, once per finished week (`usage.digestWeek`), one notification "Last week: ≈ $x, 12h 30m with Claude" (`notifications.weeklyDigest`, only with `claude.showCost` for the money part), and the What's New style toast with an action that opens the panel.
9. Work-time budget `claude.dailyWorkBudgetMin` (0 = off; Settings → Claude Code): the Now card's worked line shows the level and one notice when it is passed. 10. Project budgets `claude.projectBudgets` (list "<folder>=<usd>" weekly; Settings field, one per line): from the costed rows of the history list (the 30 newest, like cost by folder): the row of that folder gets a warn/danger tint in the cost-by-folder table and one toast per week per folder when passed; the text says it counts the 30 newest conversations. 11. Today timeline: the Now card gets a collapsible "Today" list of the last 20 turns (time of day, length, tool counts text, files count, cost), memory only (extends `turnHistory`).
**C. Conversations (Task 5)**
12. Tags: a tag button per row (menu of existing tags + "New tag…" input ≤ 20 chars), up to 3 tags per conversation, `history.tags`; colors from a fixed palette by tag name hash; tag chips next to folder chips filter; caps 400 entries. 13. Hide: a hide button per row (`history.hidden`, ≤ 500) and a "Hidden (N)" toggle that shows them dimmed with an Unhide button; hidden are excluded from Remove… "All listed". 14. Storage: `claude.storage` RPC (`{totalBytes, count, biggest: [{id, title?, cwd?, bytes, endedAt}]}`, ≤ 10 biggest, sizes of `<id>.jsonl` plus sibling dir, bounded walk, links skipped) → a "Storage" toggle in the conversations header: total, count, the 10 biggest each with a trash button (the existing removal path and its dialog). 15. Clear old: *Remove…* menu gets "Older than 30 days…" / "60" / "90": `claude.old {days}` → up to 200 oldest ids older than that and the total count; the confirmation (native, existing) names the number; the rest ("N more") can be repeated. 16. Deep search (needs `permissions.deepSearch`): a "Search text" switch in the panel search; `claude.search {q}` (q 3-64 chars; scans at most the 200 newest transcripts, ≤ 2 MB per file head+tail, case-insensitive, message text only; returns ids and match counts, NO snippets; never stored; bounded time 5 s) → rows filtered to the hits with a "N matches" note.
**D. Setup list (Task 6)**
17. A third, collapsible section of the side panel, "Setup" (collapsed by default; `panel.setupOpen` is memory), with groups: MCP servers, Skills, Rules and memory, Plugins, Hooks. `claude.setup {cwd}` (files only, no processes; never `~/.claude.json`): skills from `~/.claude/skills/*/SKILL.md` and `<cwd>/.claude/skills/*/SKILL.md` (name + description frontmatter, the `skillOverrides` state from settings), plugins from `~/.claude/plugins/installed_plugins.json` + `enabledPlugins` in the settings files, rules from CLAUDE.md files found in cwd and parents + `~/.claude/CLAUDE.md` + `.claude/rules/*.md` (path, size, scoped yes/no), subagents `.claude/agents/*.md` names, hooks: event names and counts only (no commands), MCP: server names from `<cwd>/.mcp.json` ("not checked"). `claude.mcp {cwd}` runs ONLY on a click ("Check MCP servers: this starts your servers briefly"): `claude mcp list` in the focused pane's folder with a 25 s timeout and 64 KB output cap, parsed tolerantly line by line into `{name, status}` with the documented status words (connected, needs authentication, failed, pending approval, disabled) and everything else "unknown"; text redacted and clipped; arguments and URLs are never shown. Each item shows a state dot (ok / needs attention / unknown / off). Read-only: nothing here changes any setting.
**E. Permissions screen (Task 3)**: Settings section "Privacy and permissions" and a last first-run stage, switches as in the ruling, copy per switch; `resumeTyping` and `trash` flags enforced in `resumeAction`/the panel.
**F. Explain (Task 7)**: per ruling; `claude.explain {session?}` daemon RPC; the card "Explain" in the side panel (above Now, below What's New) with the result text, a dismiss button and "Uses your Claude subscription" note; button "Explain the last answer" in the Now card (idle, after a turn) shown only with `permissions.explain`; errors become a calm line, never a crash.
**G. Learn (Task 8)**: 18. `src/shared/glossary.ts` (≥ 14 entries: session, model, context window, compaction, token, cost estimate, subagent, hook, MCP server, skill, CLAUDE.md and rules, permission prompt, plan mode, transcript, plus Jaffer terms: companion, panel), overlay kind `learn` (Glossary with search; palette action "Glossary"; Settings → Help). 19. `InfoButton` (ⓘ, popover with 2-3 sentences + "More in the glossary"; keyboard accessible) next to: the session clock/ring, the cost chip, the Now card title, the context meter, the turn bars, "worked today", approvals ask, the panel section titles, chips, the Setup groups, and a few Settings fields. 20. Tour (overlay kind `tour`): coach marks over real elements (terminal, title bar ring, Now card, past conversations, palette ⌘P, split ⌘D, Settings, Privacy): Next/Back/Skip, arrows/Esc, a "Try it" where an action exists; offered on the first-run last stage and *Settings → Help → Start the tour*; `tour.done`. 21. Tips: first time per concept (compaction, first helper/subagent, first permission prompt, context ≥ 80%, first turn over 5 min, budget passed) a quiet toast "What is compaction?" with Explain (opens the glossary entry) and "Don't show tips"; `tips.seen` list, `tips.enabled` switch.
**H. Docs and release (Task 9)**: CLAUDE.md (all rule changes), ARCHITECTURE, README (+ Not verified), `docs/releases/v1.4.0.md` (card section ≤ 1200 chars before `<!-- card-end -->`), version 1.4.0, screenshots.
