## Rulings
- **The side panel gets one more temporary child: the What's New card** (dismissible, inside `.side-panel`, above Now). The panel keeps its two sections; CLAUDE.md's panel rule is amended. Nothing else is added to the window.
- **Release notes are bundled by a generator**, not packaged files: `scripts/gen-release-notes.mjs` reads `docs/releases/v*.md` into `src/generated/release-notes.ts` (`RELEASE_NOTES: {version: string; md: string}[]`, newest first, the standard last line "Updating from 0.2.x…" removed). It runs in `build.mjs` next to `gen-shell`, and `--check` is a unit test (as `gen-tray-icons`). CI, entitlements and electron-builder config stay untouched.
- **On disk, new:** only `config.json` keys: `updates.seenVersion` (string), `history.names` (list of text, `"<uuid> <name>"`), `history.pinned` (list of text, uuids), `claude.approvals` (boolean, default false), `window.dropdown` (boolean, default false), `appearance.seasonal` (boolean, default true). The rename text is the person's own label, not transcript text. No keys are removed. Everything else is memory only; list new memory in CLAUDE.md's memory rule.
- **Typing and clipboard rules stay**: rename/pin/chips/palette add no typing except through the existing `resumeAction` path. "Resume last" uses it too.
- **Approvals (idea 10) are opt-in and off** (`claude.approvals`, Settings → Claude Code, default false): see feature 11. Never answers without a human click on Allow; Deny is always safe; any failure, timeout or the setting off leaves Claude Code's own prompt in charge.

## Features (numbered; tasks own groups)
**A. What's New (Task 1)**
1. Generator + `RELEASE_NOTES` (above). Tiny markdown view (`src/shared/mini-md.ts`: `##`/`###` headings, `-` bullets, `**bold**`, `` `code` ``, paragraphs; rendered to Preact elements, never innerHTML; unit tests, bounded on 1 MB/8 MB lines).
2. State: `updates.seenVersion`. Effective seen = `seenVersion || (onboarded ? '1.1.1' : appVersion)`. Unseen = notes with version > seen (semver compare), at most the 5 newest shown. Dismiss writes `seenVersion = appVersion`. First onboarding writes `seenVersion = appVersion`.
3. The card (`WhatsNew` in the side panel above Now): title "What's new in 1.2.0", the unseen notes rendered, buttons Dismiss and All versions (the history list, each version collapsible, newest open). Opens on its own after an update (panel opened if closed? no: a toast "Jaffer updated to 1.2.0" with action "What's new" opens the panel and the card; open panel shows the card at once).
4. Entry points: Help menu "What's New…" (menu id `whats-new`, no accelerator, palette action "What's new"), tray menu item "What's New in 1.2.0" shown only while unseen (main reads `updates.seenVersion` from its config mirror; no tray icon change), the card persists until dismissed.
**B. Past conversations (Task 2)**
5. Rename: a pencil button per row (and F2 on the selected row) edits in place; Enter saves to `history.names`, Esc cancels, empty removes. Custom name wins over the title everywhere (rows, filter, palette, tray labels via the config mirror). Caps: 200 names, 80 chars, control characters stripped, ids by `isSessionId` (pure `src/shared/history-names.ts`: parse/format/set/remove, tolerant of bad entries).
6. Pin: a star button per row toggles `history.pinned` (50 max); pinned rows form a "Pinned" group above the days. `claude.history` takes `{include?: string[]}` (pinned ids, `isSessionId`-checked, ≤50) so pinned conversations older than the 50 newest are listed too (titles yes, cost only within the 30 newest).
7. Folder chips: a row of chips (All + the 5 most used folders, tilde short names) filters the list; memory only.
8. Cost by folder: a small toggle under the chips ("Cost by folder") lists the top 5 folders with today's and this week's estimate from the costed conversations already read (`costByFolder(items, now, home)` pure; says "from the 30 newest conversations"; only with `claude.showCost`).
9. Resume last: ⇧⌘R (menu id `resume-last`, label "Resume Last Conversation", palette action, Shell menu): resumes the newest conversation whose folder is the shell's folder, else the newest overall; reads the list first if the window has none; the same `resumeAction` rules (idle prompt only, else copy + toast). The click logic moves from `Conversations.tsx` to a shared renderer module used by the panel, the palette and this action (the 2 s type-once lock is shared).
10. Palette: with ≥2 typed characters the palette adds the conversations whose name/title/folder match (at most 5, section "Conversation"); Enter resumes like a click; the list is read when the palette opens if the window has none.
**C. Now card and Claude (Task 3)**
11. Turn bars: the Now card shows the last turns (≤20 bars, from `turnHistory`) as an SVG bar chart (height = duration, colour tint by cost level), `<title>` per bar ("1m 12s · ≈ $0.04"), only with ≥2 turns.
12. Worked today: the daemon counts the time of finished turns today (`DayTotal.workMs`, resets at local midnight with the cost); the Now card shows "Claude worked 1h 12m today" (live: plus the running turn). Memory only. Turns shorter than 1 s are ignored.
13. Seasonal companion: `appearance.seasonal` (default true; Settings → Appearance next to the companion) adds a small seasonal touch by date: pure `seasonOf(date)` in `src/shared/season.ts` (halloween Oct 24–Nov 1, winter Dec 15–Jan 3, valentine Feb 12–15, none otherwise); the mole gets a hat/accessory, scenes get a CSS-only `data-season` decoration. Reduced motion respected. Tests for `seasonOf` (boundaries) and the attribute.
**D. Terminal (Task 4)**
14. Copy a block as an image: the gutter menu item "Copy as image" renders the command (through `shownCommand`) and its output (≤ 200 lines × 160 columns, the rest cut with "…") on a canvas in the terminal's font and theme colours, and writes a PNG to the clipboard (`ClipboardItem`); toast "Copied as image". Never saved to disk.
15. Recent commands by folder: `RecentCommand.cwd?` (the shell's folder when the command ended, memory only); the ⌘R list gets a "By folder" toggle grouping rows under the tilde folder; copying stays as is.
16. Shortcuts sheet: ⌘/ (menu id `shortcuts`, Help menu "Keyboard Shortcuts", palette action) opens an overlay (kind `keys`) listing every accelerator (from `MENU_ITEMS` and the palette `keys`, grouped by section), search input, Esc closes.
**E. Window (Task 5)**
17. Drop-down mode: `window.dropdown` (default false; Settings → Appearance → Window). With it on, the hotkey slides the one window down from the top of the display under the cursor (full width of the work area, 45% of its height; pure `dropdownBounds(workArea)`), hides it when it loses focus, and ignores the saved bounds (they are not overwritten); off: the saved bounds return. No second window, no Dock change.
**F. Approvals from the notification (Task 6)** — design finalised after checking Claude Code's PermissionRequest hook (see the ledger's ruling) .
18. `claude.approvals` (default false). On: Jaffer installs a 12th hook, `PermissionRequest`, as a **blocking** (non-async) `jaffer hook PermissionRequest` entry; the CLI asks the daemon (`claude.approval`, waits up to `APPROVAL_WAIT_MS` = 20 s), the daemon asks main (event `claude.approval.ask`) which shows a notification "Claude asks to use <tool>" with **Allow**, **Deny** and **Show** buttons (tool name and a redacted one-line detail, ≤ 120 chars, sensitive commands named by tool only). Allow/Deny answer the waiting hook, which prints Claude Code's decision JSON; Show or no click within 20 s, a closed window, the setting turned off, the daemon unreachable, any error: the hook prints nothing and exits 0 and Claude Code's own prompt appears. The title-bar needs-you chip and the panel Now card show "Waiting for your answer (20 s)" with Allow/Deny buttons too (same RPC). Answers count in `timesAnswered`. The setting's copy says Claude Code's own prompt appears if you don't answer in 20 s. A new hook event needs its entry in the watcher privacy test.
