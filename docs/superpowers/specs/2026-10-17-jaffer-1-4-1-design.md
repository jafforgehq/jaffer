# 1.4.1: hardening from the 1.4.0 audit

Date: 2026-10-17 · Status: scope proposed from the audit (`.superpowers/audit-1.4.0.md`) and approved by the owner ("yea let's go with 1.4.1"). Patch release: no new features; fixes, hardening, docs. Built on main @ 116bfc9 (1.4.0, signed, Latest).

## Rulings
- **No entitlement, fuse, signing or CI-workflow changes in this release** (the owner's standing rule; S-1 and S-10 stay open and are listed in the release notes' limits and as candidates for 1.5).
- No new on-disk keys except `terminal.screenReader` (a string `'auto' | 'on' | 'off'`, default `'auto'`).
- Everything else keeps the 1.4.0 rules (CLAUDE.md).

## Items
1. **Renderer crash recovery (R-3).** Main handles `render-process-gone` (any reason but `clean-exit`) and `unresponsive` (after 10 s still unresponsive) of the window's webContents: reload the page (`webContents.reload()`), at most 3 times in 60 s (then show one dialog through the counting `dialog` wrapper: "The window stopped responding" with Reload / Quit; Reload default); the daemon and shells are untouched (the reloaded page re-attaches and resyncs from snapshots); a one-line log (reason only) in the daemon-independent main log is NOT added (no new logging): use `console.error` only in unpackaged builds. A pure `crashAction({count, windowMs, reason})` in `src/shared/` decides (tested). While reloading, tips/tour/approval timers restart from scratch (existing behaviour of a reload).
2. **Incremental live cost (R-1).** `readLive`/`cost.ts` stop re-reading the whole turn: per session keep `{file, offset, partialTail, totals}`; each tick reads only the appended bytes (async `fs.promises`, from `offset`, ≤ 4 MB per tick, `setImmediate` yield), parses only complete lines, adds to the running totals (same dedupe by message id as today, same price table); a shrunk or replaced file (size < offset, or different inode/dev) resets that session's state and re-reads from the turn's start once; Stop's final count still uses the full `summarizeLines` over the turn (the existing correctness path) so totals cannot drift; tests: byte-for-byte equality of incremental totals vs a full read over random splits of a planted transcript (split mid-line, mid-UTF-8), reset on truncation, bounded bytes per tick, no sync fs calls on the live path (grep test), 4 sessions × 24 MB transcript stays under a few ms of sync work per tick.
3. **Screen reader.** xterm `screenReaderMode` follows `terminal.screenReader` (`'on'` always, `'off'` never, `'auto'` when macOS reports assistive technology: main listens to Electron's `accessibility-support-changed` and `app.isAccessibilitySupportEnabled()` and sends the page a boolean (new `jaffer:event` name `app.accessibility`, no new IPC channel); the setting is a select in Settings → Appearance (Terminal group) "Screen reader support" with hint "Exposes terminal text to VoiceOver. Slower with lots of output." Applied live to every pane's xterm. Tests: option wiring per mode, event handling, the select writes the key.
4. **OSC 8 hyperlinks.** Set xterm's `linkHandler` for every pane: `activate(event, uri)` opens only `http:` and `https:` URIs (validated with `new URL`, length ≤ 2048, no credentials in the URL: refuse `user:pass@`), and only with ⌘ held (like plain URL links), through the existing `window.jaffer.openExternal`; `file:` and everything else do nothing (a toast "Only web links open from the terminal" once per session); `hover`/`leave` show the URL in the title attribute of the terminal host? (a small tooltip via xterm's default is fine); never `confirm()`/`window.open`. Docs fix S-5: CLAUDE.md says a ⌘-click on a printed http(s) URL opens the browser (plain and OSC 8), and nothing else.
5. **Hardening batch.** (a) S-2: `jaffer:call` allow-list in main: a `Set` of the daemon methods the page may call (derive it from the actual `call('...')` sites in `src/renderer`, tested by a unit test that greps the renderer for method names and asserts each is on the list and each list entry is used somewhere or documented as test-only); everything else rejects with a fixed error. Daemon-only methods (`hello`, `claude.event`, `claude.approval`, `setup.cli.install`? decide by grep) never pass. (b) S-3: `session.defaultSession.setPermissionRequestHandler((_, __, cb) => cb(false))` and `setPermissionCheckHandler(() => false)` (deny all: the page needs none; clipboard writes use user gestures) with a note; verify the UI tests (clipboard copy via the bridge are browser-side, unaffected) and the Electron-only paths by reading. (c) S-4: the Stop and live cost readers open `transcript_path` through the same confinement as the other readers: extract ONE helper `openTranscript(claudeDir, file)` in `src/core/claude/transcript-open.ts` (realpath root `<claudeDir>/projects`, inside-root check, `O_RDONLY | O_NOFOLLOW`, regular file only, returns `{fh, size}` or null) and use it in history.ts, explain.ts, search.ts, usage-window.ts, cost.ts (keep each caller's behaviour; tests per caller still pass; new unit tests for the helper incl. links, FIFO, outside root, `..`). (d) S-6: `JAFFER_UPDATE_URL` honoured only when `!app.isPackaged`. (e) S-8: on daemon start, `chmod 0700` the `run/` folder and `~/.jaffer` itself if it is more open (best effort, only for folders that belong to the user). (f) `test/invariants.test.ts`: source scans (comment-stripped) that fail on: `dialog.show*` outside the counting wrapper in `src/main`, `shell.openPath` anywhere except the one allowed call, an `ipcMain.handle` whose handler does not call `trusted(`, `redactText(` called on input not clipped (heuristic: allow-list of known bounded call sites by file with a count; a new call site fails the test until added with a note), `child_process` spawns with `shell: true` or `exec(`, `ANTHROPIC_API_KEY` passed through; each rule with a comment naming the CLAUDE.md rule. (g) `SECURITY.md` (report vulnerabilities by email address of the repo owner? NO email: use GitHub's private vulnerability reporting link of the repository `https://github.com/jafforgehq/jaffer/security/advisories/new`; scope, what Jaffer protects and the local-trust model in plain words, supported versions: latest only).
6. **Real-Claude check of `claude mcp list` (S-7)** (investigation, no code unless it fails): in a throwaway folder with a `.mcp.json` whose server command is `/usr/bin/touch <marker file>`, run the installed `claude mcp list` once with the folder as cwd and see whether the unapproved project server was started (marker exists) and what the output looks like (a sample of the real text format with names only). Also record `claude --version`, `claude --help` flags for the Explain helper, never `claude -p`. If an unapproved project server IS started: the Setup "Check MCP servers" button must not run it for folders where `.mcp.json` lists servers the person hasn't approved: gate = skip the check and show "This folder has project servers you haven't approved; Claude Code asks you first" (Jaffer can't read approval state without ~/.claude.json: so the safe gate is: when the folder has a `.mcp.json`, run the check only from a neutral cwd (the home folder) and say project servers aren't checked). Document the finding either way in README (move the item from Not verified to Verified or state the gate).
7. **Docs and release.** CLAUDE.md/README/ARCHITECTURE for items 1-6 (crash recovery rule, incremental live cost, screen reader setting, OSC 8, allow-list, permission handlers, invariants test, SECURITY.md), the audit's open items listed under README limits (S-1 entitlements and fuses, CI pinning, no linter, 60 unverified items), `docs/releases/v1.4.1.md` (card ≤ 1200 chars before `<!-- card-end -->`, last line exact), version 1.4.1.
