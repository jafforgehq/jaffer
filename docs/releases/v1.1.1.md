## What is new in 1.1.1

**Past conversations have titles, and a click resumes the conversation in your terminal.** Jaffer is still one window, one shell and a companion: no tabs, no splits, no second window, no chat box. The one change in what Jaffer types is below, and it is the first since `claude` itself.

### Titles
- **Each of the 30 newest past conversations shows a title** in bold on its row, with the folder, the time, how long it lasted and the estimated cost underneath. Older rows say *Conversation*. The title is Claude Code's own title or summary line for the conversation when its transcript has one (a title you gave it wins), otherwise the first line of your first message. It is redacted like everything Jaffer shows (a token or a `password=` in it is masked), cut to one line of at most 80 characters, and never stored: it is read from the start and the end of the transcript when the panel opens, kept in memory, and gone when you quit.
- **The search matches titles as well as folders.**
- **The menu bar icon's list of conversations uses the title** (cut to 40 characters) when there is one, and the folder's name when there is not.
- **Still not read: anything else you or Claude said.** The title is the one piece of text Jaffer takes from a transcript. A later message, a reply and a tool's input never come out.

### Click to resume
- **A click on a conversation in the side panel, or Enter on the selected one, resumes it in the terminal.** Jaffer types `claude --resume <id>` and presses Enter. If your shell is in another folder than the conversation's, it types `cd '<folder>' && claude --resume <id>`. Before that it clears a half-typed line (Ctrl-E, then Ctrl-U) so your own text does not end up in the command. Then it says *Resuming…* and puts the keyboard back in the terminal.
- **It types only when the terminal is at an idle prompt.** While any command runs, Claude Code included, nothing is typed: the command is copied instead and a message says why (*Claude is already running here: quit it first (/exit)*, or *`sleep 31` is running: command copied*). A conversation whose folder is not known is copied, too, without the `cd`. The session id must be a real one, and a click counts once: a double click does not type twice.
- **A small copy button on each row** (it shows when you point at the row, and with the keyboard) copies the same command, with the `cd` when the folder differs, and types nothing.
- **The menu bar's conversations still only copy.** That menu cannot type.
- **This widens one rule on purpose.** Until now the only thing Jaffer typed into your shell was `claude` (`⇧⌘C`, and the first-run switch). Now it also types the resume line, only after your click or Enter on a conversation. Nothing else is typed, and nothing printed in the terminal is ever typed.

### Limits, honestly
- Jaffer knows the terminal is idle from the shell's own marks. A program that prints forged marks can make it look idle. A continuation prompt (a line left open by an unclosed quote or a trailing `\`) and the shell's vi command mode also count as idle, so a click there types the line into whatever the shell is waiting for. If you use those, copy the command with the copy button.
- Titles and the resume line have been checked against transcripts planted in the layout Claude Code is known to use, and in real bash, not yet against every version of Claude Code or on a real Mac with your own prompt and shell setup. The README's "Not verified here" lists this.

**What happens when you update**
- Nothing is moved or deleted and no new setting appears. Jaffer's hooks in `~/.claude/settings.json` are unchanged (the same eleven events). Updating from 0.5.x or earlier still runs the one-time clean-up of 0.6.0 (see below).

**Coming from 0.5 or earlier?** Jaffer has been a plain terminal since 0.6.0: the memory, the saved screen, *Resume Claude* and *Restart Claude Code*, the login agent and the Safety edges are gone, and quitting ends the shell and anything running in it (`⌘Q` asks first when Claude Code is working or a command runs; a logout, restart or shutdown and the Dock's *Quit* do not ask). On the first start Jaffer cleans up what they left, once (up to 30 seconds): it removes the login agent, **copies `~/.jaffer/memory/NOTES.md` and `POLICY.md` to `~/.jaffer-memory-backup/`** if you wrote something in them, **deletes `~/.jaffer/memory` and `~/.jaffer/session`**, removes only Jaffer's own entries from Claude Code's files (the marked block in `~/.claude/CLAUDE.md`, the `jaffer-*` skills, the `jaffer` MCP server) and drops the settings that no longer exist. **To keep anything from the memory, copy `~/.jaffer/memory` before you open this version for the first time** (if you update from inside the app, copy it before you click *Update and restart*). `jaffer config set migrated 0` runs the clean-up again; *Settings → Reset* does the same and more. If an older Jaffer's session is still running in the background, one dialog asks to end it (the default button is Quit).

Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.
