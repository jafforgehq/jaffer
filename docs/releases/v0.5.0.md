## What is new in 0.5.0

Jaffer now keeps the session, and the Claude Code conversation in it, running through the things that used to end them: a crashed daemon, a restart, an update. Nothing is installed on your Mac without your switch.

**New**
- **Claude comes back by itself.** After a restart Jaffer types `claude --resume <id>` for the conversation that was running, after a 3-second notice with a **Cancel**. It waits for an empty prompt and a quiet 2 seconds, never adds to a line you started typing, and tries at most 3 times in 10 minutes before leaving the **Resume Claude** button. It does not resume a conversation you ended yourself (`/exit`, Ctrl+C, *Quit and End Session*) or a `claude -p` run. Switch it off in *Settings → Claude Code → Resume Claude automatically*.
- **Restart Claude Code, to use an update** (command palette, or *Settings → Claude Code*). After Claude Code has updated itself, one action restarts your shell in the same folder and takes up the same conversation on the new version. It asks first, because anything else running in the shell stops. It works with automatic resume off.
- **Keep my session running in the background** (*Settings → Appearance*, off by default; the first-run step offers it on). It installs a login agent so that macOS starts the session at login and again if the daemon crashes or is killed, with or without the window open. `jaffer service [status|install|remove]` does the same from the command line. It works only for the usual `~/.jaffer` and an app in Applications, and *Settings → Reset* and `jaffer reset` remove it. Turning it off while macOS is running your session ends that session, so Jaffer asks first.
- **Your Mac stays awake while Claude works** (*Settings → Appearance*, on by default). While Claude or a background agent works, or a command has run for 30 seconds or more, the Mac does not go to sleep on its own; the screen still can. It needs no admin rights and lets go 15 seconds after the work stops. **It does not override the lid:** a laptop on its own with the lid closed still sleeps and everything pauses until it wakes; with power, an external display and a keyboard or mouse it keeps working (not yet checked on a real Mac, see below).
- **A notice, never a kill, for two Claude conversations.** If a second one starts while another is running, Jaffer says so once and resumes the newest after a restart. It ends neither.

**Changed**
- *Quit and End Session* now forgets the conversation: Claude is not resumed at the next start. An update or *Restart session* still resumes it.
- A shell that exits (a crash, *Restart shell*) now takes its Claude with it in Jaffer's view, so the resume offer comes back in the new shell.
- The daemon reads only the first 4096 characters of a command line when it decides whether it was a `claude` run, a print-mode run or an interactive program, so a line forged by program output cannot make it slow.

**By hand, on your Mac**
The launchd and power parts are tested against stand-ins, because the real ones touch your LaunchAgents and power settings. Not yet checked on a real Mac: launchd restarting a killed daemon in about 5 seconds, `kickstart` on a running job, turning the switch off from inside the job it ends, launchd's minimal environment for the daemon, `pmset -g assertions` showing the hold while Claude works and not after, a closed lid with and without power and a display, a reboot, and an update with the agent on.

Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.
