## What is new in 0.5.0

Jaffer now brings your session back after the things that used to end it: a crashed daemon, a restart, an update. The folder, the screen (as last saved, with *Keep the screen for a restart* on) and the Claude Code conversation come back; programs that were running in the shell stop and are not restarted. Nothing is installed on your Mac without your switch.

**New**
- **Claude comes back by itself.** After a restart Jaffer types `claude --resume <id>` for the conversation that was running, after a 3-second notice with a **Cancel**. It types only when the shell itself has the terminal (never while a program such as `ssh` runs, even one that prints a shell's prompt marks), at an empty prompt after a quiet 2 seconds; it never adds to a line you started typing (typing while the notice counts down counts as a Cancel); and it tries at most 3 times in 10 minutes before leaving the **Resume Claude** button. It does not resume a conversation you ended yourself (`/exit`, Ctrl+C, *Quit and End Session*) or a `claude -p` run. Switch it off in *Settings → Claude Code → Resume Claude automatically*.
- **Restart Claude Code, to use an update** (command palette, or *Settings → Claude Code*). After Claude Code has updated itself, one action restarts your shell in the same folder (programs running in it stop) and takes up the same conversation on the new version. It asks first, because anything else running in the shell stops. It works with automatic resume off.
- **Keep my session running in the background** (*Settings → Appearance*, off by default; the first-run step offers it on). It installs a login agent so that macOS starts the session at login and again if the daemon crashes or is killed, with or without the window open. Turned on while a session is already running (the first-run switch too), it only installs the agent: Settings reads *installed, active from the next login or restart*, and launchd takes over at your next login or the next time Jaffer starts the session; until then a crashed daemon is not restarted. `jaffer service [status|install|remove]` does the same from the command line (`remove` also works when no daemon answers). If launchd cannot start the daemon, Jaffer starts it itself after a few seconds. It works only for the usual `~/.jaffer` and not for an app run from a disk image or a temporary location, nor for a development run; *Settings → Reset* and `jaffer reset` remove it. Turning it off while macOS is running your session ends that session, so Jaffer asks first. The agent names Jaffer as its app, so that *Login Items → Allow in the Background* can list it under Jaffer.
- **Your Mac stays awake while Claude works** (*Settings → Appearance*, on by default). While Claude or a background agent works, or a command has run for 30 seconds or more, the Mac does not go to sleep on its own; the screen still can. It needs no admin rights and lets go 15 seconds after the work stops. **It does not override the lid:** a laptop on its own with the lid closed still sleeps and everything pauses until it wakes; with power, an external display and a keyboard or mouse it keeps working (not yet checked on a real Mac, see below).
- **A notice, never a kill, for two Claude conversations.** If a second one starts while another is running, Jaffer says so once and resumes the most recently active conversation after a restart. It ends neither.

**Changed**
- *Quit and End Session* now forgets the conversation: Claude is not resumed at the next start. An update or *Restart session* still resumes it.
- A shell that exits (a crash, *Restart shell*) now takes its Claude with it in Jaffer's view, so the resume offer comes back in the new shell.
- Jaffer reads only the first 4096 characters of a command line when it decides whether it was a `claude` run, a print-mode run or an interactive program, so a line forged by program output cannot make the daemon or the window slow.

**Known limitation**
Automatic resume trusts the prompt marks that Jaffer's own shell integration prints. A program inside your own shell (a background job, or a function or script the shell runs) that prints those same marks can make Jaffer think the shell is at an empty prompt; with a half-typed line and a quiet pause the resume line could then be added to it. The notice stays visible and cancellable, and *Resume Claude automatically* can be switched off. A per-shell secret on the marks would close it and is planned.

**By hand, on your Mac**
The launchd and power parts are tested against stand-ins, because the real ones touch your LaunchAgents and power settings; on macOS the generated plist is only linted with `plutil`. Not yet checked on a real Mac: a real `launchctl bootstrap` of the generated plist and a real bootout and uninstall, launchd restarting a killed daemon in about 5 seconds (once launchd runs the daemon, which is after the next login or restart of the session with the switch on), `kickstart` on a running job and during launchd's throttle after a crash, turning the switch off from inside the job it ends, launchd's minimal environment for the daemon, logging out and in (which is what loads an agent installed into a running session), the wrapper removing the agent when the app is deleted or moved, *Login Items → Allow in the Background* showing the agent as Jaffer (and Jaffer starting the daemon itself when that item is not allowed), `pmset -g assertions` showing the hold while Claude works and not after, a closed lid with and without power and a display, a reboot, and an update with the agent on.

Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.
