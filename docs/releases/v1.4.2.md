## What is new in 1.4.2

**A fix release: the Setup list now tells the truth about your MCP servers and finds all your skills.**
- **Working MCP servers are no longer called failed.** *Check MCP servers* now runs with your shell's `PATH`, so servers started with `npx`, `node` or `uvx` connect as they do in Claude Code.
- **The claude.ai connectors are listed** (Gmail, Google Drive and the others), and so are plugin servers.
- **Skills from your plugins, and the skills the Claude app syncs, are listed** in Skills, each with whether it is on.

**Jaffer 1.4.2 is a patch release with three fixes to the side panel's Setup list**, found on a real Mac where Claude Code's own `/mcp` showed servers connected that Jaffer showed as *Failed to connect*, and where Skills said 0. It adds no setting and changes no signing, entitlement or update setting. The notes of 1.4.1 and 1.4.0 still apply.

### What changed
- **The MCP check uses your shell's `PATH`.** A Mac app started from the Dock gets only `/usr/bin:/bin:/usr/sbin:/sbin`, so `claude mcp list`, run by Jaffer, could not find `npx` and reported those servers as failed. The shell integration (zsh, bash and fish) now tells the terminal its `PATH` after your startup files ran, before a prompt and only when it changed. *Check MCP servers* runs with the `PATH` of the terminal you have focused. Until a shell has reported one, it uses the app's own `PATH` with `~/.local/bin`, `/opt/homebrew/bin`, `/opt/homebrew/sbin` and `/usr/local/bin` added when they exist. The report carries a random value that the shell keeps out of its environment, so text a program prints cannot change the `PATH` of the check, and only absolute folders are used: a `.` in your `PATH` never makes the check run a program of the folder it checks. The `PATH` stays in memory and is never logged.
- **Server names with spaces.** `claude mcp list` prints claude.ai connectors as `claude.ai <Name>: <address> - <state>`; the old reader skipped any name with a space, so they were missing. A name still ends at the first `: `; only on a `claude.ai ` line may it end at a later one, the first that an address follows. `plugin:<plugin>:<server>` names stay whole as before. Only names and states are shown, never an address, a command or an error text.
- **More skills.** Besides `~/.claude/skills/<name>` and the project's `.claude/skills/<name>`, Setup now looks up to three folders deep in `~/.claude/skills` (the Claude app syncs skills to `~/.claude/skills/synced/<id>/<name>`) and into the `skills` folder of each installed plugin (only when the plugin's install is inside `~/.claude/plugins`). A plugin's skills are labelled with the plugin and are on while the plugin is enabled. At most 300 skills are listed.

### Limits
- Only `PATH` comes from your shell. A server that needs something else your startup files set, such as a variable only your rc file exports, can still fail in the check although it works in Claude Code.
- The fish script was not run in the tests (zsh and bash were), and the list has not yet been compared with `claude /mcp` on the Mac where the bug was found.

Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.
