## What is new in 1.4.1

**A hardening release: a crashed window comes back, live cost is lighter, and the security story is written down.**
- **A crashed window reloads itself.** Your terminals keep running and the window attaches to them again. After three crashes in a minute it asks first.
- **Live cost is lighter.** While Claude works, Jaffer reads only what was added to the conversation file, not the whole turn again.
- **Screen reader support.** *Settings → Appearance → Screen reader support* (Auto, On, Off) exposes terminal text to VoiceOver.
- **Terminal links.** A ⌘-click opens a web link a program printed with the terminal's link escape; the address shows when you hover it.
- **Safer inside.** The window may call only the terminal-host methods it uses, and the conversation files Jaffer reads are opened more carefully.
- **`SECURITY.md`** says how to report a problem and what Jaffer does and does not protect.

**Jaffer 1.4.1 is a patch release that follows a security and reliability review of 1.4.0.** It adds one setting and no new feature, and it changes no signing, entitlement or update setting. Everything from 1.4.0 (split terminals, the privacy screen, Setup, Explain) is as it was, and the notes of 1.4.0 still apply.

### What changed
- **A crashed or hung window is reloaded.** If the window's page crashes, or hangs for ten seconds, Jaffer reloads it; the shells and Claude Code are in a separate process and are not touched, and the page draws each terminal again from its snapshot. If it crashes three times within a minute, a question appears: *Reload* (the default, and Esc) or *Quit* (quitting ends your terminals).
- **Live cost reads only what is new.** The greyed "so far" figure used to read the whole turn again every two seconds, up to 24 MB for each of four sessions. It now keeps where it stopped and reads at most 4 MB a tick in all, with a pause between pieces. The figure after an answer (Stop) is counted as before, so on a turn longer than 24 MB the live figure can be a little higher and then drop to Stop's number.
- **Screen reader support.** *Settings → Appearance → Screen reader support*: *Auto* turns terminal text on for VoiceOver when macOS reports an assistive tool (this can also happen for other assistive tools; *Off* switches it off), *On* always, *Off* never. It is slower with a lot of output.
- **Links.** A program can print a hyperlink with a hidden address (OSC 8). A ⌘-click opens it only when it is a web link (`http` or `https`, no login in the address, not longer than 2048 characters); the real address shows as a tooltip when you hover the link. Files and other kinds of link are not links. A web link Jaffer refuses says why, once. A plain printed `http(s)` address also opens on ⌘-click, as before (the project's own rules said otherwise: that was wrong).
- **Safer inside.** The window may call only the terminal-host methods it actually uses. It is allowed one web permission, writing the clipboard (a program's OSC 52 and *Copy as image* need it), and nothing else. Every file of Claude's that Jaffer reads for cost, context, search, Explain or the stop line is opened through one careful routine (it stays inside `~/.claude/projects`, never waits on a named pipe, and notices a swapped file). A transcript outside that folder gets no cost. Jaffer's folder and its socket folder are made private (0700) at start if an older version left them open, and the update feed can no longer be redirected by an environment variable.
- **`SECURITY.md`.** How to report a vulnerability privately, what Jaffer protects, what leaves your Mac, and what it does not protect against. A new test (`test/invariants.test.ts`) keeps eight of the project's rules from being broken by accident.
- **Check MCP servers.** Verified on Claude Code 2.1.302: `claude mcp list` does not start a project's `.mcp.json` servers that you have not approved (it lists them as waiting for approval). A repository's own settings can approve them, so when a folder has a `.mcp.json` and settings that do, Jaffer runs the check from your home folder instead and says so.

### What is still open
- **A same-user program can borrow Jaffer's permissions** (audit S-1). The app keeps the Electron "run as Node" fuse and two entitlements, so another program of yours can run code as Jaffer's signed binary and inherit what macOS has granted it. Closing it needs the terminal host to stop running as Electron-as-Node: planned, not in this release.
- **CI** pins its actions by tag and sets no default token permissions (S-10). **No linter or formatter** yet; the new invariants test covers some rules, not all.
- **The unverified list is long.** About 60 behaviours (the menu bar item, the packaged dialogs, the real Claude Code hook semantics and more) have been checked only in a browser or with stand-ins; the README's *Not verified here* lists them. The crash reload and the screen reader mode are Electron wiring that no test runs, and VoiceOver itself was not tried.
- **`CLAUDE_CONFIG_DIR`** set only in a shell startup file (not in the app's environment) means Jaffer looks in `~/.claude` and shows no cost or context for conversations kept elsewhere.
- With several sessions catching up at once, the live cost serves them in the order Claude Code reported them, not in turn.
- A local program holding many socket connections can still make the terminal host use memory (S-9); it needs your user account.

**What happens when you update**
- Nothing is moved or deleted. One setting appears with its default: `terminal.screenReader` (`auto`). Nothing new is written to disk about your work.

Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.
