## What is new in 0.6.0

**Jaffer is now a plain terminal with the companion.** One shell, a thin title bar, and the animations that show what Claude Code is doing. Everything that existed only to bring a session back, or to remember things, is gone.

**Quitting ends the session.** `⌘Q` (*Quit Jaffer*) quits Jaffer and ends the shell and anything running in it. When Claude Code is working or a command is running, it asks first (*Quit Jaffer?*, **Quit** or **Cancel**; the default button is Cancel and Esc cancels). **Only that menu item asks.** A logout, restart or shutdown, an AppleScript quit and *Quit* in the Dock's menu end the session without asking, and a running Claude Code or command stops (macOS would take a question at logout as the app refusing to quit and cancel the logout). `⌘W` only hides the window, and the global hotkey brings it back. Updating ends the session too, as it always did, and a fresh terminal starts. A second copy of Jaffer opened while one runs brings the first window forward instead of starting another: if the older Jaffer app is still open when you start 0.6.0, 0.6.0 exits at once, so quit the older Jaffer first.

**Removed**
- **Memory**: the drawer and `⇧⌘M`, the learning from your sessions, the MCP tools for Claude Code, the exports into `~/.claude/CLAUDE.md` and skills, `jaffer remember`, `recall`, `forget`, `context`, `memory` and `mcp`, and the memory's data on disk.
- **The saved screen, Resume Claude, Restart Claude Code** and the notice for two Claude conversations. A shell that exits is replaced by a fresh one in the same folder with a blank screen.
- **The login agent** (*Keep my session running in the background*, `jaffer service`) and a session that outlives the app. *Quit and End Session* and *Quit Jaffer (session keeps running)* are gone with it.
- **The Safety edges** (the amber edge on a protected branch, the red one while `ssh` runs).

**Why.** The saved screen was replayed into the new shell after an update, with the terminal modes the old program had set. One of them, mouse reporting, made the new shell receive mouse movements as typed text. That bug is gone with the restore: a new shell gets a blank screen and nothing is replayed into it. Resume, the login agent and the background session existed around that restore, and the memory is a part of Jaffer that a plain terminal does not need.

**What happens on the first start of 0.6.0**

Installing 0.6.0 over a running 0.5 or earlier ends that session. If an older Jaffer's session is still running in the background when you open 0.6.0 (Jaffer waits up to 3 seconds first, in case it is just ending), one dialog asks: **End it** (its shell and anything running in it stop, and a fresh terminal starts) or **Quit** (nothing is ended; the default button is Quit and Esc means Quit).

Then, once, Jaffer cleans up what the removed features left on your Mac. It usually takes a second or two (it is limited to 30 seconds, and the window opens after it):

- it takes away the **login agent**: `~/Library/LaunchAgents/com.jafforge.jaffer.daemon.plist`, `~/.jaffer/bin/jafferd` and its job in launchd;
- it **copies `~/.jaffer/memory/NOTES.md` and `POLICY.md` to `~/.jaffer-memory-backup/`** when you wrote something in them (a `POLICY.md` that still holds the text Jaffer put there is not yours and is not copied; nothing is overwritten there);
- it **deletes `~/.jaffer/memory` and `~/.jaffer/session`** (the memory, the saved screen and scrollback, the saved folder, the remembered conversation). **To keep anything from the memory, copy `~/.jaffer/memory` somewhere before you open 0.6.0 for the first time**. That is easy when you install by dragging the app in; if you update from inside the app, the first start follows at once after *Update and restart* (the prompt you see then is the one of the version you are updating FROM: it says *Your memory is kept* and that the shell comes back in the same folder, and neither is true for this update), so copy it before you click;
- it removes **Jaffer's own entries in Claude Code's files** and nowhere else: the marked block in `~/.claude/CLAUDE.md` (and in `~/.codex/AGENTS.md` and `~/.gemini/GEMINI.md`, where the first builds also wrote it), the `jaffer-*` skills that carry Jaffer's marker line, and the `jaffer` MCP server (`claude mcp remove jaffer -s user`). The rest of those files is left as it was, byte for byte;
- it drops the settings that no longer exist (memory, Safety, saved screen, resume, background session) from `~/.jaffer/config.json`; your other settings stay.

Jaffer's hooks in `~/.claude/settings.json` stay, and are rewritten at the start of the terminal. `~/.jaffer/migrate.log` gets one "started" line, one summary line with the result of every step, and one line for each step that failed (step names and error codes, never paths or content). A step that fails does not stop the others and is not retried at every start; `jaffer config set migrated 0` runs it all again at the next start, and *Settings → Reset* does the same cleanups and more. The clean-up only touches your Claude Code files and launchd when Jaffer runs on the usual `~/.jaffer`: a build started with another `JAFFER_HOME` cleans up inside that folder (the one exception: the two memory files are copied to `~/.jaffer-memory-backup/`).

**What stays**
- The terminal: themes, command palette, find, text size, the global hotkey, drag a file in to paste its path.
- The **companion**: the mole and five scenes, with a helper for every background agent, driven by Claude Code's hooks.
- **Notifications** (Claude needs you, a long turn finished, a long command finished), the **cost figure** per answer, and the sign-in help for Claude Code (Claude stays optional; a plain terminal is one click).
- **Your Mac stays awake while Claude works** (an idle-sleep hold, no admin rights; a closed lid still sleeps).
- **Updates ask first**, and **Reset**.

**Changed**
- Claude Code's `SessionStart` and `Stop` hooks are now asynchronous and silent, like the other eight: Claude Code no longer waits for Jaffer when a session starts or when an answer ends. One caveat: the cost of a `claude -p` run can be missed when its Stop hook arrives after its SessionEnd (a 10-second grace covers most cases).
- `jaffer` talks to the running app and never starts a terminal: with Jaffer closed, `status` and `doctor` say so and `daemon start` fails, `config` falls back to the config file, `setup claude --status` and `--remove` work, and installing the hooks needs the wrapper `~/.jaffer/bin/jaffer` that the app writes when it starts. `jaffer daemon stop` ends the session, and the app quits with it. What is left: `status`, `doctor`, `config`, `setup claude` (the hooks), `daemon [status|stop]`, `reset` and `hook` (Claude Code's own).
- If the app crashes or is killed, its terminal ends with it; if the terminal itself stops, Jaffer says so and offers a fresh one or Quit.
- *Reset* also takes away what older versions left (the login agent, the memory tools in Claude Code, the block in `CLAUDE.md`, the skills).

**By hand**
- A Claude Code conversation is yours to take up again: `claude --resume` and `claude -c` work as always, typed by you. Jaffer no longer offers them.
- `~/.jaffer-memory-backup/` holds your own notes if you had any: keep it or delete it. Nothing reads it.
- Not yet checked on a real Mac, and not verified until the owner has checked it there: the first start on a Mac that ran an older Jaffer (a real `launchctl bootout` of the installed agent, a real `claude mcp remove`, the dialog when an older session is still running), the terminal ending when the app is killed (tested with a stand-in for the app), the quit question, the older-session question and the terminal-stopped dialog of the packaged app (including what Return does in the first two, where one button is both default and cancel), a logout, restart or shutdown with Claude Code or a command running (the session should end without a question and the logout go on), *Settings → Reset* in the packaged app, starting 0.6.0 while the older Jaffer app is open (it should exit at once and bring the old window forward), `pmset -g assertions` and a closed lid for staying awake, and a desktop notification.

Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.
