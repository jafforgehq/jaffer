## What is new in 0.6.0

**Jaffer is now a plain terminal with the companion.** One shell, a thin title bar, and the animations that show what Claude Code is doing. Everything that existed only to bring a session back, or to remember things, is gone.

**Quitting ends the session.** `⌘Q` quits Jaffer and ends the shell and anything running in it. When Claude Code is working or a command is running, Jaffer asks first (*Quit Jaffer?*, **Quit** or **Cancel**; Return means Cancel). `⌘W` only hides the window, and the global hotkey brings it back. Updating ends the session too, as it always did, and a fresh terminal starts. A second copy of Jaffer opened while one runs brings the first window forward instead of starting another.

**Removed**
- **Memory**: the drawer and `⇧⌘M`, the learning from your sessions, the MCP tools for Claude Code, the exports into `~/.claude/CLAUDE.md` and skills, `jaffer remember`, `recall`, `forget`, `context`, `memory` and `mcp`, and the memory's data on disk.
- **The saved screen, Resume Claude, Restart Claude Code** and the notice for two Claude conversations. A shell that exits is replaced by a fresh one in the same folder with a blank screen.
- **The login agent** (*Keep my session running in the background*, `jaffer service`) and a session that outlives the app. *Quit and End Session* and *Quit Jaffer (session keeps running)* are gone with it.
- **The Safety edges** (the amber edge on a protected branch, the red one while `ssh` runs).

**Why.** The saved screen was replayed into the new shell after an update, with the terminal modes the old program had set. One of them, mouse reporting, made the new shell receive mouse movements as typed text. That bug is gone with the restore: a new shell gets a blank screen and nothing is replayed into it. Resume, the login agent and the background session existed around that restore, and the memory is a part of Jaffer that a plain terminal does not need.

**What happens on the first start of 0.6.0**

Installing 0.6.0 over a running 0.5 or earlier ends that session. If an older Jaffer's session is still running in the background when you open 0.6.0, one dialog asks: **End it** (its shell and anything running in it stop, and a fresh terminal starts) or **Quit** (nothing is ended; Return and Esc mean Quit).

Then, once, Jaffer cleans up what the removed features left on your Mac. It usually takes a second or two (it is limited to 30 seconds, and the window opens after it):

- it takes away the **login agent**: `~/Library/LaunchAgents/com.jafforge.jaffer.daemon.plist`, `~/.jaffer/bin/jafferd` and its job in launchd;
- it **copies `~/.jaffer/memory/NOTES.md` and `POLICY.md` to `~/.jaffer-memory-backup/`** when you wrote something in them (a `POLICY.md` that still holds the text Jaffer put there is not yours and is not copied; nothing is overwritten there);
- it **deletes `~/.jaffer/memory` and `~/.jaffer/session`** (the memory, the saved screen and scrollback, the saved folder, the remembered conversation). **To keep anything from the memory, copy `~/.jaffer/memory` somewhere before you open 0.6.0 for the first time**;
- it removes **Jaffer's own entries in Claude Code's files** and nowhere else: the marked block in `~/.claude/CLAUDE.md` (and in `~/.codex/AGENTS.md` and `~/.gemini/GEMINI.md`, where the first builds also wrote it), the `jaffer-*` skills that carry Jaffer's marker line, and the `jaffer` MCP server (`claude mcp remove jaffer -s user`). The rest of those files is left as it was, byte for byte;
- it drops the settings that no longer exist (memory, Safety, saved screen, resume, background session) from `~/.jaffer/config.json`; your other settings stay.

Jaffer's hooks in `~/.claude/settings.json` stay, and are rewritten at the start of the terminal. A line for each step is in `~/.jaffer/migrate.log` (names and error codes, never paths or content). A step that fails does not stop the others and is not retried at every start; `jaffer config set migrated 0` runs it all again, and *Settings → Reset* does the same cleanups and more. It only touches your Claude Code files and launchd when Jaffer runs on the usual `~/.jaffer`: a build started with another `JAFFER_HOME` cleans up inside that folder only.

**What stays**
- The terminal: themes, command palette, find, text size, the global hotkey, drag a file in to paste its path.
- The **companion**: the mole and five scenes, with a helper for every background agent, driven by Claude Code's hooks.
- **Notifications** (Claude needs you, a long turn finished, a long command finished), the **cost figure** per answer, and the sign-in help for Claude Code (Claude stays optional; a plain terminal is one click).
- **Your Mac stays awake while Claude works** (an idle-sleep hold, no admin rights; a closed lid still sleeps).
- **Updates ask first**, and **Reset**.

**Changed**
- Claude Code's `SessionStart` and `Stop` hooks are now asynchronous and silent, like the other eight: Claude Code no longer waits for Jaffer at the start or the end of a turn.
- `jaffer` talks to the running app and never starts a terminal: with Jaffer closed, `jaffer status` and the like say so. `jaffer daemon stop` ends the session, and the app quits with it. What is left: `status`, `doctor`, `config`, `setup claude` (the hooks), `daemon [status|stop]`, `reset` and `hook` (Claude Code's own).
- If the app crashes or is killed, its terminal ends with it; if the terminal itself stops, Jaffer says so and offers a fresh one or Quit.
- *Reset* also takes away what older versions left (the login agent, the memory tools in Claude Code, the block in `CLAUDE.md`, the skills).

**By hand**
- A Claude Code conversation is yours to take up again: `claude --resume` and `claude -c` work as always, typed by you. Jaffer no longer offers them.
- `~/.jaffer-memory-backup/` holds your own notes if you had any: keep it or delete it. Nothing reads it.
- Not yet checked on a real Mac, and not verified until the owner has checked it there: the first start on a Mac that ran an older Jaffer (a real `launchctl bootout` of the installed agent, a real `claude mcp remove`, the dialog when an older session is still running), the terminal ending when the app is killed (tested with a stand-in for the app), the quit question and the terminal-stopped dialog of the packaged app, `pmset -g assertions` and a closed lid for staying awake, and a desktop notification.

Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.
