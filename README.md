## Why Jaffer

- **One terminal.** No tabs of throw-away shells, no splits, no extra windows and no "new chat": one shell in a calm window with a thin title bar and one side panel. Quitting Jaffer ends the shell and anything running in it: `⌘Q` (the menu's *Quit Jaffer*) asks first when Claude Code or a command is running, while a logout, restart or shutdown, or *Quit* in the Dock's menu, end the session without asking. The window's ✕ and `⌘W` do not quit: they hide the window to the menu bar and the terminal runs on (you can change that in *Settings → Appearance → Window*). Nothing of the terminal is saved or replayed: the next start is a fresh shell.
- **Life when something happens.** A small animation in the corner works while a command or Claude works, sits up when Claude needs you and celebrates when a turn ends. Choose a mole, digital rain, an agent network, a starfield, a radar or a reactor core.
- **Claude Code, optional.** It runs inside Jaffer like anywhere else (real TTY, truecolor, mouse, `Shift+Enter`); connect it and the companion, the notifications and a per-answer cost figure follow it. A plain terminal is one click at first launch.

## Install

Download the `.dmg` for your Mac (Apple Silicon `arm64` or Intel `x64`) from [Releases](https://github.com/jafforgehq/jaffer/releases) and drag Jaffer to Applications. Releases are signed and notarized and come with a `SHA256SUMS.txt`; how they are built and published is in [docs/SIGNING.md](docs/SIGNING.md). An unsigned preview built by CI needs `xattr -dr com.apple.quarantine /Applications/Jaffer.app` once.

To build it yourself (a local build opens with no warnings): `./scripts/install-mac.sh` (Node 22+).

**Updates ask first.** The signed app checks for a new release, downloads it in the background and then asks *Update and restart* or *Later*. Updating ends your terminal session (the shell and anything running in it stop and a fresh terminal starts), so the prompt says so, and nothing installs without your yes, not even on quit. The background check can be switched off in *Settings → Updates*.

On first launch Jaffer asks what it may do: sign in to Claude or use a plain terminal, follow Claude Code (its hooks), start `claude` for you. Sign-in opens your browser and nothing more: nothing is installed or typed until you click *Get started*, and a plain terminal installs and types nothing at all.

**Coming from 0.5 or earlier?** Jaffer has been a plain terminal since 0.6.0: the memory, the saved screen, *Resume Claude* and *Restart Claude Code*, the login agent that kept a session running in the background and the Safety edges are gone, and quitting Jaffer ends the shell. The first start cleans up what they left on your Mac, once, and keeps a copy of the two memory files you wrote yourself, if there are any. What it removes and what stays is in the [1.1.1 release notes](docs/releases/v1.1.1.md) (the clean-up is unchanged since 0.6.0).

All six behave the same way. They sleep when nothing runs, rest while Claude Code is open, work while a command or Claude works, sit up with an alert when Claude needs you, and celebrate when a turn ends. **The longer the work takes, the harder they go**: faster after 30 seconds, strained after 2 minutes, at full tilt after 5. **Every background agent brings a helper** (up to three) that celebrates when its agent finishes. **They notice the tool:** the mole shows a book while Claude reads, a hammer while it writes, an antenna for the web and a hard hat for agents (a helper mole shows its own agent's tool), and the scenes change colour or rhythm. After ten minutes of nothing they doze (dimmer, slower) and wake at any activity. When a command that failed three times in a row finally exits 0, a short burst of sparks says so, and a bell makes the companion flinch (and, with the window behind, bounces the Dock icon once).

They are decoration only: they ignore the mouse, stand still with *Settings → Appearance → Animations* off or macOS *Reduce motion* on, take their colours from the theme, and never type or send anything.

## Claude Code

There is exactly one Claude: the `claude` in your terminal (`⇧⌘C`, or just type it). You talk to it there, with its own permission prompts; Jaffer adds no second chat or prompt box (its side panel only shows what Claude is doing) and, unless you switch on the experimental permission prompts below, answers none of Claude Code's questions. Claude Code reports what it does through hooks, and Jaffer turns that into the companion, the title-bar ring, the notifications and the cost figure. It follows only a `claude` running in Jaffer's own terminal, redacts everything it handles, and notices a declined prompt or `Esc` from the transcript (Claude Code fires no hook for those).

Jaffer runs on Claude **subscriptions** only: there is no API key anywhere (`ANTHROPIC_API_KEY` is ignored), and whether you are signed in comes from `claude auth status`. Sign-in opens your browser and nothing is typed into your terminal for it. Jaffer types two things into your terminal: `claude`, when you press `⇧⌘C` or leave *Start Claude Code in the terminal now* on at first launch, and, since 1.1.1, the resume line of a past conversation, only after your own click, Enter (in the panel or in the command palette) or `⇧⌘R` (since 1.2.0), and only at an idle prompt.

- **The hooks.** *Settings → Claude Code → Connect* (or `jaffer setup claude`) adds Jaffer's hooks to `~/.claude/settings.json`: eleven events (prompts, tool calls, background agents, notifications, the end of a turn, the start and end of a session, and the moment before Claude compacts its context), all asynchronous, so they never delay Claude, and all of them do nothing outside Jaffer's own terminal. The experimental permission prompts (below) add a twelfth, the one hook that makes Claude Code wait, only while that switch is on. Your own hooks and settings are never touched, only entries tagged `jaffer-managed`; *Disconnect* (or `--remove`) takes them out.
- **What each answer cost.** After every answer a figure like `≈ $0.04` appears in the title bar; while Claude works it grows, greyed (`≈ $0.03 so far`, read from the token counts every 2 seconds; *Settings → Claude Code → Live cost* turns that off). Hover for the tokens, the session total, **today's total** and the cost and length of the last 20 turns as two small lines. Set a *Daily budget* and the figure turns yellow at 80 % of it and red past it (nothing is stopped). It is an **estimate**: Jaffer adds up the token counts in Claude Code's own transcript (numbers only, never the words) at Anthropic's API list prices. On a subscription nothing is billed per token, so read it as what the work would be worth. A model without a known price shows tokens, not a guess, and background agents' own usage is not counted. Today's total and the turn history live in memory and start again when Jaffer quits.
- **What Claude is doing.** While it works, the ring beside the folder fills against how long a turn usually takes (the median of your last ones; before there is one it just spins, and past it the ring stays full and pulses); it turns dotted while Claude compacts its context. Hover it for the session clock (`Claude · 42 min · 9 turns · ≈ $1.20`) and each running agent's time. A 2 pixel strip under the title bar shows this turn's tool calls as segments coloured by kind (red when one failed) and as wide as they took. A pencil chip names the file Claude is editing (click to show it in Finder), and when it needs you the title bar says which tool and what it asks, and "2nd time" when you have already answered a prompt for that tool in this session. **You answer in the terminal: Jaffer answers nothing**, unless you switch on the experimental permission prompts below, and then only after your click on *Allow* or *Deny*.
- **When a turn ends** (10 seconds or more, not cut short) a toast says how long it took, what it did (`3 reads, 2 edits, 1 shell`), the cost, and lists the files it edited (up to five, each a button that shows it in Finder). *Settings → Claude Code → Turn summary* turns it off. Claude's edited files are remembered by name for the session only, never a path that looks like a key or a credential, and nothing else about the files.
- **The side panel.** The *Now* card at the top of the panel (`⌘B`) is the same information as the title bar, in words: the state, the tool and the turn's time, this turn's counts (`3 reads · 2 edits · 1 shell`), up to eight edited files (a click shows one in Finder), the running agents (numbered, never by id), the estimated cost and today's total (with *Show what each answer cost*, and with the same *estimate* note), and the summary when a turn ends. When Claude needs you it names the tool and says to answer in the terminal (or, with the experimental switch, offers *Deny* and, when the request is shown whole, *Allow*). Since 1.2.0 it also draws small bars for the last twenty turns once there are two (the height is how long a turn took, the tint what it cost compared with the others; hover a bar for the numbers) and *Claude worked 1h 12m today*, the time of today's finished turns plus the one running (memory only; it starts again at midnight and when Jaffer quits, and a turn you cut short is not counted). **What's New:** after an update a card above *Now* shows the release notes you have not seen (from the app itself, nothing is fetched); *Dismiss* hides it, *All versions* lists every version, and *Help → What's New…* and the palette open it any time. Closed, the panel renders nothing and reads nothing; open or closed, the terminal is fitted once per change, not on every pixel of a drag.
- **Past conversations.** The lower half of the side panel. `⇧⌘O` (or *Past Claude conversations…* in the palette, the *Shell* menu and *All Past Conversations…* in the menu bar icon's menu) opens the panel if it is closed and puts the cursor in its search. It lists the last 50 conversations Claude Code has kept for you, newest first under *Today*, *Yesterday* and the date; the ones you pinned (the star on a row, up to 50) come first in a *Pinned* group and stay listed even when they are older. Each row has a **title** in bold (for the newest 30: Claude Code's own title or summary line for the conversation, else the first line of your first message; older rows say *Conversation*) and under it the folder it began in, when it ended, how long it lasted and, for the newest 30 and with *Show what each answer cost* on, an estimated cost (`≈ $0.11`, or a dash when there is none). Type to filter by name, title or folder, or pick a folder chip (*All* and your five most used folders); ↑ and ↓ move. **Rename** a conversation with the pencil or `F2` (Enter saves, Esc cancels): your own name wins over the title in the rows, the search, the palette and the menu bar, and is stored in `config.json` as you typed it. *Cost by folder* (with *Show what each answer cost*) lists today's and this week's estimate for your five busiest folders, from the 30 newest conversations only. In the command palette, two letters or more find conversations too (up to five; Enter resumes). **A click, Enter, or `⇧⌘R` (the newest conversation of your shell's folder, else the newest; it reads the list first) resumes the conversation in the terminal.** At an idle prompt Jaffer clears whatever you had half typed (Ctrl-E, Ctrl-U, then Ctrl-X Ctrl-K, which clears zsh's whole buffer), types `claude --resume <id>` (or `cd '<folder>' && claude --resume <id>` when your shell is in another folder) and presses Enter, says *Resuming…* and gives the keyboard back to the terminal. While any command runs, Claude Code included, **nothing is typed**: the command is copied and a message says why. A folder whose name holds a backslash is never typed: only `claude --resume <id>` is copied. The small copy button on a row copies the same command and types nothing. The resume line goes into your shell's own history like any command you type (Jaffer itself keeps nothing). This is the one thing besides `claude` that Jaffer types into your shell, and only after your click or keypress. Jaffer reads Claude Code's transcripts for this (`~/.claude/projects`, or `$CLAUDE_CONFIG_DIR/projects`) read-only and takes nothing but the id (the file name), the folder, the first and last time, the token counts and the title: never anything else you or Claude said. The list is read when the panel opens, after a finished turn, with its refresh button, when the palette opens and when `⇧⌘R` runs (with the panel closed, too); a closed panel itself reads nothing. It is never saved.
- **Permission prompts from the notification (experimental, off by default).** *Settings → Claude Code → Answer permission prompts from the notification* adds a twelfth hook, `PermissionRequest`, to `~/.claude/settings.json` (turned off, it is removed again). When Claude Code then asks to use a tool, the hook waits up to 20 seconds for you. While the window is in the background a notification, *Claude asks to use <tool>*, shows one redacted line of what it asks (at most 120 characters) with the buttons **Show**, **Deny** and **Allow**; the title bar and the Now card show the question with a countdown. **Allow** is offered only when the request is shown whole (not for a cut line, a masked secret, a sensitive command or file, or a tool with nothing to show), only in the Now card, only 0.75 seconds after it appeared, and only to a real mouse click, never the keyboard or a script. **Deny** is always safe. *Show*, *Answer in terminal*, 20 seconds of silence, the setting off, Jaffer closed or any error: Jaffer prints nothing and Claude Code's own prompt appears as usual. Jaffer never allows by itself and has no "always allow". Any program of your user account can talk to Jaffer's socket (as it can type into your terminal through it), so this is a convenience with care taken, not a security boundary. macOS keeps the text of delivered notifications in its own notification database, like any notification's.
- **Notifications** while the window is in the background: Claude needs you, a long turn finished, a long command finished. The first two have a *Show* button (and a click does the same) that brings the window back, also a hidden one. *Tell me when Claude finishes* in *Settings → Claude Code* switches the finished-turn one off. In **focus mode** (`⌥⌘F`; `⌃⌘F` is macOS's own full screen) they are held, and when you leave it one notification says what you missed (`While you were focused: Claude finished twice, 1 command failed`). A command that finished while the window was behind also gets a toast when you come back.
- **Closing the window does not stop it.** The red ✕ and `⌘W` hide the window to the menu bar and Claude Code runs on; the icon, your hotkey or a notification's *Show* bring the window back. (In full screen, the window leaves full screen first, so no empty Space is left.) The first time, one notification says where Jaffer went. With *Drop-down mode* on (it needs the hotkey), the hotkey brings the window down at the top of the screen under the pointer, the full width and about 45 % of the height, and it hides when you click elsewhere; your normal window size and place are untouched and come back when you switch it off.
- **Quitting stops it.** Claude Code runs in Jaffer's terminal, so it ends with it. `⌘Q` (or *Quit Jaffer* in the menu bar icon's menu) asks first while Claude is working or a command runs; a logout, restart, shutdown or the Dock's *Quit* do not (macOS takes a question at logout as the app refusing to quit and cancels the logout), so save your work before you log out with Claude running.
- **Awake while Claude works.** While Claude (or a background agent) works, or a command has run for 30 seconds or more (not an interactive program such as `ssh`, `vim` or `tail -f`; capped at 6 hours), Jaffer holds the Mac off idle sleep with `caffeinate -i`, no admin rights and no password, and lets go 15 seconds after the work stops. The screen can still sleep. **It does not override the lid:** a laptop on its own with the lid closed still sleeps, and everything pauses until it wakes. With power, an external display and a keyboard or mouse (macOS's closed-display mode) it keeps working; that has not been checked on a real Mac yet. *Settings → Appearance → Keep my Mac awake while Claude works* switches it off.

## The terminal and the command line

**What the terminal adds.** *Command blocks* read the shell's own marks (zsh, bash and fish, as Jaffer's shell integration emits them) on the window's side: after a re-attach or a clear they start again, and a program in the full-screen mode (`vim`, `claude`) is one block. They do not fold output (the terminal has no folding). *Pasting several lines* asks first (*Paste* or *Cancel*), and dropping a file still pastes its path. A *file path* that a program prints is clickable with ⌘ (`path`, `path:line`, `path:line:col`; absolute, `~/` or relative to your folder): it shows the file in Finder, or opens it in the editor you choose in *Settings → Terminal* (`vscode://file/{path}:{line}:{col}`; only editor links such as VS Code, Cursor, Windsurf, Zed, IntelliJ, Sublime and TextMate are allowed). Jaffer never opens or runs a path a program printed. *Recent commands* (`⌘R`) lists this session's commands (a *By folder* switch groups them by the folder each ran in) and **copies** the one you pick: nothing is typed for you. *Copy as image* in a mark's right-click menu draws the command (not a sensitive one) and up to 200 lines of 160 columns of its output on a canvas in your font and colours and puts the PNG on the clipboard; nothing is saved. `⌘/` (or *Help → Keyboard Shortcuts*) opens a searchable sheet of every shortcut. *Images* in the terminal (sixel and iTerm2 inline images) work and can be switched off; **Kitty graphics are not supported**. *Git counts* come from `git status` after each prompt (1 second at most, no lock taken; a repository whose own config names a filter program, as Git LFS can when configured locally, shows no counts, and on a Mac without the developer tools git is not run). A running server's `localhost:5173` gets a chip in the title bar.

The app is a window onto `jafferd`, a process it starts as its own child: it owns your shell, a headless copy of the screen and what Claude Code is doing, and it ends with the app (quit, crash or kill). Re-attaching the window, after a page reload say, restores the exact screen, including full-screen programs. If your shell exits, a fresh one starts in the same folder with a blank screen.

```sh
jaffer status | doctor    jaffer setup claude [--remove|--status]
jaffer config get|set <dot.path> <json>    jaffer daemon [status|stop]
```

The command line talks to the running app and never starts a terminal. With Jaffer closed, `status` and `doctor` say it is not running and `daemon start` fails (*Jaffer is not running. Open Jaffer and run this again.*); `setup claude` fails the same way only when `~/.jaffer/bin/jaffer`, the wrapper the app writes when it starts, is missing, while `setup claude --status` and `--remove` always work; `config get|set` fall back to `config.json`. `daemon stop` ends the session, which quits the app with it. Inside Jaffer `jaffer` is already on your `PATH`; elsewhere run *Install the `jaffer` command* from the palette.

**Start over:** *Settings → Reset → Reset…*, or `jaffer reset` from another terminal (`--yes` skips the question, `--delete` skips the backup). It ends the session and removes `~/.jaffer` (moved aside as `~/.jaffer.backup-<time>` unless you delete it), Jaffer's hooks in Claude Code, the `jaffer` link and the app's data, together with anything an older Jaffer left behind (its login agent, its memory tools in Claude Code, the block it wrote into `~/.claude/CLAUDE.md`, the skills it published). Claude Code itself, its login and your own settings stay. If `~/.jaffer` is a link, Reset renames or removes the link, not what it points to. Then drag Jaffer.app to the Trash.

## Development

```sh
npm ci && npm run build        # esbuild: daemon, CLI, Electron main/preload, renderer
npm run dev                    # build + launch
npm run typecheck && npm test  # real PTYs (bash, zsh), the bundled daemon and CLI as processes, the real `claude` where it is installed
npm run test:e2e               # the real UI in headless Chromium against the real daemon (set JAFFER_CHROME)
npm run screenshots            # regenerate docs/screenshots (temp homes; needs a short TMPDIR and JAFFER_CHROME); then python3 scripts/shrink-screenshots.py
scripts/release-mac.sh         # on your Mac: build, sign, notarize, verify; --publish uploads it
```

**Careful when you run the app from a checkout:** `npm run dev`, `npm start` and `npm run smoke` use your real `~/.jaffer`, and on a Mac that ran an older Jaffer (0.5 or earlier) the first start cleans it up for real (it deletes the old memory and saved session there). Give them a throwaway folder: `JAFFER_HOME=/tmp/jaffer-dev npm run dev` (the name must contain "jaffer"). That protects your Claude Code files and launchd from the first-start clean-up only (it touches `~/.claude`, the login agent and the MCP server only for the default home). A run with a throwaway `JAFFER_HOME` can still write hooks into your real `~/.claude/settings.json` (the first-run switch *Let Jaffer follow Claude Code* and *Settings → Claude Code → Connect*, pointing at that home's wrapper), and *Settings → Reset* or `jaffer reset` remove the real hooks, MCP server, `CLAUDE.md` block and skills of Jaffer's from your real `~/.claude`. *Settings → Reset* and `jaffer reset` also remove Jaffer's app data under your real `~/Library` (Application Support, Preferences, Saved Application State, Logs, Caches and the update cache), and the palette's *Install the `jaffer` command* links `~/.local/bin/jaffer` to that home. For experiments use a throwaway `HOME` as well, as the tests do: `HOME=/tmp/jaffer-x JAFFER_HOME=/tmp/jaffer-x/.jaffer npm run dev`. The tests use temporary homes, and `JAFFER_NO_LAUNCHCTL=1` keeps them away from the real `launchctl`.

`src/core` has no Electron dependency, so nearly everything is tested as real processes. CI runs the suite on Linux and macOS, builds the `.app`, boots it in a smoke test (`JAFFER_SMOKE=1`) and checks signing end to end with a throwaway identity. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [CLAUDE.md](CLAUDE.md) for the layout and the rules that matter.

## Limitations

- macOS only. Fish integration is experimental (zsh and bash are tested).
- Jaffer keeps no session of its own: when it quits, updates or crashes, the shell and Claude Code end, and the next start is a fresh terminal. Claude Code's own `claude --resume` and `claude -c` still work, typed by you; since 1.1.1 a click on a past conversation in the side panel types the resume line for you when the terminal is idle (and, since 1.2.0, so do Enter on one in the palette and `⇧⌘R`). (A `tmux` you start in it is yours, and works as anywhere.)
- Only *Quit Jaffer* (`⌘Q`, or the menu bar icon's menu, or a close set to quit) asks before it ends a running Claude Code or command. A logout, restart, shutdown, an AppleScript quit and the Dock's *Quit* end the session without asking.
- One side panel by design, with two sections (and the What's New card until you dismiss it). No chat or prompt box, no tabs and no second panel: you answer Claude Code's permission prompts in the terminal, or, if you switch on the experimental setting, with a click on *Deny* or *Allow*.
- Built on xterm.js (WebGL): fast, but not a native GPU terminal like Ghostty. No Kitty graphics, no folding of command output, no soft-wrap toggle (long lines always wrap), no horizontal scrolling.
