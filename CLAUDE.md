# Jaffer — notes for coding agents

Jaffer is a macOS terminal (Electron, and a terminal host `jafferd` that the app starts as its own child) with up to four terminals (only by the person's own split) and a companion that shows what Claude Code is doing. It is a plain terminal: no memory, no saved or resumed terminal state (Claude Code's own conversations can be resumed from the side panel, see the typing rule), no login agent. Read `README.md` and `docs/ARCHITECTURE.md` first.

## Rules that matter
- **The app owns the session.** Quitting Jaffer ends every shell and anything running in them. `jafferd` is the app's child: `startOwnedDaemon` spawns it (not detached) with `JAFFER_OWNED=1` and a pipe on its stdin that the app never writes; the daemon reads the flag, deletes it from its own environment at once (the shell never sees it) and, when the pipe ends (the app quits, crashes or is SIGKILLed), runs its normal shutdown: the shell is let go, the socket removed, exit 0. The flag is opt-in, because the tests, `ensureDaemon` and the dev bridge start the daemon detached with `stdio: 'ignore'` (`detachedSpawnArgs` removes the flag from the environment). The app connects only to its own child (`hello.pid` is the child's pid); anything else that answers on the socket (after a 3 s wait for a session that is already ending by itself) is an older Jaffer's background session, which the app ends only after the person's click (`LEGACY_DIALOG`: the default button is Quit, Esc means Quit; nothing is claimed about Return, which is unverified when default and cancel are the same button). Every quit ends every terminal, but only the menu's **Quit Jaffer** (⌘Q, a custom item that sets `askOnQuit`; `shouldAskOnQuit`, `quitNeedsConfirm`) asks first, and only when Claude Code is working or a command runs in **any** terminal (main keeps `runningCommands`, one per pane; `quitState`; the default button is Cancel, Esc cancels). A quit the system starts (logout, restart, shutdown, AppleScript, Dock → Quit) never asks, because macOS would take the question as the app refusing to quit and cancel the logout: don't put a question on those paths. An update, Reset and a session that already ended ask nothing. The menu bar item's **Quit Jaffer** is the same custom item (`quitFromMenu`), so it asks the same way. The window's ✕ and ⌘W do not quit by default: see the next rule. A child that ends by itself is a crash (`childExitAction`: a fresh terminal or Quit; exit 0 on its own, from `jaffer reset` or `jaffer daemon stop`, quits the app with it). Only the first instance runs (`requestSingleInstanceLock`): a second one exits at once and starts nothing. Never make the daemon outlive the app again, and never start one from the CLI.
- **The packaged app never runs as Node (1.6.5).** Its Electron fuses `runAsNode`, `enableNodeOptionsEnvironmentVariable` and `enableNodeCliInspectArguments` are off (`electronFuses` in `electron-builder.yml`, with `resetAdHocDarwinSignature` so an unsigned build still starts), and `build/entitlements.mac.plist` has no `allow-dyld-environment-variables`: otherwise another program of the user could run code as Jaffer's signed binary and borrow what macOS granted Jaffer. The terminal host and the `jaffer` CLI run on the official Node runtime that `scripts/after-pack.cjs` puts into the app (`Contents/Resources/node/node`; the version and both SHA-256 sums are pinned there and change together, from nodejs.org's `SHASUMS256.txt`): main's `launcher` starts it with `--disable-sigusr1` when `app.isPackaged`, the wrapper `~/.jaffer/bin/jaffer` that the host writes passes the same flag on, and `daemonEnv` deletes `NODE_OPTIONS`. A dev run (unpackaged) still uses Electron-as-Node. `disable-library-validation` stays (a self-signed or ad-hoc build has no Team ID; with the app's JavaScript outside a sealed archive it adds little). Never turn a fuse back on, never use `child_process.fork` in main (it needs RunAsNode), and run nothing as Electron-as-Node in the packaged app. `test/invariants.test.ts` and CI's fuse check guard it.
- **Never move or rename `dist/daemon/jafferd.cjs`** (inside the app: `Contents/Resources/app/dist/daemon/jafferd.cjs`): the app starts that exact file as its child, and a login agent that an older Jaffer left on a Mac (its wrapper `~/.jaffer/bin/jafferd` runs that exact path, until the first start of 0.6.0 removes it) would otherwise fail every five seconds.
- **Closing the window hides it; the terminal runs on** (1.0.1; `closeDecision` in `src/shared/close-action.ts`, `closeWindow` / `hideWindow` in `main.ts`). The red ✕ and ⌘W (the menu's Hide Window calls `window.close()`, so both take the same path) do what `window.closeAction` says: `menubar` (the default) hides the window, `quit` goes the way of Quit Jaffer (which asks when something runs), `ask` shows a sheet (Hide to Menu Bar / Quit Jaffer / Cancel; Cancel is the default and Esc cancels) and only while the menu bar item exists (without it `ask` hides, because the sheet's words would be false). Any other value hides. A window in full screen leaves it first and hides after `leave-full-screen` (a 2 s timer is the fallback; showing the window calls the hide off): hidden in full screen it would leave an empty Space. The first hide while the item is there shows one notification (`window.hintShown`). The **menu bar item** (`window.menuBar`, on by default) is the one new surface of 1.0.1: a template icon in the menu bar (never a second window; the peek panel idea became extra menu lines on ⌥-click), its icon shows idle / working / needs-you (`TrayIconPlayer`; the icons are generated, never hand-edited), a click shows or hides the window, a right-click opens a menu built fresh each time, and an optional text beside the icon (`window.menuBarTitle`: the costs only with `claude.showCost`). `window.menuBarOnly` hides the Dock icon (`app.dock.hide()`), and only while the menu bar item exists: the item and the hotkey are the way back, so never hide the Dock icon without a Tray. If the Tray cannot be made, there is no item and no crash, and the window and the Dock work as before. The quit rules above do not change: closing never quits unless the person set it to, and a quit the system starts still never asks. **Drop-down mode** (1.2.0, `window.dropdown`, off by default, needs a hotkey: Settings disables the switch without one): the registered hotkey is `hotkeyToggle`, which with the setting on shows the one window at the top of the display under the pointer (`dropdownBounds(workArea)`: the work area's width and at most 45% of its height, at least `MIN_WINDOW_HEIGHT` 420) and a second press hides it; a window in full screen is left alone (the plain toggle). The window hides on `blur` while it is on (and a hotkey is registered, and it is not in full screen) **unless a dialog of ours is open**: `dialog` in `main.ts` is a wrapper that counts `showMessageBox` and `showSaveDialog` (`dialogsOpen`), so **any new dialog must go through that wrapper**, never `electron.dialog` directly, or a sheet would hide its own window. The bounds of a drop-down window are never saved (`window.json` keeps the normal ones), and turning the mode off puts the saved bounds back (or the default size, centred, when none was saved; after leaving full screen when it was in it). The tray click, the Dock and notifications still just show the window where it is. There is still one window and no Dock change. The menu bar item's menu has one more line, *What's New in <version>*, shown only while release notes are unseen, and the Help menu has *What's New…* and *Keyboard Shortcuts* (⌘/).
- **The first start cleans up an upgraded Mac, once** (`prepareHome` → `migrateToPlainTerminal`, after an older session is ended and before the child starts; 30 s at most; `migrated: 1` in `config.json` makes every later start a single file read). It removes the login agent (`removeLegacyAgent`), copies the person's own `memory/NOTES.md` and `memory/POLICY.md` (when they hold anything: a `POLICY.md` still equal to the seeded text is not theirs) to `~/.jaffer-memory-backup/` (0700, never over a file there), deletes `memory/`, `session/` and `bin/jafferd` (the memory only once its backup is made), takes Jaffer's marked block out of `~/.claude/CLAUDE.md` (and `~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md`) and its `jaffer-*` skills that carry its marker, prunes the dead config keys (`DEAD_KEYS`, just before the last step) and runs `claude mcp remove jaffer -s user`. Each step is on its own (one that fails is a line in `migrate.log`, the others still run), it never throws, nothing is removed from a folder `assertJafferHome` does not accept, and a link is removed, never followed. What lies outside `~/.jaffer` (launchd, Claude Code's files, the MCP server) is touched by the clean-up only for the default home (`isDefaultHome`): a smoke test or a dev run with another `JAFFER_HOME` cleans inside that folder, with one exception (the backup of `NOTES.md` and `POLICY.md` goes to `~/.jaffer-memory-backup/` in the user's home for any Jaffer home; it only copies). That guard is not wider than the clean-up: first-run *Let Jaffer follow Claude Code* and *Settings → Connect* write hooks into the real `~/.claude/settings.json`, pointing at the running home's wrapper, whatever `JAFFER_HOME` is, and Reset (`jaffer reset`, *Settings → Reset*) does its Claude-side removal (hooks, MCP server, `CLAUDE.md` block, skills) on the real files for any home. Reset does the same cleanups when asked. The markers and names in `legacy-claude.ts` and `legacy-agent.ts` are the exact text older versions wrote: they must never change.
- **Never run the app against a Mac's real `~/.jaffer` to look at it** (`npm run dev`, `npm start`, `npm run smoke` set no `JAFFER_HOME`): on a Mac that ran an older Jaffer that is the migration, for real and irreversibly. Start it with `JAFFER_HOME` set to a throwaway folder whose name contains "jaffer", and for experiments also a throwaway `HOME` (`HOME=/tmp/x JAFFER_HOME=/tmp/x/.jaffer`), as the tests do: `JAFFER_HOME` alone protects your Claude files from the clean-up only (see above). Tests never reach the real `launchctl` or `claude`: `JAFFER_NO_LAUNCHCTL=1` is set for every test run (an injected `launchctl` is blocked by it too, so a test of the agent lowers it for itself), the tests of the clean-up and of Reset inject a fake `launchctl` and a refusing `execFile` mock, and a temp home is never `isDefaultHome` (tests that need it force it for their own folder).
- Redaction: anything shown from a hook payload or a command (the watcher's notice, a notification, the window) goes through `src/shared/redact.ts` first, and a sensitive command (`isSensitiveCommand`) is not named at all. Jaffer keeps no command history, command output or transcript text on disk: what it writes in `~/.jaffer` is `config.json`, `window.json`, the daemon's log, the shell scripts, `bin/jaffer`, `updater.log` and (once) `migrate.log`. 1.0.0 adds only settings to `config.json` (and `claude.typicalTurnMs`, one number: the median length of the last turns, for the ring); 1.0.1 adds only the `window` section (`closeAction`, `menuBar`, `menuBarOnly`, `menuBarTitle`, `hintShown`). 1.2.0 adds only these keys: `updates.seenVersion` (the newest version whose release notes were dismissed), `history.names` (the person's own labels for conversations, `"<session id> <name>"`, at most 200 of at most 80 characters: what the person typed, **not** transcript text; a title is never written as a name) and `history.pinned` (session ids, at most 50), `claude.approvals` (false), `window.dropdown` (false) and `appearance.seasonal` (true). 1.3.0 adds only `appearance.petSize` (`small`, `normal`, `large` or `huge`; default `normal`; an unknown value counts as `normal`). 1.4.0 adds only these keys: `permissions.explain` (false), `permissions.deepSearch` (false), `permissions.resumeTyping` (true), `permissions.trash` (true), `tour.done` (false), `tips.enabled` (true) and `tips.seen` (the ids of the tips shown), `history.tags` (`"<session id> <tag>"`: what the person typed, at most 3 a conversation, 400 in all, 20 characters each) and `history.hidden` (session ids, at most 500), `claude.dailyWorkBudgetMin` (0), `claude.projectBudgets` (`"<folder>=<usd a week>"`, at most 20: the person's own folders, the only folders ever written), `notifications.weeklyDigest` (true) and `usage` (numbers and ISO week ids only: `week` and `lastWeek` as `{id, usd, workMs}`, and `digestWeek`; the daemon writes it at each counted turn). 1.4.1 adds only `terminal.screenReader` (`'auto'`, `'on'` or `'off'`; default `'auto'`; any other text counts as `'auto'`). No text of Claude's, no command and no layout of the terminals is ever written.

it starts again at local midnight), which hook events were seen and when, the command blocks (the window's marks and their commands, through `safeCommand`), the focus-mode counts (main), the menu bar's last five commands (main: `RecentCommands`, same filter as above, labels redacted and clipped to 60) and its last list of past conversations (ids, folders, times and, since 1.1.1, titles), the open past-conversations list with its titles (the window), since 1.3.0 the *Remove…* menu's open state (the window, component state), and, since 1.2.0: the folder chip's choice, the cost-by-folder toggle and a rename's draft (the window, component state), the ⌘R list's By folder toggle and each recent command's `cwd` (the folder the command ran in: the shell's folder when its end mark came, redacted, at most 4096 characters; a repeat keeps the newest folder), the daemon's `DayTotal.workMs` (the time of today's finished turns, for "Claude worked … today"; it resets at local midnight and with the daemon, ignores turns under 1 s and undercounts a turn that was interrupted, because only a Stop adds it), the window's list of pending permission requests and the daemon's own (at most 5, each up to 20 s: an id, the session, the tool name and one redacted line of at most 120 characters, never the request itself) and the What's New card's open state, and, since 1.4.0: the window's pane order, each terminal's info (`paneInfo`), the focused pane and the open close question (`closeAsk`), main's running command per terminal (`runningCommands`), the daemon's per-terminal git status and timers and each connection's attached and stale pane sets, a session's context numbers (watcher), the window's `usage5h`, the Today timeline (`turnHistory` entries also hold the time of day, the counts text and the file count), the sets behind the one-time toasts (the context toast per session id, the work-budget day, the project-budget folder-and-week keys) and main's `digestAsked`, the daemon's last-5-hours cache (numbers by file, size and mtime), its storage figures (30 s) and its Explain bookkeeping (the `claude --help` answer per `claude` path, the end of the last helper run), the Setup section's data and the MCP check's result for one folder and `setupOpen`, the tag menu, the tag filter, the Hidden toggle, the Storage figures, the deep-search switch and its hits, the *Older than* counts while *Remove…* is open (all component state), the Explain card (its busy state and the answer text) and `explainSupported`, the tour's step and what it opened, the open glossary entry, the last tip's time (`tipAt`) and an open ⓘ popover; since 1.4.1: the daemon's live-cost read state per working session (`LiveCost`: the file, its dev and inode, the offset, the running token tally and the unfinished last line of the transcript, held until its newline comes and never more than `LIVE_TAIL_MAX` = 8 × 1024 × 1024 (about 8.4 million) characters, never logged; dropped when the session ends, when the cost or its live part is switched off, or when the daemon stops), main's last three page-reload times (the crash counter) and the window's `assistiveTech` flag and its once-per-window-session link-refusal toast flag; since 1.5.0: each terminal's label (`paneLabels`: what the person typed, at most 24 characters, cleaned by `cleanPaneLabel`, gone with its terminal and with the app), the zoomed pane (`zoomPane`), the Terminals section's drag state, rename draft and close-idle question (component state), each terminal's companion timers (`paneActivityAt`, `paneFixedAt`, `paneBellAt`: times only) and main's `paneFolders` (terminal id to folder, from `pane.list`, `pty.cwd` and `session.lifecycle`, only to name a terminal in a notification; cleared with the terminal); since 1.4.2: each terminal's shell PATH (`PtySession.shellPath`, from its shell's `633;P;Path` mark; no RPC or event carries it (the mark passes through the terminal's output like the other marks), never logged; it ends with the terminal) and the nonce that signs that mark (`JAFFER_NONCE`, a random value per zsh, bash or fish start, which the scripts move into an unexported shell variable: zsh's shim and bash's init file before the person's startup files, fish after `config.fish`, whose programs inherit it: accepted, code running as the person can rewrite their rc files anyway); and in the watcher what the next rule says. Don't write any of it to disk, and don't add to this list without saying so here.
- Jaffer is for Claude Code only. Don't add integrations or copy for other agents (Codex, Gemini, ...).
- Jaffer runs on Claude subscriptions only: there is no Anthropic API key anywhere (no UI, no RPC, no CLI command, no engine), and `ANTHROPIC_API_KEY` is ignored. Don't add key entry back without being asked.
- Whether the user is signed in to Claude comes only from `claude auth status` (`src/core/integrations/claude-auth.ts`): never read Claude's credential files or keychain item, and never let the account email or organisation out of that function. Claude is optional: the first-run sign-in step offers "Use Jaffer as a plain terminal for now" (it then installs nothing and starts nothing, and sets `claude.skipped` so nothing nags; connecting Claude Code clears it), and the step itself types nothing into the terminal; tests fake `claude` with `test/helpers/fake-claude.ts`. Claude Code's own questions (trust, permissions) stay in the terminal and Jaffer never answers them.
- **Jaffer types into the shell only `claude` and, since 1.1.1, the resume line of a past conversation.** (1) `claude` (⇧⌘C, and the first-run switch "Start Claude Code in the terminal now", on by default and worded plainly), through the renderer's terminal, as the person would. (2) **Only after the person's click or Enter on a past conversation in the side panel, Enter on a conversation in the palette (1.2.0), or ⇧⌘R, Resume Last Conversation (1.2.0)**, exactly: Ctrl-E, Ctrl-U, Ctrl-X Ctrl-K (clears a half-typed line wherever the cursor is: bash's Ctrl-U kills only what is before it; Ctrl-X Ctrl-K is zsh's kill-buffer for a buffer Shift+Enter made several lines long, and only rings bash's bell; `test/resume-typing.test.ts` pins it in real bash and zsh), then `claude --resume <id>` (when the shell is already in that folder: `info.cwd === cwd`) or `cd '<folder>' && claude --resume <id>` (the folder single-quoted, `'` written `'\''`), then Enter.
