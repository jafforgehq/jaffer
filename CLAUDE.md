# Jaffer — notes for coding agents

Jaffer is a macOS terminal (Electron, and a terminal host `jafferd` that the app starts as its own child) with up to four terminals (only by the person's own split) and a companion that shows what Claude Code is doing. It is a plain terminal: no memory, no saved or resumed terminal state (Claude Code's own conversations can be resumed from the side panel, see the typing rule), no login agent. Read `README.md` and `docs/ARCHITECTURE.md` first.

## Rules that matter
The rules marked *Full text* are digests: the original, longer text of each is in `docs/RULES.md` (same title). Read the full text before you change code in that area.

- **The app owns the session.** Quitting Jaffer ends every shell and anything running in them. `jafferd` is the app's child: `startOwnedDaemon` spawns it (not detached) with `JAFFER_OWNED=1` and a pipe on its stdin that the app never writes; the daemon reads the flag, deletes it from its own environment at once (the shell never sees it) and, when the pipe ends (the app quits, crashes or is SIGKILLed), runs its normal shutdown: the shell is let go, the socket removed, exit 0. The flag is opt-in, because the tests, `ensureDaemon` and the dev bridge start the daemon detached with `stdio: 'ignore'` (`detachedSpawnArgs` removes the flag from the environment). The app connects only to its own child (`hello.pid` is the child's pid); anything else that answers on the socket (after a 3 s wait for a session that is already ending by itself) is an older Jaffer's background session, which the app ends only after the person's click (`LEGACY_DIALOG`: the default button is Quit, Esc means Quit; nothing is claimed about Return, which is unverified when default and cancel are the same button). Every quit ends every terminal, but only the menu's **Quit Jaffer** (⌘Q, a custom item that sets `askOnQuit`; `shouldAskOnQuit`, `quitNeedsConfirm`) asks first, and only when Claude Code is working or a command runs in **any** terminal (main keeps `runningCommands`, one per pane; `quitState`; the default button is Cancel, Esc cancels). A quit the system starts (logout, restart, shutdown, AppleScript, Dock → Quit) never asks, because macOS would take the question as the app refusing to quit and cancel the logout: don't put a question on those paths. An update, Reset and a session that already ended ask nothing. The menu bar item's **Quit Jaffer** is the same custom item (`quitFromMenu`), so it asks the same way. The window's ✕ and ⌘W do not quit by default: see the next rule. A child that ends by itself is a crash (`childExitAction`: a fresh terminal or Quit; exit 0 on its own, from `jaffer reset` or `jaffer daemon stop`, quits the app with it). Only the first instance runs (`requestSingleInstanceLock`): a second one exits at once and starts nothing. Never make the daemon outlive the app again, and never start one from the CLI.
- **The packaged app never runs as Node (1.6.5).** Its Electron fuses `runAsNode`, `enableNodeOptionsEnvironmentVariable` and `enableNodeCliInspectArguments` are off (`electronFuses` in `electron-builder.yml`, with `resetAdHocDarwinSignature` so an unsigned build still starts), and `build/entitlements.mac.plist` has no `allow-dyld-environment-variables`: otherwise another program of the user could run code as Jaffer's signed binary and borrow what macOS granted Jaffer. The terminal host and the `jaffer` CLI run on the official Node runtime that `scripts/after-pack.cjs` puts into the app (`Contents/Resources/node/node`; the version and both SHA-256 sums are pinned there and change together, from nodejs.org's `SHASUMS256.txt`): main's `launcher` starts it with `--disable-sigusr1` when `app.isPackaged`, the wrapper `~/.jaffer/bin/jaffer` that the host writes passes the same flag on, and `daemonEnv` deletes `NODE_OPTIONS`. A dev run (unpackaged) still uses Electron-as-Node. `disable-library-validation` stays (a self-signed or ad-hoc build has no Team ID; with the app's JavaScript outside a sealed archive it adds little). Never turn a fuse back on, never use `child_process.fork` in main (it needs RunAsNode), and run nothing as Electron-as-Node in the packaged app. `test/invariants.test.ts` and CI's fuse check guard it.
- **Never move or rename `dist/daemon/jafferd.cjs`** (inside the app: `Contents/Resources/app/dist/daemon/jafferd.cjs`): the app starts that exact file as its child, and a login agent that an older Jaffer left on a Mac (its wrapper `~/.jaffer/bin/jafferd` runs that exact path, until the first start of 0.6.0 removes it) would otherwise fail every five seconds.
- **Closing the window hides it; the terminal runs on** (1.0.1; `closeDecision` in `src/shared/close-action.ts`, `closeWindow` / `hideWindow` in `main.ts`). The red ✕ and ⌘W do what `window.closeAction` says: `menubar` (the default) hides, `quit` goes the way of Quit Jaffer (which asks when something runs), `ask` shows a sheet (Cancel is the default, Esc cancels) and only while the menu bar item exists; any other value hides. Never hide the Dock icon (`window.menuBarOnly`) without a Tray. A quit the system starts never asks. Drop-down mode (1.2.0, off by default, needs a hotkey) hides the window on blur **unless a dialog of ours is open**: **any new dialog must go through the counting `dialog` wrapper in `main.ts`**, never `electron.dialog` directly. Still one window and one menu bar item. Full text: `docs/RULES.md`, section "Closing the window hides it; the terminal runs on".
- **The first start cleans up an upgraded Mac, once** (`prepareHome` → `migrateToPlainTerminal`; `migrated: 1` in `config.json` makes every later start a single file read). Each step is on its own, never throws, removes nothing from a folder `assertJafferHome` does not accept and never follows a link; the person's own `memory/NOTES.md` and `POLICY.md` are copied to `~/.jaffer-memory-backup/` before `memory/` is deleted. What lies outside `~/.jaffer` (launchd, Claude Code's files, the MCP server) is touched only for the default home (`isDefaultHome`); Reset does its Claude-side removal on the real files for any home. The markers and names in `legacy-claude.ts` and `legacy-agent.ts` are the exact text older versions wrote: they must never change. Full text: `docs/RULES.md`, section "The first start cleans up an upgraded Mac, once".
- **Never run the app against a Mac's real `~/.jaffer` to look at it** (`npm run dev`, `npm start`, `npm run smoke` set no `JAFFER_HOME`): on a Mac that ran an older Jaffer that is the migration, for real and irreversibly. Start it with `JAFFER_HOME` set to a throwaway folder whose name contains "jaffer", and for experiments also a throwaway `HOME` (`HOME=/tmp/x JAFFER_HOME=/tmp/x/.jaffer`), as the tests do: `JAFFER_HOME` alone protects your Claude files from the clean-up only (see above). Tests never reach the real `launchctl` or `claude`: `JAFFER_NO_LAUNCHCTL=1` is set for every test run (an injected `launchctl` is blocked by it too, so a test of the agent lowers it for itself), the tests of the clean-up and of Reset inject a fake `launchctl` and a refusing `execFile` mock, and a temp home is never `isDefaultHome` (tests that need it force it for their own folder).
- **Redaction, and what Jaffer writes to disk.** Anything shown from a hook payload or a command (the watcher's notice, a notification, the window) goes through `src/shared/redact.ts` first, and a sensitive command (`isSensitiveCommand`) is not named at all. Jaffer keeps no command history, command output or transcript text on disk: it writes only `config.json`, `window.json`, the daemon's log, the shell scripts, `bin/jaffer`, `updater.log` and (once) `migrate.log`. Every config key added since 1.0.0 is a setting, a number, an id or a label the person typed, never Claude's text, a command or the layout of the terminals; **a new key needs a default of the right kind and an entry in the full list of keys in `docs/RULES.md`.** Full text: `docs/RULES.md`, section "Redaction".
- **What Jaffer keeps in memory, and only there** (it ends with the app; none of it is written anywhere): the recent commands (⌘R: at most 200; a sensitive command or one over `4 * COMMAND_HEAD` is never kept), pinned lines, turn history and today's numbers, command blocks (through `safeCommand`), the pane state (order, labels, zoom, per-terminal info and companion timers), pending permission requests (one redacted line, never the request), caches of the past-conversation list, storage, last-5-hours and Setup/MCP results, the live-cost read state, each terminal's shell PATH and the nonce that signs its mark, and the open state of the panel's cards and menus. **Don't write any of it to disk, never log it, and don't add to the list without adding it to the full list in `docs/RULES.md`.** Full text: `docs/RULES.md`, section "What Jaffer keeps in memory, and only there".
- Jaffer is for Claude Code only. Don't add integrations or copy for other agents (Codex, Gemini, ...).
- Jaffer runs on Claude subscriptions only: there is no Anthropic API key anywhere (no UI, no RPC, no CLI command, no engine), and `ANTHROPIC_API_KEY` is ignored. Don't add key entry back without being asked.
- Whether the user is signed in to Claude comes only from `claude auth status` (`src/core/integrations/claude-auth.ts`): never read Claude's credential files or keychain item, and never let the account email or organisation out of that function. Claude is optional: the first-run sign-in step offers "Use Jaffer as a plain terminal for now" (it then installs nothing and starts nothing, and sets `claude.skipped` so nothing nags; connecting Claude Code clears it), and the step itself types nothing into the terminal; tests fake `claude` with `test/helpers/fake-claude.ts`. Claude Code's own questions (trust, permissions) stay in the terminal and Jaffer never answers them.
- **Jaffer types into the shell only `claude`, since 1.1.1 the resume line of a past conversation and, since 1.6.6, `/exit` into an idle Claude.** (1) `claude` (⇧⌘C, and the first-run switch), as the person would. (2) After the person's click or Enter on a past conversation (panel, palette) or ⇧⌘R, exactly Ctrl-E, Ctrl-U, Ctrl-X Ctrl-K, then `claude --resume <id>` (with `cd '<folder>' && ` when the shell is elsewhere) and Enter: only at an idle prompt of the **focused terminal** (its own marks), with `permissions.resumeTyping` on, a UUID id (`isSessionId`), a safe absolute folder, once per click (the 2 s lock in `resumeConversation`, `src/renderer/resume.ts`, the one place); otherwise the line is **copied** with a toast. `resumeAction` (`src/shared/resume-action.ts`) decides. (3) *End and resume* (1.6.6): with the focused Claude idle, a click on *End and resume* types once Ctrl-E, Ctrl-U, `/exit`, Enter, waits up to 10 s for the shell, then resumes; any doubt falls back to copy. **Nothing printed in the terminal is ever typed; no restart, no `runCommand`, no other automatic typing and no wider resume line (no flags, no other command) without being asked** (it would need its own tests against bash and zsh). The menu bar's items only copy. Full text: `docs/RULES.md`, section "Jaffer types into the shell only".
- **Up to four terminals, only by the person's own split (1.4.0).** `SessionHost` (`src/core/session/host.ts`) holds the panes `main`, `p2`, `p3`, `p4`; each shell gets `JAFFER_PANE=<id>`. A pane opens only for `pane.split` (⌘D, *Split Terminal*, the Terminals section; refused at four) and ends only for `pane.close {pane}` (the last one is refused: `session.restart {pane}` gives it a fresh shell). **The layout is memory only**: no restore, nothing of a terminal saved or replayed; a shell that exits is replaced in its folder unless the person closed the pane. The geometry is `src/shared/pane-grid.ts` (equal sizes, no dragging). One window, one daemon child, one side panel. **Don't add tabs, a draggable divider, saved layouts or a fifth terminal without being asked.** Full text: `docs/RULES.md`, section "Up to four terminals, only by the person's own split".
- **Terminals section, a pet per terminal, zoom (1.5.0; memory only, no config key, nothing typed).** The panel's *Terminals* section (`Terminals.tsx`) holds the person's own controls (a row per terminal, *New terminal*, rename (24 characters), reorder, *Close idle…* (never the focused terminal nor one where a command or Claude runs), the row's cost with `claude.showCost`); none of them types into a shell. Zoom (⇧⌘↩, `zoomPane`) hides the other terminals with `display: none`. Every `.pane` holds its own companion (`Pet`, from `claudeFor(pane)`) and, with two or more terminals, outlines Claude's state. Notifications name the terminal (`terminalWhere`) and focus it (`app.focus-pane`); focus never types or answers anything. **Still forbidden without being asked: tabs, a draggable divider, a fifth terminal, saved layouts or names, a terminal control in the title bar.** Full text: `docs/RULES.md`, section "Terminals section, a pet per terminal, zoom".
- Config is conformed on load and on every patch to the kind of the defaults' values (`conform` in `src/shared/config.ts`: a section stays an object, a switch a boolean, a list a list of text; what does not fit keeps the default or the previous value), so code may rely on those kinds; a new key needs a default of the right kind. `jaffer config set` says when a value was refused (`session.stayAwake`, say, is true or false). Anything the window shows about a command goes through `safeCommand()` or the same redaction.
- Don't use a global CSS class name that is also a layout utility (`.row`) for state (we shipped that bug once). CSS here is global: before adding a modifier class (`.tag.run`, `.row-ico.agent`, `.seg-btn.mem` were all real bugs), check it is not already a standalone selector (`.run`, `.agent`, `.mem`).
- The renderer's colours are layered tokens from `themes.ts` (`--chrome`, `--surface`, `--raised`); use them instead of literals so every theme works. The UI shows commands only through `safeCommand()` (redacts, hides sensitive ones).
- **The window is a calm terminal:** a thin title bar, the terminals, a companion per terminal and **one side panel** (`SidePanel.tsx`; right side, open by default, ⌘B, 220 to 480 px). The panel has exactly: the temporary cards (What's New, Explain), *Now*, *Terminals*, *Past conversations* and *Setup*. It shows only what the window already shows, through the same redaction (`safeCommand`, `claude-ui.ts`), makes only the daemon reads listed in the full rule, and types nothing of its own (a click on a conversation resumes it by the typing rule above). The terminal fits once per gesture (`layoutHold`). **Don't add a second panel, a tab bar, a prompt or chat box, a status bar, a drawer, a left sidebar, a divider to drag between terminals, a second window or command stripes, and no ⓘ or terminal control in the title bar, without being asked.** The overlay kinds are `settings`, `palette`, `onboarding`, `find`, `recent`, `keys`, `learn` and `tour` (the 1.1.0 modal list of past conversations is gone). The calm-window UI test lists the allowed children of `.workspace`, `.stage`, `.terminal-area` and `.pane`: change that list only for an addition named here. Full text: `docs/RULES.md`, section "The window is a calm terminal".
- **There is one Claude per terminal: the `claude` in it.** No second chat, prompt box or background `claude` that talks for the user; the companion and the notification only show what Claude Code's hooks report. The hooks (`jaffer hook <event>`, eleven events) are asynchronous, print nothing, exit 0 on every path and do nothing unless `JAFFER_SESSION=1`; the one exception is the optional blocking `PermissionRequest` (the approvals rule). Anything shown from a payload is redacted first (`ClaudeWatcher`). **The watcher may keep, in memory and for the session only: tool names and category, per-turn counts and timings, whether a call failed, redacted paths of files that `Edit`, `Write`, `MultiEdit` and `NotebookEdit` write (never a sensitive one, at most 50 a turn), `pane` and `context` numbers. Nothing else (no prompt, reply, command text, other tool argument or agent description); a new hook event or watcher field needs its own entry in the watcher privacy test.** Never start `claude` with `--dangerously-skip-permissions` or a mode that auto-allows. Full text: `docs/RULES.md`, section "There is one Claude per terminal".
- **Approvals from the notification (1.2.0, experimental, `claude.approvals`, off by default).** On, Jaffer installs a twelfth, **blocking** hook `PermissionRequest` (`jaffer hook permission-request`, `timeout: 25`, tagged `# jaffer-managed`); off, it is removed. The hook prints a decision only for `allow` or `deny` (Claude Code's `hookSpecificOutput`, never `updatedInput`, `updatedPermissions` or `interrupt`); on anything else it prints nothing and exits 0, so **any failure is silent and safe**. **Never exit code 2, and no default button, key binding, "always allow" or auto-answer.** *Allow* needs a trusted click (`isTrusted`, `detail === 1`) armed 750 ms after the request showed, only in the Now card, and only when the request is shown verbatim (`allowable`); `Edit`, `Write`, `MultiEdit` and `NotebookEdit` are never allowable; the notification offers *Show* and *Deny*, never Allow. The daemon keeps only a redacted one-line view (at most 5, 20 s), never `tool_input`. Full text: `docs/RULES.md`, section "Approvals from the notification".
- **The cost figure and past conversations read transcripts narrowly.** The cost (`shared/claude-cost.ts`, `core/claude/cost.ts`) reads only the token counts of Claude Code's transcript. Past conversations (`core/claude/history.ts`) take only the file name (the id), `cwd`, the first and last timestamps, tokens for the newest 30 (only with `claude.showCost`) and one **title** (redacted, 80 characters, memory only); the result's keys are exactly `id`, `cwd`, `title`, `startedAt`, `endedAt`, `durMs`, `usd`. **Every transcript reader opens its file through the one confined opener `openTranscript` / `openTranscriptSync` (`transcript-open.ts`): add no reader that opens a transcript another way.** Reads are read-only, confined to `realpath(<claudeDir>/projects)`, regular `<uuid>.jsonl` files only and bounded; `isSessionId` runs before an id is used anywhere; `claude.showCost` gates every read of token counts. Costs are estimates at API list prices (say so); a model missing from the price table gets tokens and no dollars; update the table from Anthropic's pricing page, not from memory. Live cost reads incrementally (`LiveCost`, bounded, no `*Sync` call on that path). Don't read more of a transcript than the rules say without saying so here. Full text: `docs/RULES.md`, section "The cost figure".
- **The one write to Claude Code's transcripts: remove past conversations (1.3.0).** Only the person's own pick, moved with `shell.trashItem` (**never a permanent delete**), touching exactly `<claudeDir>/projects/<folder>/<id>.jsonl` and its sibling real folder `<id>/`, with paths from `conversationFiles` (never from the page), at most 200 at a time, after a native confirmation in main (default Cancel, Esc cancels, once per request, looked at again after the answer). A conversation the daemon knows as not ended is refused (*still running*); if the live sessions cannot be looked up nothing is moved; `permissions.trash` off refuses everything. **Don't add another write to Claude's files, a permanent delete, or a removal without that question.** Full text: `docs/RULES.md`, section "The one write to Claude Code's transcripts".
- **The permissions model (1.4.0; `permissions.*` in `config.json`; Settings → Privacy and permissions and the last first-run stage, `PrivacySwitches` in `Overlays.tsx`).** Five switches, each worded with what it reads, sends or does: `permissions.explain` (false; Explain, below), `permissions.deepSearch` (false; the panel's *Search text*), `permissions.resumeTyping` (true; off: the resume line is only copied), `permissions.trash` (true; off: main refuses every id with the reason `off` before it looks anything up or asks, and the panel shows no remove buttons) and the existing `claude.approvals` (false; it lives only here now). **Locked, with no switch, don't add one:** *Allow* needs the trusted, armed click and the whole request shown; Jaffer never reads Claude's login or credential files (`~/.claude.json`, the keychain item); nothing is deleted for good; everything shown is redacted and a sensitive command is never named. **A switch is consent, not a boundary:** any process of the same user can `config.patch` it or call the daemon's RPCs on the 0600 socket, as it can send `pty.write`. The daemon re-checks `explain` and `deepSearch` on every call and main re-checks `trash`, so the page, the daemon and main agree, and that is all they promise. The first-run privacy stage writes at once and is shown on the plain-terminal path too. A new capability that reads Claude's words or acts on Claude Code's files needs a switch here and an entry in this rule.
- **Transcript reads added in 1.4.0 (each narrow; none written, none kept as text).** (a) Context and last 5 hours, only with `claude.showCost`, token counts only. (b) *Storage* and *Older than N days*: names and sizes only, links skipped, bounded. (c) *Deep search* (`permissions.deepSearch`, re-checked by the daemon at every call): only `user` and `assistant` message text, never meta, compaction, sidechain, tool or thinking text; the answer is ids and counts only, **no snippet**. - **Setup (1.4.0; the panel's last section, collapsed by default).** `claude.setup {cwd}` (`src/core/claude/setup.ts`) reads files only and starts no process: skills, plugins, rules and memory files (path and size, never the text), subagent names, hook event names and counts (**never commands**) and the server names of `.mcp.json` (never a command, URL or env). **A real path whose name starts `.claude.json` is never opened**; files open `O_RDONLY | O_NOFOLLOW | O_NONBLOCK` and are bounded; frontmatter is parsed by hand (no regex over a value). `claude.mcp` runs `claude mcp list` **only on the person's click**, for the app's connection, as an argv without a shell in a process group that is killed at the end, with the focused terminal's shell PATH reduced to absolute entries (`mcpPath`), and **only through the MCP gate** (`mcpGate` / `mcpGateFor`): a folder whose settings pre-approve its project servers is checked in the home folder instead. **Don't run `claude mcp list` in a folder without the gate; nothing in Setup changes a setting.** Full text: `docs/RULES.md`, section "Setup".
- **Explain (1.4.0; opt-in `permissions.explain`).** The one place Jaffer sends Claude's words anywhere, only after the switch and a click on *Explain the last answer*. `lastReply` takes only the assistant text since the last real user prompt, redacted and clipped to 6000 characters; `runExplain` runs the person's own `claude` with exactly `-p --tools "" --strict-mcp-config --no-session-persistence --output-format text --permission-prompts none --safe-mode` (**never `--bare`**, no API key, every `JAFFER_*` and key variable removed, `JAFFER_NO_HOOKS=1`) in a fresh empty temporary folder, 60 s at most, one run at a time, 5 s apart, a fixed set of failure reasons, nothing logged. Offered only when `claude --help` lists those flags. Full text: `docs/RULES.md`, section "Explain".
- **Insight numbers (1.4.0).** `usage` in `config.json` (the daemon adds a counted turn's dollars while `claude.showCost` is on, and its work time always; `weekId` is the local ISO week, `rollWeek` moves a finished week to `lastWeek`) feeds the weekly summary: at the window's first load of an app run (`digestAsked` in main), `digestDue` picks the week just past, `usage.digestWeek` is written **before** anything is shown, then one notification (kind `digest`; focus mode holds it as "the weekly summary") and a toast with *Open panel* (`app.digest`, main → page) unless `notifications.weeklyDigest` is off; the money only with `claude.showCost`. `claude.dailyWorkBudgetMin` colours the worked line (80 % / 100 %) and toasts once a day; `claude.projectBudgets` (`parseProjectBudgets`: absolute or `~` folders, dollars a week, the last `=` splits, at most 20) tints the folder's row in *Cost by folder* and toasts once per folder and ISO week, counted from the 30 newest costed conversations only (the table says so); a folder outside the five busiest has no row and still gets the toast. The context toast (85 %) needs `claude.showCost` and fires once per session id, again after a compaction. No budget stops anything.
- **Learn (1.4.0): glossary, ⓘ buttons, tour, tips.** Pure data in `src/shared` (`glossary.ts`, `tour.ts`, `tips.ts`); the glossary and the tour are the overlay kinds `learn` and `tour`; the tour types nothing and writes only `tour.done`; **no ⓘ in the title bar**; a tip is shown at most once per 90 s, never while first run or the tour is up or the window is away, and is gated by `tips.enabled` and `tips.seen`. Claims about Claude Code are limited to what its docs say. Full text: `docs/RULES.md`, section "Learn".
- The window shows only its own page (`isAppUrl` in `shared/window-policy.ts`, used by `will-navigate` and the IPC sender check): never allow any `file://`. A program in the terminal may write the clipboard (OSC 52) but never read it. **Permission handlers (1.4.1, `createWindow` in `main.ts`):** the window's session grants exactly one web permission, `clipboard-sanitized-write`, and only to the app's own webContents, because OSC 52 and Copy as image write the clipboard without a user gesture; every other permission, `clipboard-read` included, is refused in both the request and the check handler. Don't add another. Every redaction rule runs on the daemon's main thread over untrusted text, so each must be bounded (no unbounded character run before a literal); `test/redact.test.ts` has the timing tests. The same goes for the command-line helpers (`isClaudeCommand`, `isInteractiveCommand`) and for the readers of printed text and git's answer (`findPaths`, `findPorts`, `isSensitivePath`, `parseGitStatus`, `safeCommand`): a command line is forgeable at any length, so each slices its input to a head itself (`COMMAND_HEAD`, 4096 characters, for a command; `isSensitivePath` fails closed past 4096; `parseGitStatus` reads the first megabyte; `findPorts` the first 64 KB) and none has an unbounded run before a literal; keep new ones the same, with timing tests on 1 MB and 8 MB lines. **`redactText` itself throws (`RangeError`) on a multi-megabyte single-run string:** every caller that redacts untrusted text clips it to `4 * COMMAND_HEAD` first (the daemon's `633;E` command and `Cwd`, `commandNotification`, `safeCommand`), and `grep redactText(` over `src/main`, `src/daemon` and `src/core` must show only bounded callers.
- **git status runs a program after each prompt, so it is locked down** (`src/core/session/git-status.ts`): `execFile('git', [...])` with an argv array (no shell), a 1 s timeout (SIGKILL), 1 MB of output, `GIT_OPTIONAL_LOCKS=0` (the person's own git never waits for it), `-c core.fsmonitor=false`, `--ignore-submodules=all`. Before it, `git config --show-scope --get-regexp '^filter\..*\.(clean|process|smudge)$'` runs: a repository whose own config (any scope but `system` and `global`) names a filter driver gets no status, because `git status` would run that program. On macOS it is skipped (once per daemon run) when `xcode-select -p` fails, because `/usr/bin/git` then pops the install-developer-tools dialog on every run. Tests use temporary repositories and `GIT_CONFIG_GLOBAL=/dev/null`; don't make it run anything else of git's.
- **The page may use only these IPC channels of main, and each checks `trusted(e)` (the sender is the app's own page):** `jaffer:call` (the daemon's RPC, **only the methods on `ALLOWED_PAGE_METHODS`** in `src/shared/page-methods.ts`, which `test/page-methods.test.ts` keeps equal to the renderer's literal `call('…')` sites; `hello`, `claude.event`, `claude.approval`, `session.snapshot` and `app.shutdown` are never on it; defense in depth, not a boundary), `jaffer:open-external` (http(s) only), `jaffer:reveal`, `jaffer:app-info`, `jaffer:update-state`, `jaffer:update-check`, `jaffer:reset`, `jaffer:set-login-item`, `jaffer:save-text`, `jaffer:open-path`, `jaffer:reveal-path`, `jaffer:focus-mode`, `jaffer:trash-conversations`, and from main to the page `jaffer:system-stats`. **Nothing printed in the terminal is ever run, and only web links are opened**: a printed path is revealed in Finder or handed to an editor link on the `EDITOR_SCHEMES` allow-list, never `shell.openPath`; a ⌘-click on an `http(s)` URL or on an OSC 8 link that passes `safeLinkUrl` opens the browser through `jaffer:open-external`, nothing else does. Full text: `docs/RULES.md`, section "The page may use these IPC channels".
- **Focus mode is ⌥⌘F** (⌃⌘F is macOS's Full Screen, which Electron's own role holds: no item of ours may share it; `menu-spec.ts` and its test enforce unique accelerators). While it is on, main holds notifications and the needs-you Dock bounce and counts them by kind (`FocusHold`: never what a notification said), drops the bell's Dock bounce, and shows one "Focus mode ended" notification when it ends. The update prompt's notice is never held. Focus mode ends silently when the window closes or the page reloads.
- Updates ask first: nothing installs without a click (`autoInstallOnAppQuit` stays off, quitting never replaces the app behind a running session), only a packaged, Developer ID signed app checks, and `latest-mac.yml` is uploaded last and only by `scripts/release-mac.sh` (never by CI previews). Installing an update ends the terminal session (the prompt says so) and a fresh terminal starts. Since 1.4.1 there is no feed override in any build: `JAFFER_UPDATE_URL` is gone (it only worked in a signed packaged app, where it was a test hook left live), the feed is the GitHub release the app was built for, and an update test cannot point the app at a local server.
- **A crashed or hung page is reloaded (1.4.1; `crashAction` in `src/shared/crash-policy.ts`, `onPageGone` / `reloadPage` in `main.ts`).** `render-process-gone` of the window's webContents (any reason but `clean-exit`) and `unresponsive` that lasts `HANG_MS` (10 s) reload the page (`webContents.reload()`, also while the window is hidden); the daemon and every shell are untouched, and the reloaded page attaches again and draws each terminal from its snapshot. At most `CRASH_RELOADS` (3) reloads in `CRASH_WINDOW_MS` (60 s); the next one asks, once at a time, through the counting `dialog` wrapper (a sheet on the window, shown first when it is hidden): *The window stopped responding.* with **Reload** (the default; Esc also reloads: a stray key must not end every terminal) and **Quit** (`quitConfirmed = true; app.quit()`, like `onChildExit`'s Quit, so no second question). Reload clears the counter. A page ended because the app is quitting is not a crash. A hung page is crashed with `forcefullyCrashRenderer()` before the reload, and a **one-shot flag** (`selfCrashed`, consumed by the first `render-process-gone` after it) keeps that crash from being counted again without hiding a real one that follows. `console.error` (the reason only) only in an unpackaged build: no new logging. This is main-process wiring, typechecked and read, not run by any test (the README lists it as not verified).

Main sends the page one boolean, the `jaffer:event` name `app.accessibility` (no new IPC channel), on every page load and on Electron's `accessibility-support-changed`; the page keeps it in `assistiveTech` (only `true` counts). **`app.isAccessibilitySupportEnabled()` is true for any assistive client, not only VoiceOver**, so *auto* can turn the slower mode on without a screen reader (the hint says it is slower with a lot of output); `off` is the way out. Not verified with a real VoiceOver (the README says so).
- **The 1.4.1 hardening rules (from the 1.4.0 audit; `SECURITY.md` says them to the person).** (1) The page-method allow-list and the permission handlers. (2) One confined transcript opener. A new violation is a failing test, not a review comment. (5) Keep `SECURITY.md` true when a rule here changes. Full text: `docs/RULES.md`, section "The 1.4.1 hardening rules".
