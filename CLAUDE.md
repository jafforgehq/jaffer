# Jaffer — notes for coding agents

Jaffer is a macOS terminal (Electron, and a terminal host `jafferd` that the app starts as its own child) with one session and a companion that shows what Claude Code is doing. It is a plain terminal: no memory, no saved or resumed sessions, no login agent. Read `README.md` and `docs/ARCHITECTURE.md` first.

## Layout
- `src/main` — Electron main/preload: the window, menu, notifications, hotkey and updates (`updates.ts`), the start order and the quit question (`main.ts`), and `prepare-home.ts` (the first-start clean-up). `src/renderer` — Preact UI. `src/dev/bridge.ts` — browser↔daemon bridge used only by tests.
- `src/core/daemon-client.ts` — starts the app's own `jafferd` as its child (`startOwnedDaemon`) and connects to it. `src/daemon` — `jafferd` (`service.ts`: the RPC and what the daemon owns; `shutdown.ts`) and `src/core/rpc.ts` (NDJSON over a unix socket).
- `src/core/session` — PTY host, shell integration (OSC 133/633), headless-xterm snapshots, `stay-awake.ts` + `caffeinate.ts` (the idle-sleep hold). `resources/shell/*` are the real scripts; `src/generated/shell-scripts.ts` is generated from them (`npm run gen`, checked in CI).
- `src/core/claude` — `watcher.ts` (pure state machine: what the terminal's Claude is doing, from its hook events), `transcript-watch.ts` (notices a prompt declined in the terminal) and `cost.ts` (the token counts of an answer). `src/core/integrations` — `claude.ts` (Jaffer's hooks in `~/.claude/settings.json`, finding `claude`), `claude-auth.ts` (`claude auth status` / `claude auth login`) and `legacy-claude.ts` (what older versions wrote into Claude Code's files, and how to take it back).
- `src/core/migrate.ts` — the first-start clean-up of a Mac an older Jaffer ran on. `src/core/service/legacy-agent.ts` — takes away the login agent older versions installed. `src/core/reset.ts` — taking Jaffer off the Mac (`jaffer reset`, Settings → Reset). `src/cli` — `jaffer` (`hook`, `config`, `setup claude`, `status`/`doctor`, `reset`, `daemon [status|stop]`). `src/shared` — pure pieces shared by the processes (redaction, config, paths, the policies for quitting, updating and notifying, the cost table).

## Rules that matter
- **The app owns the session.** Quitting Jaffer ends the shell and anything running in it. `jafferd` is the app's child: `startOwnedDaemon` spawns it (not detached) with `JAFFER_OWNED=1` and a pipe on its stdin that the app never writes; the daemon reads the flag, deletes it from its own environment at once (the shell never sees it) and, when the pipe ends (the app quits, crashes or is SIGKILLed), runs its normal shutdown: the shell is let go, the socket removed, exit 0. The flag is opt-in, because the tests, `ensureDaemon` and the dev bridge start the daemon detached with `stdio: 'ignore'` (`detachedSpawnArgs` removes the flag from the environment). The app connects only to its own child (`hello.pid` is the child's pid); anything else that answers on the socket (after a 3 s wait for a session that is already ending by itself) is an older Jaffer's background session, which the app ends only after the person's click (`LEGACY_DIALOG`: the default button is Quit, Esc means Quit; nothing is claimed about Return, which is unverified when default and cancel are the same button). Every quit ends the terminal, but only the menu's **Quit Jaffer** (⌘Q, a custom item that sets `askOnQuit`; `shouldAskOnQuit`, `quitNeedsConfirm`) asks first, and only when Claude Code is working or a command runs (the default button is Cancel, Esc cancels). A quit the system starts (logout, restart, shutdown, AppleScript, Dock → Quit) never asks, because macOS would take the question as the app refusing to quit and cancel the logout: don't put a question on those paths. An update, Reset and a session that already ended ask nothing; ⌘W only hides the window. A child that ends by itself is a crash (`childExitAction`: a fresh terminal or Quit; exit 0 on its own, from `jaffer reset` or `jaffer daemon stop`, quits the app with it). Only the first instance runs (`requestSingleInstanceLock`): a second one exits at once and starts nothing. Never make the daemon outlive the app again, and never start one from the CLI.
- **Never move or rename `dist/daemon/jafferd.cjs`** (inside the app: `Contents/Resources/app/dist/daemon/jafferd.cjs`): the app starts that exact file as its child, and a login agent that an older Jaffer left on a Mac (its wrapper `~/.jaffer/bin/jafferd` runs that exact path, until the first start of 0.6.0 removes it) would otherwise fail every five seconds.
- **The first start cleans up an upgraded Mac, once** (`prepareHome` → `migrateToPlainTerminal`, after an older session is ended and before the child starts; 30 s at most; `migrated: 1` in `config.json` makes every later start a single file read). It removes the login agent (`removeLegacyAgent`), copies the person's own `memory/NOTES.md` and `memory/POLICY.md` (when they hold anything: a `POLICY.md` still equal to the seeded text is not theirs) to `~/.jaffer-memory-backup/` (0700, never over a file there), deletes `memory/`, `session/` and `bin/jafferd` (the memory only once its backup is made), takes Jaffer's marked block out of `~/.claude/CLAUDE.md` (and `~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md`) and its `jaffer-*` skills that carry its marker, prunes the dead config keys (`DEAD_KEYS`, just before the last step) and runs `claude mcp remove jaffer -s user`. Each step is on its own (one that fails is a line in `migrate.log`, the others still run), it never throws, nothing is removed from a folder `assertJafferHome` does not accept, and a link is removed, never followed. What lies outside `~/.jaffer` (launchd, Claude Code's files, the MCP server) is touched by the clean-up only for the default home (`isDefaultHome`): a smoke test or a dev run with another `JAFFER_HOME` cleans inside that folder, with one exception (the backup of `NOTES.md` and `POLICY.md` goes to `~/.jaffer-memory-backup/` in the user's home for any Jaffer home; it only copies). That guard is not wider than the clean-up: first-run *Let Jaffer follow Claude Code* and *Settings → Connect* write hooks into the real `~/.claude/settings.json`, pointing at the running home's wrapper, whatever `JAFFER_HOME` is, and Reset (`jaffer reset`, *Settings → Reset*) does its Claude-side removal (hooks, MCP server, `CLAUDE.md` block, skills) on the real files for any home. Reset does the same cleanups when asked. The markers and names in `legacy-claude.ts` and `legacy-agent.ts` are the exact text older versions wrote: they must never change.
- **Never run the app against a Mac's real `~/.jaffer` to look at it** (`npm run dev`, `npm start`, `npm run smoke` set no `JAFFER_HOME`): on a Mac that ran an older Jaffer that is the migration, for real and irreversibly. Start it with `JAFFER_HOME` set to a throwaway folder whose name contains "jaffer", and for experiments also a throwaway `HOME` (`HOME=/tmp/x JAFFER_HOME=/tmp/x/.jaffer`), as the tests do: `JAFFER_HOME` alone protects your Claude files from the clean-up only (see above). Tests never reach the real `launchctl` or `claude`: `JAFFER_NO_LAUNCHCTL=1` is set for every test run (an injected `launchctl` is blocked by it too, so a test of the agent lowers it for itself), the tests of the clean-up and of Reset inject a fake `launchctl` and a refusing `execFile` mock, and a temp home is never `isDefaultHome` (tests that need it force it for their own folder).
- Redaction: anything shown from a hook payload or a command (the watcher's notice, a notification, the window) goes through `src/shared/redact.ts` first, and a sensitive command (`isSensitiveCommand`) is not named at all. Jaffer keeps no command history, command output or transcript text on disk: what it writes in `~/.jaffer` is `config.json`, `window.json`, the daemon's log, the shell scripts, `bin/jaffer`, `updater.log` and (once) `migrate.log`.
- Jaffer is for Claude Code only. Don't add integrations or copy for other agents (Codex, Gemini, ...).
- Jaffer runs on Claude subscriptions only: there is no Anthropic API key anywhere (no UI, no RPC, no CLI command, no engine), and `ANTHROPIC_API_KEY` is ignored. Don't add key entry back without being asked.
- Whether the user is signed in to Claude comes only from `claude auth status` (`src/core/integrations/claude-auth.ts`): never read Claude's credential files or keychain item, and never let the account email or organisation out of that function. Claude is optional: the first-run sign-in step offers "Use Jaffer as a plain terminal for now" (it then installs nothing and starts nothing, and sets `claude.skipped` so nothing nags; connecting Claude Code clears it), and the step itself types nothing into the terminal; tests fake `claude` with `test/helpers/fake-claude.ts`. Claude Code's own questions (trust, permissions) stay in the terminal and Jaffer never answers them.
- **The only thing Jaffer ever types into the shell is `claude`** (⇧⌘C, and the first-run switch "Start Claude Code in the terminal now", on by default and worded plainly), through the renderer's terminal, as the person would. There is no resume, no restart and no other automatic typing, and no `runCommand`; don't add one without being asked (it would need its own tests against bash and zsh: a pending Escape in readline swallows the first byte). `claude --resume <id>` is the person's own to type.
- There is exactly one session and one terminal: no splits, tabs, extra panes or second windows. `SessionHost` only ever spawns `main` and the daemon has no RPC to create another; don't add one (tests in `session.test.ts`, `daemon.test.ts` and the UI e2e guard this). A shell that exits is replaced by a fresh one in the folder it was in, with a blank screen: nothing of a terminal is saved or replayed.
- Config is conformed on load and on every patch to the kind of the defaults' values (`conform` in `src/shared/config.ts`: a section stays an object, a switch a boolean, a list a list of text; what does not fit keeps the default or the previous value), so code may rely on those kinds; a new key needs a default of the right kind. `jaffer config set` says when a value was refused (`session.stayAwake`, say, is true or false). Anything the window shows about a command goes through `safeCommand()` or the same redaction.
- Don't use a global CSS class name that is also a layout utility (`.row`) for state (we shipped that bug once). CSS here is global: before adding a modifier class (`.tag.run`, `.row-ico.agent`, `.seg-btn.mem` were all real bugs), check it is not already a standalone selector (`.run`, `.agent`, `.mem`).
- The renderer's colours are layered tokens from `themes.ts` (`--chrome`, `--surface`, `--raised`); use them instead of literals so every theme works. The UI shows commands only through `safeCommand()` (redacts, hides sensitive ones).
- The window is a calm terminal: a thin title bar, the terminal and the companion (the mole or one of the scenes). Don't add a sidebar, a status bar, a drawer, a Claude panel or command stripes back without being asked; the companion, the title-bar ring and the notification are how Claude's activity shows.
- There is one Claude: the `claude` in the terminal. Don't add a second chat, a prompt box or a background `claude` that talks for the user; the companion and the notification only show what Claude Code's hooks report. The hooks (`jaffer hook <event>`, all ten events, installed with `# jaffer-managed` and a `JAFFER_SESSION` guard) are asynchronous, print nothing, exit 0 on every path, and do nothing unless `JAFFER_SESSION=1`; anything shown from a payload is redacted first (`ClaudeWatcher`). For the approvals release: Jaffer answers a permission prompt **allow** only after a human click, **deny** is always safe, and any failure leaves Claude Code's own prompt in charge. Never start `claude` with `--dangerously-skip-permissions` or a mode that auto-allows.
- The cost figure (`shared/claude-cost.ts`, `core/claude/cost.ts`) reads only the token counts of Claude Code's transcript: never keep or show anything else from it. It is an estimate at API list prices (a subscription is not billed per token) and must say so; a model missing from the price table gets tokens and no dollars, never a neighbour's price. The table is checked against Anthropic's pricing page: update it with the page, not from memory. The switch is `claude.showCost` (Settings → Claude Code).
- The window shows only its own page (`isAppUrl` in `shared/window-policy.ts`, used by `will-navigate` and the IPC sender check): never allow any `file://`. A program in the terminal may write the clipboard (OSC 52) but never read it. Every redaction rule runs on the daemon's main thread over untrusted text, so each must be bounded (no unbounded character run before a literal); `test/redact.test.ts` has the timing tests. The same goes for the command-line helpers (`isClaudeCommand`, `isInteractiveCommand`): a command line is forgeable at any length, so each slices its input to a `COMMAND_HEAD` (4096-character) head itself (`isInteractiveCommand` then reads it in one pass); keep new ones the same, with timing tests on 1 MB and 8 MB lines.
- Updates ask first: nothing installs without a click (`autoInstallOnAppQuit` stays off, quitting never replaces the app behind a running session), only a packaged, Developer ID signed app checks, and `latest-mac.yml` is uploaded last and only by `scripts/release-mac.sh` (never by CI previews). Installing an update ends the terminal session (the prompt says so) and a fresh terminal starts.
- Staying awake (`session.stayAwake`) is an idle-sleep hold only: `/usr/bin/caffeinate -i -w <daemon pid>` while Claude or a long command works. It never overrides the lid and never needs admin rights: `pmset disablesleep` is not used and Jaffer never asks for a password. Copy says so plainly: a laptop on its own with the lid closed still sleeps (the README's "Not verified here" says how far closed-display mode has been checked).

## Verify
`npm run typecheck && npm test` (real PTYs, bash+zsh, the bundled daemon/CLI as processes, the real `claude` TUI where it is installed, `test/helpers/fake-claude.ts` for the sign-in; `claude`-dependent tests skip if `claude` is absent). `npm run test:e2e` drives the UI in Chromium (`JAFFER_CHROME=/path/to/chrome`, screenshots in `$JAFFER_SHOTS`; use `?renderer=dom` for screenshots in headless). macOS CI also boots the packaged app (`JAFFER_SMOKE=1`, with a temp `JAFFER_HOME`, and it checks that the terminal is the app's own child). Test hooks the daemon reads, inert unless set: `JAFFER_TEST_HOLD_LOG=<file>` stands in for `caffeinate`. Known flaky on a Mac, also on `main`: the real-`claude` TUI test; the README screenshots test (`npm run screenshots`) is written for Linux CI (it needs a short `TMPDIR` because of the unix socket path limit, and `/bin/zsh` on macOS).
