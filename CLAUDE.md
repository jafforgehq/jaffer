# Jaffer — notes for coding agents

Jaffer is a macOS terminal (Electron, and a terminal host `jafferd` that the app starts as its own child) with one session and a companion that shows what Claude Code is doing. It is a plain terminal: no memory, no saved or resumed terminal state (Claude Code's own conversations can be resumed from the side panel, see the typing rule), no login agent. Read `README.md` and `docs/ARCHITECTURE.md` first.

## Layout
- `src/main` — Electron main/preload: `trash-conversations.ts` (removing past conversations, 1.3.0: no Electron import, main passes the dialog, the Trash and the live sessions in), the window, menu, the menu bar item (the `Tray`, its menu, the close decision, the Dock icon), notifications, hotkey and updates (`updates.ts`), the start order and the quit question (`main.ts`), and `prepare-home.ts` (the first-start clean-up). `src/renderer` — Preact UI (`state.ts`: the signals and what the window keeps in memory; `blocks.ts` + `components/Blocks.tsx`: command blocks; `components/Chrome.tsx`: the title bar; `ToolStrip.tsx`; `SidePanel.tsx` + `Conversations.tsx` + `panel.ts`: the side panel, its Now card (with the turn bars and the worked-today line) and its past conversations; `components/WhatsNew.tsx`: the What's New card (1.2.0); `resume.ts`: resuming a past conversation, shared by the panel's rows, the palette and ⇧⌘R (1.2.0); `block-image.ts`: copy a block as an image; `season.ts`: the date's season for the companion; the companion's size (1.3.0: `petScale` in `src/shared/companions.ts`, applied by `Pet.tsx`); `claude-ui.ts`: the pure helpers for what the title bar shows; `Overlays.tsx`: Settings, the palette, the find bar, recent commands (with its By folder toggle), the shortcuts sheet (overlay kind `keys`), the paste bar and the pins; `actions.ts`: the palette actions, one id per menu item). `src/dev/bridge.ts` — browser↔daemon bridge used only by tests.
- `src/core/daemon-client.ts` — starts the app's own `jafferd` as its child (`startOwnedDaemon`) and connects to it. `src/daemon` — `jafferd` (`service.ts`: the RPC and what the daemon owns; `shutdown.ts`) and `src/core/rpc.ts` (NDJSON over a unix socket).
- `src/core/session` — PTY host, shell integration (OSC 133/633), headless-xterm snapshots, `stay-awake.ts` + `caffeinate.ts` (the idle-sleep hold), `git-status.ts` (the counts in the folder pill). `resources/shell/*` are the real scripts; `src/generated/shell-scripts.ts` is generated from them (`npm run gen`, checked in CI).
- `src/core/claude` — `watcher.ts` (pure state machine: what the terminal's Claude is doing, from its hook events: its tool calls, counts and timings, the files it edits, compacting), `transcript-watch.ts` (notices a prompt declined in the terminal) and `cost.ts` (the token counts of an answer) and, since 1.2.0, `approvals.ts` (the decision JSON of the optional blocking hook, and the one line shown for a permission request). `src/core/integrations` — `claude.ts` (Jaffer's hooks in `~/.claude/settings.json`, finding `claude`), `claude-auth.ts` (`claude auth status` / `claude auth login`) and `legacy-claude.ts` (what older versions wrote into Claude Code's files, and how to take it back).
- `src/core/migrate.ts` — the first-start clean-up of a Mac an older Jaffer ran on. `src/core/service/legacy-agent.ts` — takes away the login agent older versions installed. `src/core/reset.ts` — taking Jaffer off the Mac (`jaffer reset`, Settings → Reset). `src/cli` — `jaffer` (`hook`, `config`, `setup claude`, `status`/`doctor`, `reset`, `daemon [status|stop]`). `src/shared` — pure pieces shared by the processes (redaction, config, paths, the policies for quitting, updating and notifying, the cost table, `sensitive-path.ts`, `tool-category.ts`, `find-paths.ts`, `find-ports.ts`, `editor-url.ts`, `focus-hold.ts`, `menu-spec.ts`: the menu's labels and accelerators, which a test keeps in step with the palette; since 1.0.1 also `close-action.ts`, `tray-state.ts`, `recent-commands.ts`, `history-label.ts`, `session-id.ts`, `claude-text.ts` and, since 1.1.1, `resume-action.ts`: the line a click on a past conversation types, and when; since 1.2.0 also `mini-md.ts` (the tiny Markdown of the release notes: data, never HTML), `whats-new.ts` (which notes are unseen), `history-names.ts` (the person's own names and pins for conversations), `season.ts`, `shortcuts.ts` (what the ⌘/ sheet lists) and the `dropdownBounds` of `window-policy.ts`). `src/core/claude/history.ts` — the list of past Claude conversations (the `claude.history` RPC). `src/generated/tray-icons.ts` is generated by `scripts/gen-tray-icons.mjs` (`npm run gen:tray`; its `--check` is a test). `src/generated/release-notes.ts` is generated by `scripts/gen-release-notes.mjs` (`npm run gen:notes`, also run by the build; its `--check` is a test) from every `docs/releases/v*.md`: **keep the old notes**, the What's New card shows the history, and a new release adds `docs/releases/v<version>.md` (a leading `## What is new in <version>` line, and the standard last line "Updating from 0.2.x or later asks first, as always. 0.1.x apps have no updater: install this version from this page once.", which the card does not show).

## Rules that matter
- **The app owns the session.** Quitting Jaffer ends the shell and anything running in it. `jafferd` is the app's child: `startOwnedDaemon` spawns it (not detached) with `JAFFER_OWNED=1` and a pipe on its stdin that the app never writes; the daemon reads the flag, deletes it from its own environment at once (the shell never sees it) and, when the pipe ends (the app quits, crashes or is SIGKILLed), runs its normal shutdown: the shell is let go, the socket removed, exit 0. The flag is opt-in, because the tests, `ensureDaemon` and the dev bridge start the daemon detached with `stdio: 'ignore'` (`detachedSpawnArgs` removes the flag from the environment). The app connects only to its own child (`hello.pid` is the child's pid); anything else that answers on the socket (after a 3 s wait for a session that is already ending by itself) is an older Jaffer's background session, which the app ends only after the person's click (`LEGACY_DIALOG`: the default button is Quit, Esc means Quit; nothing is claimed about Return, which is unverified when default and cancel are the same button). Every quit ends the terminal, but only the menu's **Quit Jaffer** (⌘Q, a custom item that sets `askOnQuit`; `shouldAskOnQuit`, `quitNeedsConfirm`) asks first, and only when Claude Code is working or a command runs (the default button is Cancel, Esc cancels). A quit the system starts (logout, restart, shutdown, AppleScript, Dock → Quit) never asks, because macOS would take the question as the app refusing to quit and cancel the logout: don't put a question on those paths. An update, Reset and a session that already ended ask nothing. The menu bar item's **Quit Jaffer** is the same custom item (`quitFromMenu`), so it asks the same way. The window's ✕ and ⌘W do not quit by default: see the next rule. A child that ends by itself is a crash (`childExitAction`: a fresh terminal or Quit; exit 0 on its own, from `jaffer reset` or `jaffer daemon stop`, quits the app with it). Only the first instance runs (`requestSingleInstanceLock`): a second one exits at once and starts nothing. Never make the daemon outlive the app again, and never start one from the CLI.
- **Never move or rename `dist/daemon/jafferd.cjs`** (inside the app: `Contents/Resources/app/dist/daemon/jafferd.cjs`): the app starts that exact file as its child, and a login agent that an older Jaffer left on a Mac (its wrapper `~/.jaffer/bin/jafferd` runs that exact path, until the first start of 0.6.0 removes it) would otherwise fail every five seconds.
- **Closing the window hides it; the terminal runs on** (1.0.1; `closeDecision` in `src/shared/close-action.ts`, `closeWindow` / `hideWindow` in `main.ts`). The red ✕ and ⌘W (the menu's Hide Window calls `window.close()`, so both take the same path) do what `window.closeAction` says: `menubar` (the default) hides the window, `quit` goes the way of Quit Jaffer (which asks when something runs), `ask` shows a sheet (Hide to Menu Bar / Quit Jaffer / Cancel; Cancel is the default and Esc cancels) and only while the menu bar item exists (without it `ask` hides, because the sheet's words would be false). Any other value hides. A window in full screen leaves it first and hides after `leave-full-screen` (a 2 s timer is the fallback; showing the window calls the hide off): hidden in full screen it would leave an empty Space. The first hide while the item is there shows one notification (`window.hintShown`). The **menu bar item** (`window.menuBar`, on by default) is the one new surface of 1.0.1: a template icon in the menu bar (never a second window; the peek panel idea became extra menu lines on ⌥-click), its icon shows idle / working / needs-you (`TrayIconPlayer`; the icons are generated, never hand-edited), a click shows or hides the window, a right-click opens a menu built fresh each time, and an optional text beside the icon (`window.menuBarTitle`: the costs only with `claude.showCost`). `window.menuBarOnly` hides the Dock icon (`app.dock.hide()`), and only while the menu bar item exists: the item and the hotkey are the way back, so never hide the Dock icon without a Tray. If the Tray cannot be made, there is no item and no crash, and the window and the Dock work as before. The quit rules above do not change: closing never quits unless the person set it to, and a quit the system starts still never asks. **Drop-down mode** (1.2.0, `window.dropdown`, off by default, needs a hotkey: Settings disables the switch without one): the registered hotkey is `hotkeyToggle`, which with the setting on shows the one window at the top of the display under the pointer (`dropdownBounds(workArea)`: the work area's width and at most 45% of its height, at least `MIN_WINDOW_HEIGHT` 420) and a second press hides it; a window in full screen is left alone (the plain toggle). The window hides on `blur` while it is on (and a hotkey is registered, and it is not in full screen) **unless a dialog of ours is open**: `dialog` in `main.ts` is a wrapper that counts `showMessageBox` and `showSaveDialog` (`dialogsOpen`), so **any new dialog must go through that wrapper**, never `electron.dialog` directly, or a sheet would hide its own window. The bounds of a drop-down window are never saved (`window.json` keeps the normal ones), and turning the mode off puts the saved bounds back (or the default size, centred, when none was saved; after leaving full screen when it was in it). The tray click, the Dock and notifications still just show the window where it is. There is still one window and no Dock change. The menu bar item's menu has one more line, *What's New in <version>*, shown only while release notes are unseen, and the Help menu has *What's New…* and *Keyboard Shortcuts* (⌘/).
- **The first start cleans up an upgraded Mac, once** (`prepareHome` → `migrateToPlainTerminal`, after an older session is ended and before the child starts; 30 s at most; `migrated: 1` in `config.json` makes every later start a single file read). It removes the login agent (`removeLegacyAgent`), copies the person's own `memory/NOTES.md` and `memory/POLICY.md` (when they hold anything: a `POLICY.md` still equal to the seeded text is not theirs) to `~/.jaffer-memory-backup/` (0700, never over a file there), deletes `memory/`, `session/` and `bin/jafferd` (the memory only once its backup is made), takes Jaffer's marked block out of `~/.claude/CLAUDE.md` (and `~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md`) and its `jaffer-*` skills that carry its marker, prunes the dead config keys (`DEAD_KEYS`, just before the last step) and runs `claude mcp remove jaffer -s user`. Each step is on its own (one that fails is a line in `migrate.log`, the others still run), it never throws, nothing is removed from a folder `assertJafferHome` does not accept, and a link is removed, never followed. What lies outside `~/.jaffer` (launchd, Claude Code's files, the MCP server) is touched by the clean-up only for the default home (`isDefaultHome`): a smoke test or a dev run with another `JAFFER_HOME` cleans inside that folder, with one exception (the backup of `NOTES.md` and `POLICY.md` goes to `~/.jaffer-memory-backup/` in the user's home for any Jaffer home; it only copies). That guard is not wider than the clean-up: first-run *Let Jaffer follow Claude Code* and *Settings → Connect* write hooks into the real `~/.claude/settings.json`, pointing at the running home's wrapper, whatever `JAFFER_HOME` is, and Reset (`jaffer reset`, *Settings → Reset*) does its Claude-side removal (hooks, MCP server, `CLAUDE.md` block, skills) on the real files for any home. Reset does the same cleanups when asked. The markers and names in `legacy-claude.ts` and `legacy-agent.ts` are the exact text older versions wrote: they must never change.
- **Never run the app against a Mac's real `~/.jaffer` to look at it** (`npm run dev`, `npm start`, `npm run smoke` set no `JAFFER_HOME`): on a Mac that ran an older Jaffer that is the migration, for real and irreversibly. Start it with `JAFFER_HOME` set to a throwaway folder whose name contains "jaffer", and for experiments also a throwaway `HOME` (`HOME=/tmp/x JAFFER_HOME=/tmp/x/.jaffer`), as the tests do: `JAFFER_HOME` alone protects your Claude files from the clean-up only (see above). Tests never reach the real `launchctl` or `claude`: `JAFFER_NO_LAUNCHCTL=1` is set for every test run (an injected `launchctl` is blocked by it too, so a test of the agent lowers it for itself), the tests of the clean-up and of Reset inject a fake `launchctl` and a refusing `execFile` mock, and a temp home is never `isDefaultHome` (tests that need it force it for their own folder).
- Redaction: anything shown from a hook payload or a command (the watcher's notice, a notification, the window) goes through `src/shared/redact.ts` first, and a sensitive command (`isSensitiveCommand`) is not named at all. Jaffer keeps no command history, command output or transcript text on disk: what it writes in `~/.jaffer` is `config.json`, `window.json`, the daemon's log, the shell scripts, `bin/jaffer`, `updater.log` and (once) `migrate.log`. 1.0.0 adds only settings to `config.json` (and `claude.typicalTurnMs`, one number: the median length of the last turns, for the ring); 1.0.1 adds only the `window` section (`closeAction`, `menuBar`, `menuBarOnly`, `menuBarTitle`, `hintShown`). 1.2.0 adds only these keys: `updates.seenVersion` (the newest version whose release notes were dismissed), `history.names` (the person's own labels for conversations, `"<session id> <name>"`, at most 200 of at most 80 characters: what the person typed, **not** transcript text; a title is never written as a name) and `history.pinned` (session ids, at most 50), `claude.approvals` (false), `window.dropdown` (false) and `appearance.seasonal` (true). 1.3.0 adds only `appearance.petSize` (`small`, `normal`, `large` or `huge`; default `normal`; an unknown value counts as `normal`).
- **What Jaffer keeps in memory, and only there** (it ends with the app; none of it is written anywhere): the recent commands (⌘R: at most 200, newest first; a sensitive command or one longer than `4 * COMMAND_HEAD` is never kept), the pinned lines (at most 3), the turn history behind the sparklines (the last 20 turns' length and cost), the daemon's last 15 turn lengths, the count of answered approvals per tool, today's estimated cost (the daemon; it starts again at local midnight), which hook events were seen and when, the command blocks (the window's marks and their commands, through `safeCommand`), the focus-mode counts (main), the menu bar's last five commands (main: `RecentCommands`, same filter as above, labels redacted and clipped to 60) and its last list of past conversations (ids, folders, times and, since 1.1.1, titles), the open past-conversations list with its titles (the window), since 1.3.0 the *Remove…* menu's open state (the window, component state), and, since 1.2.0: the folder chip's choice, the cost-by-folder toggle and a rename's draft (the window, component state), the ⌘R list's By folder toggle and each recent command's `cwd` (the folder the command ran in: the shell's folder when its end mark came, redacted, at most 4096 characters; a repeat keeps the newest folder), the daemon's `DayTotal.workMs` (the time of today's finished turns, for "Claude worked … today"; it resets at local midnight and with the daemon, ignores turns under 1 s and undercounts a turn that was interrupted, because only a Stop adds it), the window's list of pending permission requests and the daemon's own (at most 5, each up to 20 s: an id, the session, the tool name and one redacted line of at most 120 characters, never the request itself) and the What's New card's open state, and in the watcher what the next rule says. Don't write any of it to disk, and don't add to this list without saying so here.
- Jaffer is for Claude Code only. Don't add integrations or copy for other agents (Codex, Gemini, ...).
- Jaffer runs on Claude subscriptions only: there is no Anthropic API key anywhere (no UI, no RPC, no CLI command, no engine), and `ANTHROPIC_API_KEY` is ignored. Don't add key entry back without being asked.
- Whether the user is signed in to Claude comes only from `claude auth status` (`src/core/integrations/claude-auth.ts`): never read Claude's credential files or keychain item, and never let the account email or organisation out of that function. Claude is optional: the first-run sign-in step offers "Use Jaffer as a plain terminal for now" (it then installs nothing and starts nothing, and sets `claude.skipped` so nothing nags; connecting Claude Code clears it), and the step itself types nothing into the terminal; tests fake `claude` with `test/helpers/fake-claude.ts`. Claude Code's own questions (trust, permissions) stay in the terminal and Jaffer never answers them.
- **Jaffer types into the shell only `claude` and, since 1.1.1, the resume line of a past conversation.** (1) `claude` (⇧⌘C, and the first-run switch "Start Claude Code in the terminal now", on by default and worded plainly), through the renderer's terminal, as the person would. (2) **Only after the person's click or Enter on a past conversation in the side panel, Enter on a conversation in the palette (1.2.0), or ⇧⌘R, Resume Last Conversation (1.2.0)**, exactly: Ctrl-E, Ctrl-U, Ctrl-X Ctrl-K (clears a half-typed line wherever the cursor is: bash's Ctrl-U kills only what is before it; Ctrl-X Ctrl-K is zsh's kill-buffer for a buffer Shift+Enter made several lines long, and only rings bash's bell; `test/resume-typing.test.ts` pins it in real bash and zsh), then `claude --resume <id>` (when the shell is already in that folder: `info.cwd === cwd`) or `cd '<folder>' && claude --resume <id>` (the folder single-quoted, `'` written `'\''`), then Enter. It is typed **only at an idle prompt** (`info.busy` empty, from the shell's marks), never while any command or Claude runs (then the command is copied and a toast says why); the id passes `isSessionId`; the folder is absolute, has no control character and no backslash and is at most 4096 characters, else only `claude --resume <id>` is copied; once per click (a type action locks further ones until the next `pty.start` or 2 s; a click in that time says "Already resuming…"). `isClaudeCommand` also knows a line that starts with exactly that `cd '<folder>' && ` (the cd read within `5 * COMMAND_HEAD`, the rest by its usual head), so a resumed Claude is Claude to the badge, ⇧⌘C, the resume toast, the quit question and the daemon's `endAll`. `resumeAction` in `src/shared/resume-action.ts` decides and `test/resume-action.test.ts` and the UI test (real bash) pin it; the renderer only executes it, always through `resumeConversation` in `src/renderer/resume.ts` (the one place with the 2 s type-once lock, which the panel's rows, the palette and ⇧⌘R share). ⇧⌘R (`resumeLast`) **always reads `claude.history` first** (one RPC: a list the window kept may be hours old and an old conversation must not be resumed) and, when that read fails, falls back to the list it has; it resumes the newest conversation whose folder is the shell's, else the newest. Renaming, pinning, the folder chips, cost by folder and the palette's search add no typing and no new path to the shell. The menu bar's items (past conversations, recent commands) still only **copy**: main cannot type. Accepted and listed as unverified in the README: forged OSC 133/633 marks can fake an idle prompt, and a PS2 continuation prompt and the shell's vi command mode count as idle. Every 1.0.0 action that "re-runs", "opens" or "pastes" works through the clipboard, Finder, the browser, an editor link or a save dialog: the recent commands (⌘R) *copy* the command and say so, the paste bar only passes on what the person pasted, and nothing printed in the terminal is ever typed. There is no restart, no other automatic typing and no `runCommand`; don't add one without being asked (it would need its own tests against bash and zsh: a pending Escape in readline swallows the first byte). Don't widen the resume line (no flags, no other command) without being asked.
- There is exactly one session and one terminal: no splits, tabs, extra panes or second windows. `SessionHost` only ever spawns `main` and the daemon has no RPC to create another; don't add one (tests in `session.test.ts`, `daemon.test.ts` and the UI e2e guard this). A shell that exits is replaced by a fresh one in the folder it was in, with a blank screen: nothing of a terminal is saved or replayed.
- Config is conformed on load and on every patch to the kind of the defaults' values (`conform` in `src/shared/config.ts`: a section stays an object, a switch a boolean, a list a list of text; what does not fit keeps the default or the previous value), so code may rely on those kinds; a new key needs a default of the right kind. `jaffer config set` says when a value was refused (`session.stayAwake`, say, is true or false). Anything the window shows about a command goes through `safeCommand()` or the same redaction.
- Don't use a global CSS class name that is also a layout utility (`.row`) for state (we shipped that bug once). CSS here is global: before adding a modifier class (`.tag.run`, `.row-ico.agent`, `.seg-btn.mem` were all real bugs), check it is not already a standalone selector (`.run`, `.agent`, `.mem`).
- The renderer's colours are layered tokens from `themes.ts` (`--chrome`, `--surface`, `--raised`); use them instead of literals so every theme works. The UI shows commands only through `safeCommand()` (redacts, hides sensitive ones).
- The window is a calm terminal: a thin title bar, the terminal, the companion (the mole or one of the scenes) and, since 1.1.0, **one side panel**. The panel (`SidePanel.tsx`; right side, open by default, ⌘B and the title bar's button toggle it, `panel: { open, width }` in the config, 220 to 480 px) has exactly two sections: *Now* (what the terminal's Claude is doing, from the same `claude.state` the title bar reads; since 1.2.0 also the turn bars of the last 20 turns, and "Claude worked … today") and *Past conversations* (⇧⌘O and the menu bar's *All Past Conversations…* open it and focus its search; since 1.2.0 each row can be renamed (pencil, F2) and pinned (star), and the section has folder chips and the cost-by-folder toggle; since 1.3.0 each row has a trash button (*Move to Trash*) and the header a *Remove…* menu, and `Delete`/`Backspace` on a selected row asks to remove it: always through the native question of the paragraph above), plus **one temporary child, the What's New card** (1.2.0, `WhatsNew.tsx`: inside `.side-panel`, above Now, dismissible; `updates.seenVersion` says which release notes were dismissed; its text is the bundled `RELEASE_NOTES` rendered by `mini-md.ts` into elements, never as HTML). The UI test pins the panel's children: handle, card, Now, conversations. It shows only what the window already shows or the menu bar already lists, through the same redaction (`safeCommand`, `claude-ui.ts`): it adds no data, no RPC and no reads of its own beyond `claude.history` (asked with `include`: the pinned ids). The panel reads it when it opens, after a finished turn and on its refresh button; closed, the panel renders nothing and reads nothing. Since 1.2.0 the list is also read when the palette opens and when ⇧⌘R runs, with the panel closed (the window keeps the answer in memory). It has no input that talks to Claude and types nothing of its own: a click or Enter on a conversation resumes it by typing the line of the typing rule above (idle prompt only: otherwise it copies), a small copy button on the row copies it, and nothing else is typed or sent. A name the person gives a conversation is stored in `history.names` (the person's own words, in `config.json`) and wins over the title in the rows, the search, the palette and the menu bar's labels. ⌘B arrives from the View menu's accelerator and from the page's own key handler; `togglePanel` ignores the second source within 250 ms (`lastPanelToggle`), so one press is one toggle. The terminal fits once per gesture: the panel's layout width changes at once, a drag of its left edge holds the fit (`layoutHold`) and fits on release (one `pty.resize`; a resize per pixel makes Claude Code's TUI redraw and duplicate output). Don't add a second panel, a panel inside the panel, a tab bar, a prompt or chat box, or more sections without being asked. The 1.1.0 overlay for past conversations is gone: don't bring a modal list back. 1.0.1 added one thing outside the window, the menu bar item (above). The 1.0.0 additions are exactly these: the gutter marks of the command blocks, the 2 px tool strip under the title bar, the sticky command header, pinned lines (at most 3), the paste bar, chips in the title bar (needs-you, editing, port, git counts, cost), the opt-in resource strip, the right-click menu on a gutter mark and toasts with actions. 1.2.0 adds exactly these outside the panel: the gutter menu's *Copy as image* (a PNG to the clipboard, drawn from the command and at most 200 lines of 160 columns of its output; never saved), recent commands grouped by folder, the shortcuts sheet (⌘/, overlay kind `keys`) and, from the notification, permission prompts (below). The overlay kinds are `settings`, `palette`, `onboarding`, `find`, `recent` and `keys`. Still forbidden without being asked: a status bar, a drawer, a left sidebar, a Claude panel or chat box, tabs, splits, a second window, command stripes. The companion, the title-bar ring, the glow, the strip, the panel's Now card and the notification are how Claude's activity shows. The calm-window UI test lists the allowed children of `.workspace`, `.stage` and `.terminal-area` (and that there is exactly one `.side-panel`): change it only for an addition named here.
- There is one Claude: the `claude` in the terminal. Don't add a second chat, a prompt box or a background `claude` that talks for the user; the companion and the notification only show what Claude Code's hooks report. The hooks (`jaffer hook <event>`, eleven events: `PreCompact` is the eleventh, installed with `# jaffer-managed` and a `JAFFER_SESSION` guard) are asynchronous, print nothing, exit 0 on every path, and do nothing unless `JAFFER_SESSION=1`; the one exception is the optional twelfth, `PermissionRequest` (`jaffer hook permission-request`), which is installed **only while `claude.approvals` is on** (turned off, it is removed; `HOOK_EVENTS` and the "which hooks were seen" list stay at eleven) and is blocking: see the approvals rule; anything shown from a payload is redacted first (`ClaudeWatcher`). **What the watcher may keep, in memory and for the session only:** tool names and their category (`toolCategory`), per-turn call counts and timings, whether a call failed, and the paths of files that `Edit`, `Write`, `MultiEdit` and `NotebookEdit` write (`tool_input.file_path` / `notebook_path`), redacted, at most 1024 characters, never one `isSensitivePath` flags and at most 50 a turn. Nothing else: no prompt, reply, command text, other tool argument or agent description (the watcher privacy test pins this; the call ids that pair a call with its result stay in the daemon and `view()` strips them, as it strips the transcript path). A new hook event or watcher field needs its own entry in that test. Never start `claude` with `--dangerously-skip-permissions` or a mode that auto-allows.
- **Approvals from the notification (1.2.0, experimental, `claude.approvals`, off by default).** On, Jaffer installs a twelfth hook, `PermissionRequest` (`jaffer hook permission-request`): the only hook that is **blocking** (no `async`, `timeout: 25`, tagged `# jaffer-managed`, with the `JAFFER_SESSION` guard); off, it is removed (also by `removeHooks`, disconnect and Reset), and `jaffer setup claude` follows the setting. The CLI reads at most 1 MB of stdin (then destroys it, so a stdin Claude Code keeps open cannot hold the hook), sends only `session_id`, `tool_name`, `tool_input` and `cwd` to the daemon (`claude.approval`) and waits up to `APPROVAL_WAIT_MS` (20 s; `JAFFER_TEST_APPROVAL_WAIT_MS` can only shorten it). The daemon keeps a request's *view* only (id, session, tool, one redacted line of at most 120 characters, `allowable`, expiry; never `tool_input`, and the watcher never sees the payload), at most 5 at once, and asks the app (event `claude.approvals`). **The hook prints a decision only for `allow` or `deny`** (`decisionOutput`: exactly Claude Code's `hookSpecificOutput` JSON, never `updatedInput`, `updatedPermissions` or `interrupt`); on anything else (the answer `ask`, no answer in 20 s, the setting off, no app connected, the daemon gone, any error) it prints nothing and exits 0, and Claude Code's own prompt is in charge: **any failure is silent and safe**. Never use exit code 2, never start `claude` with a mode that auto-allows, and add no default button, key binding, "always allow" or auto-answer. **Allow** is possible only (a) on a trusted click (`isTrusted`, `detail === 1`; the button has `tabindex=-1` and ignores keyboard and scripted clicks), (b) once it has been armed for 750 ms after that request first showed (`ARM_MS`; a double click allows only the first), (c) only in the panel's Now card, next to the detail (never in the notification, never in the title bar), and (d) only when the request is shown verbatim (`allowable`): not when redaction changed the text, for a sensitive command or path (`isSensitiveCommand`, `isSensitivePath`), when the line was cut (past 120 characters or `COMMAND_HEAD`), when it holds a newline or a hidden character (`\p{Cf}`, `\p{Cc}`, `\p{Zl}`, `\p{Zp}`, variation selectors, fillers: shown as `⏎` or `�`), or when there is no line at all (MCP tools, `Grep`, `Task`: only Bash, `Read`, the writing file tools and `WebFetch` give one). **`Edit`, `Write`, `MultiEdit` and `NotebookEdit` are never allowable**: their path shows, but what they would write does not (and a settings, rc or hook file can widen permissions), so they get Deny or Answer in terminal only. Otherwise only **Deny** and **Answer in terminal** are offered; Deny is always safe. **Answer in terminal** (`ask`: also the notification's Show) lets the hook go at once. The notification (Claude asks to use <tool>) is shown only while the window is not focused and focus mode does not hold it, with the buttons **Show, Deny** in that order and never Allow; a click on it only shows the window. The title-bar chip offers Deny and Answer in terminal, never Allow. The answer needs an app connection (`hello {client: 'app'}`), but any process of the same user can say that on the 0600 socket, as it can send `pty.write`: that check is defense in depth, not a boundary. The watcher privacy test pins that no payload field reaches the state. What is not known about Claude Code itself (that the hook blocks before its dialog, that silence falls back to its own prompt) is inferred from its documentation and listed in the README's *Not verified here*.
- The cost figure (`shared/claude-cost.ts`, `core/claude/cost.ts`) reads only the token counts of Claude Code's transcript: never keep or show anything else from it. **Past conversations** (1.0.1, `src/core/claude/history.ts`) are the one other thing read from transcripts, and it is narrower than it sounds: from `~/.claude/projects/*/*.jsonl` (`$CLAUDE_CONFIG_DIR/projects` when set) Jaffer may take the file name (the session id), the folder (`cwd`), the first and last timestamps and, for the newest 30 only and only with `claude.showCost`, the token usage (through the same cost reader, which keeps `usd` only) and, since 1.1.1, **a title: the one text allowed**, for the newest 30 only (older rows have none, except a pinned conversation asked for with `include`; it does not depend on `claude.showCost`). Its sources, in this order, all from the same head and tail 64 KB pieces: the latest `customTitle`, else the latest `aiTitle` (fields on any line), else the latest `type: 'summary'` line's `summary`, else the first line of the first real user message (`type: 'user'`, `message.role === 'user'`, not `isMeta`, `isSidechain` or `isCompactSummary`, text that does not start with `<`). The text is clipped to `COMMAND_HEAD` (4096) before `redactText`, control and format characters are removed, and it is cut to 80 characters; it lives in memory only (the same cache and the same bounds as the rest: never written, never logged). **Never** a later prompt, a reply, a tool input or any other text: the result's keys are exactly `id`, `cwd`, `title`, `startedAt`, `endedAt`, `durMs` and `usd`, and a test plants secret words and checks they never come out. The reading is read-only (`O_RDONLY | O_NOFOLLOW`; the one write exception is the next paragraph's) and confined: `realpath(<claudeDir>/projects)` is the root, only real folders and regular `<uuid>.jsonl` files count (a link, a subfolder such as `subagents`, or a path whose realpath is outside the root is skipped), and each file is read in two 64 KB pieces (head and tail, whole lines only; a file over 24 MB gets no cost), asynchronously, one file at a time. `isSessionId` (UUID only) runs before an id is used anywhere, including the clipboard. `claude.history` also takes `{ include }` (1.2.0): the pinned ids (`history.pinned`, at most 50, only the first 50 entries are looked at and each passes `isSessionId`), listed after the newest 50 even when older, with a title but a cost only within the 30 newest; the window's cost-by-folder table is computed from the costed rows it already has (no read of its own). The result is rebuilt on request (when the side panel opens, after a finished turn, on its refresh button, when the palette opens, when ⇧⌘R runs, and for the menu bar) and kept only in memory (a small cache by size and mtime; the panel keeps its last answer in the window's memory), never written. Don't read more of a transcript than this without saying so here. It is an estimate at API list prices (a subscription is not billed per token) and must say so; a model missing from the price table gets tokens and no dollars, never a neighbour's price. The table is checked against Anthropic's pricing page: update it with the page, not from memory. The switch is `claude.showCost` (Settings → Claude Code).
- **The one write to Claude Code's transcripts: remove past conversations (1.3.0).** Everything above is read-only, except that the person may move conversations they picked to the Trash (`src/main/trash-conversations.ts`, the panel's trash button per row and *Remove…* in the conversations header: *This folder* / *All listed*; `Delete` or `Backspace` on a selected row asks for that one). It touches exactly `<claudeDir>/projects/<folder>/<id>.jsonl` and its sibling real folder `<id>/` (subagent transcripts and tool results), nothing else. The paths come from `conversationFiles` (`history.ts`: ids pass `isSessionId`, at most 200 (`MAX_REMOVE`), `realpath(<claudeDir>/projects)` is the root, only real folders and regular files count, a link is never followed or moved, the real path must stay inside the root), never from the page. Files go to the Trash with `shell.trashItem`: **never a permanent delete**, so the person can put them back. A native confirmation in main comes first (the counting `dialog` wrapper; the default button is Cancel, Esc cancels; it names the number), once per request; main looks again after the answer (the dialog can stay open), so a conversation resumed, gone or swapped for a link meanwhile is not moved. A conversation that the daemon's watcher knows as not ended is refused (*still running*); if the live sessions cannot be looked up nothing is moved (never a guess). The guard sees only the sessions Jaffer's own hooks report: a `claude` in another terminal app is not seen, and its conversation can be moved (it is in the Trash, not gone). Moved ids leave `history.pinned` and `history.names`. Don't add another write to Claude's files, a permanent delete, or a removal without that question.
- The window shows only its own page (`isAppUrl` in `shared/window-policy.ts`, used by `will-navigate` and the IPC sender check): never allow any `file://`. A program in the terminal may write the clipboard (OSC 52) but never read it. Every redaction rule runs on the daemon's main thread over untrusted text, so each must be bounded (no unbounded character run before a literal); `test/redact.test.ts` has the timing tests. The same goes for the command-line helpers (`isClaudeCommand`, `isInteractiveCommand`) and for the readers of printed text and git's answer (`findPaths`, `findPorts`, `isSensitivePath`, `parseGitStatus`, `safeCommand`): a command line is forgeable at any length, so each slices its input to a head itself (`COMMAND_HEAD`, 4096 characters, for a command; `isSensitivePath` fails closed past 4096; `parseGitStatus` reads the first megabyte; `findPorts` the first 64 KB) and none has an unbounded run before a literal; keep new ones the same, with timing tests on 1 MB and 8 MB lines. **`redactText` itself throws (`RangeError`) on a multi-megabyte single-run string:** every caller that redacts untrusted text clips it to `4 * COMMAND_HEAD` first (the daemon's `633;E` command and `Cwd`, `commandNotification`, `safeCommand`), and `grep redactText(` over `src/main`, `src/daemon` and `src/core` must show only bounded callers.
- **git status runs a program after each prompt, so it is locked down** (`src/core/session/git-status.ts`): `execFile('git', [...])` with an argv array (no shell), a 1 s timeout (SIGKILL), 1 MB of output, `GIT_OPTIONAL_LOCKS=0` (the person's own git never waits for it), `-c core.fsmonitor=false`, `--ignore-submodules=all`. Before it, `git config --show-scope --get-regexp '^filter\..*\.(clean|process|smudge)$'` runs: a repository whose own config (any scope but `system` and `global`) names a filter driver gets no status, because `git status` would run that program. Tests use temporary repositories and `GIT_CONFIG_GLOBAL=/dev/null`; don't make it run anything else of git's.
- **The page may use these IPC channels of main, and each checks `trusted(e)` (the sender is the app's own page):** `jaffer:call` (the daemon's RPC), `jaffer:open-external` (http(s) only), `jaffer:reveal` (Jaffer's own folder), `jaffer:app-info`, `jaffer:update-state`, `jaffer:update-check`, `jaffer:reset`, `jaffer:set-login-item`, and the 1.0.0 ones: `jaffer:save-text` (a save dialog; the page names a file *name*, the person picks the place; at most 32 MB counted in bytes; the text is not kept), `jaffer:open-path` (⌘-click on a printed path), `jaffer:reveal-path` (a file the window names: an existing absolute path of at most 4096 characters, `shell.showItemInFolder` only), `jaffer:focus-mode` (a boolean), the 1.3.0 one `jaffer:trash-conversations` (`{ids}`: at most 200 UUID strings; main resolves the files itself, asks the person, refuses a running conversation and moves to the Trash; only ids and reasons come back, never a path) and, from main to the page, `jaffer:system-stats` (CPU and memory every 5 s, only while *System stats* is on). **Nothing printed in the terminal is ever opened or run:** a printed path is revealed in Finder, or handed to an editor link whose scheme is on the allow-list (`EDITOR_SCHEMES`: vscode, vscode-insiders, cursor, windsurf, zed, idea, subl, txmt; the path is encoded per segment); never `shell.openPath`, never a printed URL other than `http://localhost:<port>` built from a number.
- **Focus mode is ⌥⌘F** (⌃⌘F is macOS's Full Screen, which Electron's own role holds: no item of ours may share it; `menu-spec.ts` and its test enforce unique accelerators). The update prompt's notice is never held. Focus mode ends silently when the window closes or the page reloads.
