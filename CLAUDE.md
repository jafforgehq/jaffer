# Jaffer — notes for coding agents

Jaffer is a macOS terminal (Electron + a detached session daemon) with one never-ending session and a self-evolving memory. Read `README.md` and `docs/ARCHITECTURE.md` first.

## Layout
- `src/core/session` — PTY host, shell integration (OSC 133/633), headless-xterm snapshots. `resources/shell/*` are the real scripts; `src/generated/shell-scripts.ts` is generated from them (`npm run gen`, checked in CI).
- `src/core/memory` — store (journaled, revertible), heuristics (offline), reflector (model), consolidate, exports. Items are ranked by confidence × decay × usage × scope × BM25.
- `src/core/claude` — `watcher.ts` (pure state machine: what the terminal's Claude is doing, from its hook events), `transcript-watch.ts` (notices a prompt declined in the terminal) and `auto-resume.ts` (when to type `claude --resume <id>` by itself: a pure decision plus a small driver). `src/core/integrations` — `claude.ts` (MCP registration, hooks, finding `claude`) and `claude-auth.ts` (`claude auth status` / `claude auth login`). `src/core/agent/claude-cli.ts` — memory curation through `claude -p`. `src/core/reset.ts` — taking Jaffer off the Mac (`jaffer reset`, Settings → Reset).
- `src/daemon` — `jafferd` service + RPC (`src/core/rpc.ts`, NDJSON over a unix socket); `keep-running.ts` (the login-agent switch) and `shutdown.ts` (exit codes). `src/core/service/launch-agent.ts` — the launchd plist, wrapper and `launchctl` steps; `src/core/session/stay-awake.ts` + `caffeinate.ts` — the idle-sleep hold. `src/cli` — `jaffer`. `src/core/mcp` — MCP server.
- `src/main` — Electron main/preload. `src/renderer` — Preact UI. `src/dev/bridge.ts` — browser↔daemon bridge used only by tests.

## Rules that matter
- Anything that reaches memory, episodes or a model goes through `src/shared/redact.ts` first. Never persist command output of sensitive commands (`isSensitiveCommand`).
- The daemon owns the shell: never make the app a requirement for a running session. With the login agent on, nobody has to open the app after a crash or a login either: launchd starts the daemon.
- Updates ask first: nothing installs without a click (`autoInstallOnAppQuit` stays off, quitting never replaces the app behind a running session), only a packaged, Developer ID signed app checks, and `latest-mac.yml` is uploaded last and only by `scripts/release-mac.sh` (never by CI previews).
- Jaffer is for Claude Code only. Don't add integrations, exports or copy for other agents (Codex, Gemini, ...); `export.targets` only knows `claude-code` and `ConfigStore` drops anything else a saved config still lists.
- Jaffer runs on Claude subscriptions only: there is no Anthropic API key anywhere (no UI, no RPC, no CLI command, no engine), and `ANTHROPIC_API_KEY` is ignored. Don't add key entry back without being asked.
- Whether the user is signed in to Claude comes only from `claude auth status` (`src/core/integrations/claude-auth.ts`): never read Claude's credential files or keychain item, and never let the account email or organisation out of that function. Claude is optional: the first-run sign-in step offers "Use Jaffer as a plain terminal for now" (it then installs nothing, starts nothing, turns Claude's memory curation off, and sets `claude.skipped` so nothing nags; connecting Claude Code clears it), and the step itself types nothing into the terminal; tests fake `claude` with `test/helpers/fake-claude.ts`. The only things the product ever types into the terminal are `claude` (⇧⌘C, and the first-run switch "Start Claude Code in the terminal now", on by default and worded plainly) and `claude --resume <id>` (see the typing rule below; the id comes from Claude Code's own hooks); Claude Code's own questions (trust, permissions) stay in the terminal and Jaffer never answers them.
- There is exactly one session and one terminal: no splits, tabs, extra panes or second windows. `SessionHost` only ever spawns `main` and the daemon has no RPC to create another; don't add one (tests in `session.test.ts`, `daemon.test.ts` and the UI e2e guard this).
- Config is conformed on load and on every patch to the kind of the defaults' values (`conform` in `src/shared/config.ts`: a section stays an object, a switch a boolean, a list a list of text; what does not fit keeps the default or the previous value), so code may rely on those kinds; a new key needs a default of the right kind. `jaffer config set` says when a value was refused. Anything the window shows about a command, a host included, goes through `safeCommand()` or the same redaction.
- Don't use a global CSS class name that is also a layout utility (`.row`) for state (we shipped that bug once). CSS here is global: before adding a modifier class (`.tag.run`, `.row-ico.agent`, `.seg-btn.mem` were all real bugs), check it is not already a standalone selector (`.run`, `.agent`, `.mem`).
- The renderer's colours are layered tokens from `themes.ts` (`--chrome`, `--surface`, `--raised`); use them instead of literals so every theme works. The UI shows commands only through `safeCommand()` (redacts, hides sensitive ones).

- The window is a calm terminal: a thin title bar, the terminal, the companion (the mole or one of the scenes), and one drawer (memory). Don't add a sidebar, a status bar, a Claude panel or command stripes back without being asked; the companion, the title-bar ring and the notification are how Claude's activity shows.
- There is one Claude: the `claude` in the terminal. Don't add a second chat, a prompt box or a background `claude` that talks for the user; the companion and the notification only show what Claude Code's hooks report. The hooks (`jaffer hook <event>`) are asynchronous, print nothing, exit 0 on every path, and do nothing unless `JAFFER_SESSION=1`; anything shown from a payload is redacted first (`ClaudeWatcher`). For the approvals release: Jaffer answers a permission prompt **allow** only after a human click, **deny** is always safe, and any failure leaves Claude Code's own prompt in charge. Never start `claude` with `--dangerously-skip-permissions` or a mode that auto-allows.
- The cost figure (`shared/claude-cost.ts`, `core/claude/cost.ts`) reads only the token counts of Claude Code's transcript: never keep or show anything else from it. It is an estimate at API list prices (a subscription is not billed per token) and must say so; a model missing from the price table gets tokens and no dollars, never a neighbour's price. The table is checked against Anthropic's pricing page: update it with the page, not from memory. The switch is `claude.showCost` (Settings → Claude Code).
- The window shows only its own page (`isAppUrl` in `shared/window-policy.ts`, used by `will-navigate` and the IPC sender check): never allow any `file://`. A program in the terminal may write the clipboard (OSC 52) but never read it. Every redaction rule runs on the daemon's main thread over untrusted text, so each must be bounded (no unbounded character run before a literal); `test/redact.test.ts` has the timing tests. The same goes for the command-line helpers (`isClaudeCommand`, `endsConversation`, `isPrintMode`, `isInteractiveCommand`): a command line comes from the shell's marks, which any output can forge at any length, so the daemon hands them a `COMMAND_HEAD` (4096-character) head, and the two tokenizers (`isPrintMode`, `isInteractiveCommand`) read it in one pass with no unbounded regex; keep new ones the same.
- Jaffer never injects commands into the user's shell. It types only `claude` (⇧⌘C and the first-run switch, through the renderer's terminal) and `claude --resume <id>`, which the daemon also types by itself after a restart (auto-resume, Restart Claude Code) as well as after a click on Resume. Only for the conversation `ResumeStore` recorded, with the id checked by `isSessionId` where it is kept and again where it is typed; announced with a notice the person can cancel; at most 3 attempts per conversation in 10 minutes; never after a deliberate end (exit 0 or 130, SessionEnd, End Session, a `claude -p` run). It never extends a line the person started: any keystroke since the later of the pane's spawn and its last command start makes the line dirty (`inputSeq`), except keys typed into an interactive `claude` run, which went to Claude. There is no `runCommand`; keep it that way unless asked (it would need its own tests against bash and zsh: a pending Escape in readline swallows the first byte).
- The login agent that keeps the daemon alive (`com.jafforge.jaffer.daemon`) is configuration outside `~/.jaffer`, so: only with the person's switch (`session.keepRunning`, off by default; a plain terminal installs nothing); only for the default home (`isDefaultHome`: the real `~/.jaffer`, never a test or development home); refused from a translocated, mounted or `node_modules` path; removed by turning the switch off, `jaffer service remove`, Reset and `jaffer reset` (switch off first, then the agent). Turning it off while launchd runs the session ends that session, so the app asks first. The daemon exits 0 only for a deliberate end (`app.shutdown`), 143 on SIGTERM and 130 on SIGINT, so that launchd restarts a kill or a crash and leaves an end alone. Tests never reach the real launchd: `JAFFER_NO_LAUNCHCTL=1` is set for all test runs (both vitest configs) and makes `execLaunchctl` fail without running anything; tests of the agent inject a fake `launchctl`.
- Staying awake (`session.stayAwake`) is an idle-sleep hold only: `/usr/bin/caffeinate -i -w <daemon pid>` while Claude or a long command works. It never overrides the lid and never needs admin rights: `pmset disablesleep` is not used and Jaffer never asks for a password. Copy says so plainly: a laptop on its own with the lid closed still sleeps; only macOS's closed-display setup (power, an external display, a keyboard or mouse) keeps working (what the README lists under "Not verified here" says how far that has been checked).

## Verify
`npm run typecheck && npm test` (real PTYs, bash+zsh, bundled daemon/CLI as processes, the real `claude` against a mock API and `test/helpers/fake-claude.ts` for the sign-in; `claude`-dependent tests skip if `claude` is absent). `npm run test:e2e` drives the UI in Chromium (`JAFFER_CHROME=/path/to/chrome`, screenshots in `$JAFFER_SHOTS`; use `?renderer=dom` for screenshots in headless). macOS CI also boots the packaged app (`JAFFER_SMOKE=1`). Two hooks are read by production code and do nothing unless set: `JAFFER_TEST_HOLD_LOG=<file>` replaces the real `caffeinate` with lines of JSON, and `JAFFER_TEST_AUTORESUME_FAST=1` runs auto-resume and Restart Claude Code on a scale of milliseconds. Known flaky on a Mac, also on `main`: the real-`claude` TUI test; the README screenshots test (`npm run screenshots`) is written for Linux CI (it needs a short `TMPDIR` because of the unix socket path limit, and `/bin/zsh` on macOS).
