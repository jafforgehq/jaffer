# Jaffer — notes for coding agents

Jaffer is a macOS terminal (Electron + a detached session daemon) with one never-ending session and a self-evolving memory. Read `README.md` and `docs/ARCHITECTURE.md` first.

## Layout
- `src/core/session` — PTY host, shell integration (OSC 133/633), headless-xterm snapshots. `resources/shell/*` are the real scripts; `src/generated/shell-scripts.ts` is generated from them (`npm run gen`, checked in CI).
- `src/core/memory` — store (journaled, revertible), heuristics (offline), reflector (model), consolidate, exports. Items are ranked by confidence × decay × usage × scope × BM25.
- `src/core/claude` — `watcher.ts` (pure state machine: what the terminal's Claude is doing, from its hook events), `transcript-watch.ts` (notices a prompt declined in the terminal) and `auto-resume.ts` (types `claude --resume <id>` once for Restart Claude Code, after the person's confirmation; nothing else starts it). `src/core/integrations` — `claude.ts` (MCP registration, hooks, finding `claude`) and `claude-auth.ts` (`claude auth status` / `claude auth login`). `src/core/agent/claude-cli.ts` — memory curation through `claude -p`. `src/core/reset.ts` — taking Jaffer off the Mac (`jaffer reset`, Settings → Reset).
- `src/daemon` — `jafferd` service + RPC (`src/core/rpc.ts`, NDJSON over a unix socket); `keep-running.ts`, `shutdown.ts`. `src/core/service` — the launchd login agent; `src/core/session/stay-awake.ts` — the idle-sleep hold. `src/cli` — `jaffer`. `src/core/mcp` — MCP server.
- `src/main` — Electron main/preload. `src/renderer` — Preact UI. `src/dev/bridge.ts` — browser↔daemon bridge used only by tests.

## Rules that matter
- Anything that reaches memory, episodes or a model goes through `src/shared/redact.ts` first. Never persist command output of sensitive commands (`isSensitiveCommand`).
- The daemon owns the shell: never make the app a requirement for a running session (with the login agent on, launchd starts the daemon: nobody has to open the app after a crash or a login).
- Updates ask first: nothing installs without a click (`autoInstallOnAppQuit` stays off, quitting never replaces the app behind a running session), only a packaged, Developer ID signed app checks, and `latest-mac.yml` is uploaded last and only by `scripts/release-mac.sh` (never by CI previews).
- Jaffer is for Claude Code only. Don't add integrations, exports or copy for other agents (Codex, Gemini, ...); `export.targets` only knows `claude-code` and `ConfigStore` drops anything else a saved config still lists.
- Jaffer runs on Claude subscriptions only: there is no Anthropic API key anywhere (no UI, no RPC, no CLI command, no engine), and `ANTHROPIC_API_KEY` is ignored. Don't add key entry back without being asked.
- Whether the user is signed in to Claude comes only from `claude auth status` (`src/core/integrations/claude-auth.ts`): never read Claude's credential files or keychain item, and never let the account email or organisation out of that function. Claude is optional: the first-run sign-in step offers "Use Jaffer as a plain terminal for now" (it then installs nothing, starts nothing, turns Claude's memory curation off, and sets `claude.skipped` so nothing nags; connecting Claude Code clears it), and the step itself types nothing into the terminal; tests fake `claude` with `test/helpers/fake-claude.ts`. The only things the product ever types into the terminal are `claude` (⇧⌘C, and the first-run switch "Start Claude Code in the terminal now", on by default and worded plainly) and `claude --resume <id>` (see the typing rule below; the id comes from Claude Code's own hooks); Claude Code's own questions (trust, permissions) stay in the terminal and Jaffer never answers them.
- There is exactly one session and one terminal: no splits, tabs, extra panes or second windows. `SessionHost` only ever spawns `main` and the daemon has no RPC to create another; don't add one (tests in `session.test.ts`, `daemon.test.ts` and the UI e2e guard this).
- Config is conformed on load and on every patch to the kind of the defaults' values (`conform` in `src/shared/config.ts`: a section stays an object, a switch a boolean, a list a list of text; what does not fit keeps the default or the previous value), so code may rely on those kinds; a new key needs a default of the right kind. `jaffer config set` says when a value was refused. Anything the window shows about a command, a host included, goes through `safeCommand()` or the same redaction.
- Don't use a global CSS class name that is also a layout utility (`.row`) for state (we shipped that bug once). CSS here is global: before adding a modifier class (`.tag.run`, `.row-ico.agent`, `.seg-btn.mem` were all real bugs), check it is not already a standalone selector (`.run`, `.agent`, `.mem`).
- The renderer's colours are layered tokens from `themes.ts` (`--chrome`, `--surface`, `--raised`); use them instead of literals so every theme works. The UI shows commands only through `safeCommand()` (redacts, hides sensitive ones).

- The window is a calm terminal: a thin title bar, the terminal, the companion (the mole or one of the scenes), and one drawer (memory). Don't add a sidebar, a status bar, a Claude panel or command stripes back without being asked; the companion, the title-bar ring and the notification are how Claude's activity shows.
- There is one Claude: the `claude` in the terminal. Don't add a second chat, a prompt box or a background `claude` that talks for the user; the companion and the notification only show what Claude Code's hooks report. The hooks (`jaffer hook <event>`) are asynchronous, print nothing, exit 0 on every path, and do nothing unless `JAFFER_SESSION=1`; anything shown from a payload is redacted first (`ClaudeWatcher`). For the approvals release: Jaffer answers a permission prompt **allow** only after a human click, **deny** is always safe, and any failure leaves Claude Code's own prompt in charge. Never start `claude` with `--dangerously-skip-permissions` or a mode that auto-allows.
- The cost figure (`shared/claude-cost.ts`, `core/claude/cost.ts`) reads only the token counts of Claude Code's transcript: never keep or show anything else from it. It is an estimate at API list prices (a subscription is not billed per token) and must say so; a model missing from the price table gets tokens and no dollars, never a neighbour's price. The table is checked against Anthropic's pricing page: update it with the page, not from memory. The switch is `claude.showCost` (Settings → Claude Code).
- The window shows only its own page (`isAppUrl` in `shared/window-policy.ts`, used by `will-navigate` and the IPC sender check): never allow any `file://`. A program in the terminal may write the clipboard (OSC 52) but never read it. Every redaction rule runs on the daemon's main thread over untrusted text, so each must be bounded (no unbounded character run before a literal); `test/redact.test.ts` has the timing tests. The same goes for the command-line helpers (`isClaudeCommand`, `endsConversation`, `isPrintMode`, `isInteractiveCommand`): a command line is forgeable at any length, so each slices its input to a `COMMAND_HEAD` (4096-character) head itself (`isPrintMode` and `isInteractiveCommand` then read it in one pass); keep new ones the same, with timing tests on 1 MB and 8 MB lines.
- Jaffer never injects commands into the user's shell. It types only `claude` (⇧⌘C and the first-run switch, through the renderer's terminal) and `claude --resume <id>`, and the second only after a click: on the **Resume Claude** button (the renderer types it into the terminal, as the person would, after asking the daemon again with `claude.resume` `{ fresh: true }`: only the same conversation coming back is typed, because a shell without Jaffer's marks never says when a program took the terminal), or after the native confirmation of Restart Claude Code (the daemon types it once in the restarted shell, after a 3-second notice with a Cancel). Nothing resumes by itself: not after a start, a crash, an update or a reboot (0.5.0 did, and every risky case its reviews found came from it; `session.autoResume` is gone and an old config file that still lists it is ignored: do not bring automatic typing back without being asked). Only for the conversation `ResumeStore` recorded, with the id checked by `isSessionId` where it is kept and again where it is typed. Restart Claude's typing is checked again at the moment it types: the shell itself has the terminal (the terminal's foreground process group is the shell's pid, asked of the system with `foregroundIsShell({ fresh: true })`, never a cached answer: the marks are output and any program can print them), and it never extends a line the person started (`inputSeq`; keys typed into an interactive `claude` run are exempt: see ARCHITECTURE, *Restart Claude Code*). It is never typed for a conversation that was ended on purpose (exit 0 or 130, SessionEnd, End Session, a `claude -p` run). There is no `runCommand`; keep it that way unless asked (it would need its own tests against bash and zsh: a pending Escape in readline swallows the first byte).
- The login agent that keeps the daemon alive is configuration outside `~/.jaffer`: only with the person's switch (`session.keepRunning`, off by default; the first-run plain path shows it off and installs only if the person turns it on); only for the default home (`isDefaultHome`) and an app not run from a disk image, a temporary location or `node_modules`; removed by switching it off, `jaffer service remove`, Reset and `jaffer reset`; the app asks before turning it off ends a launchd-run session, and so does the CLI: `jaffer service remove` and `jaffer config set session.keepRunning false` typed in that session (`JAFFER_SESSION=1`) print the warning and change nothing without `--yes`. A change of `session.keepRunning` by any route (Settings, `jaffer service`, `jaffer config set`) reconciles the agent with every guard above. Exit codes, the install policy and the plist are in ARCHITECTURE (*The login agent and launchd*). Tests never reach the real launchd: `JAFFER_NO_LAUNCHCTL=1` is set for all test runs, and a test of the agent injects a fake `launchctl`. Never move or rename `dist/daemon/jafferd.cjs` (inside the app: `Contents/Resources/app/dist/daemon/jafferd.cjs`): the wrapper installed on people's Macs (`~/.jaffer/bin/jafferd`) runs that exact path, and an update that moves it leaves launchd starting nothing until a daemon started another way rewrites the wrapper.
- Staying awake (`session.stayAwake`) is an idle-sleep hold only: `/usr/bin/caffeinate -i -w <daemon pid>` while Claude or a long command works. It never overrides the lid and never needs admin rights: `pmset disablesleep` is not used and Jaffer never asks for a password. Copy says so plainly: a laptop on its own with the lid closed still sleeps (the README's "Not verified here" says how far closed-display mode has been checked).

## Verify
`npm run typecheck && npm test` (real PTYs, bash+zsh, bundled daemon/CLI as processes, the real `claude` against a mock API and `test/helpers/fake-claude.ts` for the sign-in; `claude`-dependent tests skip if `claude` is absent). `npm run test:e2e` drives the UI in Chromium (`JAFFER_CHROME=/path/to/chrome`, screenshots in `$JAFFER_SHOTS`; use `?renderer=dom` for screenshots in headless). macOS CI also boots the packaged app (`JAFFER_SMOKE=1`). Test hooks the daemon reads, inert unless set: `JAFFER_TEST_HOLD_LOG=<file>` stands in for `caffeinate`, `JAFFER_TEST_AUTORESUME_FAST=1` runs Restart Claude Code's notice, quiet wait and hold on a scale of milliseconds. Known flaky on a Mac, also on `main`: the real-`claude` TUI test; the README screenshots test (`npm run screenshots`) is written for Linux CI (it needs a short `TMPDIR` because of the unix socket path limit, and `/bin/zsh` on macOS).
